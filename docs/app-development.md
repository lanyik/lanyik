# App 开发设计：生存 RPG

当前 `apps/survivor` 已实现六边形地域、四圈驻留生态、角色/背包独立界面、法力技能、六槽宝珠和寻宝分布。
精确数值见[战斗、成长与寻宝合同](./game/combat-and-progression.md)，模型来源、处理与资源生命周期见
[角色资产合同](./game/actor-assets.md)，玩家体验见[游戏想法](../游戏想法.md)。

## 应用边界

应用是模块化单体：纯数据战斗核心、地图适配器、批量表现层、React HUD、组合入口。
核心不导入 React、Three.js、DOM、Worker 或地图内部模块；地形流送不拥有战斗事实。

```text
apps/survivor/
  assets/actors/                 # 固定来源的 CC0 原始模型、许可证和哈希
  src/core/
    CombatSimulation.ts         # 权威战斗、物品、成长、技能、嵌珠与拾取
    RegionalWorld.ts            # 六边形地域、径向等级带、四圈驻留与单次人口
    Equipment.ts                # 11 部位、44 基础名称、三轴装备和 38 种词条
    CombatStats.ts              # 加点派生、上限转换、攻击/防御公式
    Loot.ts                     # 品质目录、收益递减和概率分布
    Orbs.ts                     # 六槽解锁、宝珠类型与品质强度
    InventoryItem.ts            # 装备/宝珠/药剂联合类型、排序与低级装备判定
    DeterministicRandom.ts       # 可重放随机流
    FixedStepClock.ts            # 有界固定时钟
  src/app/
    CombatView.ts               # 最小表现端口
    CombatSession.ts            # 会话、命令、可见性与 UI 发布
    bootstrap.tsx               # 组合与生命周期
  src/adapters/HexCombatView.ts  # 世界、出生搜索、镜头和输入组合
  src/presentation/
    CombatLayer.ts              # 表现层所有权、地形高度和固定实例池
    ActorModels.ts              # 预烘焙主角/怪物模型、实例动画和释放
    MovementInputController.ts  # 相对镜头 WASD 输入
    App.tsx / app.css           # 窗口组合、快捷键、战斗 HUD
    CharacterPanel.tsx          # 固定体位装备、宝珠、加点和概率属性
    InventoryPanel.tsx          # 平铺完整详情卡、筛选、整理、自动清理和物品操作
    RegionMap.tsx               # 右上六边形地图，19 地域与玩家坐标
    ItemView.tsx                # 共用物品图标/详情/感叹号提示
```

根包的 `cameraPanEnabled`、`setCameraTarget(worldX,worldZ)` 是通用公开能力，应用不访问 HexMap 私有控制器。

## 权威状态与时钟

每局只有一个 `CombatSimulation`，独占位置、血蓝、等级、经验、金币、属性点、装备、背包、宝珠、
物品对象表、实体池、人口消费位、宝箱消费状态、战斗冷却和随机状态的写入；自动清理设置与累计件数也由核心拥有。
`CombatSession` 管理加载状态、暂停/隐藏和通知显示期限，命令调用核心公开操作后发布快照。
React 只读取冻结的低频快照和提交命令，不直接修改战斗；每 100ms 最多发布一次常规战斗 UI 更新。
界面窗口开关、筛选、选中物品 ID 和目标宝珠槽属于本地 UI 状态，不进入模拟。

固定步长 20ms，单帧最多接受 250ms 墙钟时间，后台时间不追赶。位置使用前后 tick 插值。
单 tick 顺序：

1. 保存前一位置，递减受击保护、盾、脉冲、药剂与技能冷却，应用移动；
2. 同步区块窗口，跨区块时释放失效实体、初始化新人口，独立判断六边形地域边界；
3. 自动索敌并创建弹道，线段扫掠命中，死亡立即提交经验与物品；
4. 自动施法开启时尝试脉冲；按圈层更新怪物、接触伤害与反伤；
5. 若玩家仍存活，推进经验吸附、升级、物品拾取与附近宝箱；
6. 每 25 tick 回复血蓝，失效快照。

手动施法与药剂由会话命令在同步边界提交，只在 ready 且未暂停/隐藏/死亡时有效。
暂停仍可加点、整理装备、嵌珠和切换自动施法；恢复后按新状态继续。相同种子、输入和命令顺序可重放。

## 数据布局与地域驻留

高频实体使用预分配数组与 swap-remove，不逐怪创建组件、事件、计时器或 React 对象。

| 数据池 | 上限 | 满载行为 |
|---|---:|---|
| 怪物 | 640 | 49 区块最多 539 槽，超过为明确配置错误 |
| 弹道 | 128 | 等待可用槽 |
| 经验球 | 768 | 新经验合并到索引 0，容量溢出不丢价值 |
| 地面物品 | 64 | 不创建额外物品，现有物品保留 |
| 宝箱表现 | 49 | 仅提交内圈未开箱 |

怪物数组包含真实等级、类型、精英/Boss、可见性、位置、出生位置、生命、速度、伤害、半径和闪烁，
另持有出生区块和实际地域引用。地面物品数组包含 kind、ID、品质、位置，与冻结物品表一并增删。
自动索敌和弹道命中扫描活跃前缀，不预建未被真实性能数据要求的空间索引。

方形玩法区块为 12×12，常驻窗口固定 9 个实时、16 个低频、24 个静态；低频按 ID 错峰 5Hz。
只在跨区块时重建窗口。每个出生槽在本次驻留只生成一次，死亡不补充；离开至卸载后重入重建。
宝箱和 Boss 同样按驻留消费，不维护定时轮次、死亡补充冷却或无限探索历史。
实体的出生区块失效时移除，清空引用；地面物品/经验按当前位置离开外圈时清理。

六边形地域是独立内容分区，半径 24，环数决定总体等级带，每环增加 5 级；三难度在等级带内分布。
边界出生点必须按自身坐标确定类型、等级与掉落，不直接继承区块中心的地域。
领主出现在恐怖六边形中心，中心所属的唯一方形区块拥有其出生槽。

## RPG 与界面

装备基础值、显式词条、聚合值分别存储且冻结。等级/星级/品质独立；`sumEquipment()` 是装备聚合入口。
基础属性只有力量、体魄、敏捷、精神，不影响概率或攻速。概率构筑来自装备词条，寻宝分布仅来自宝珠。
`sumOrbs()` 聚合六槽有效 rating，`lootProfile()` 同时提供掉落抽样和 UI 展示，防止说明与实际概率分叉。
宝珠只有宝箱/领主来源，开局两个槽，其余 50/100/150/200 级解锁；没有宝珠反向提高自身掉率的递归奖励。

背包物品用 `kind` 联合类型，所有操作校验真实背包 ID。穿戴/嵌入先移出新物品，再原子返回旧物品，
满包可一换一；卸下后保留的物品单独占格。宝箱按保留奖励所需格数预检，空间不足不消费奖励或箱子。
自动清理默认关闭，勾选后直接移除背包中等级低于角色的装备；开启、升级与入包边界执行，已穿戴装备和
非装备物品不受影响。`storeInventoryItem()` 对装备入包复用过滤规则，地面与宝箱容量检查排除自动清理物品。
累计清理件数进入玩家快照，不用逐件通知刷屏。整理命令直接对权威背包按品质、等级降序和 ID 升序排序。
生命/法力最大值变化保持比例；升级额外回血仅按一次经验结算治疗一次。
药剂只在资源未满时使用，共用冷却。脉冲既可自动也可手动，有真实法力成本。

角色窗口是两列：左装备/宝珠和详情、右基础加点与数值属性；装备体位和宽高由固定网格控制。
背包容量 40，采用自适应列数的平铺卡片，直接展示完整属性/效果与物品操作；删除旧空格占位和单项详情区。
工具栏提供分类、一键整理、自动清理复选框和当前阈值，底栏显示金币、件数与宝珠目标槽。
卡片使用稳定物品 ID 作为 React key 和选择值，排序保持选择；分类变化清空选择，避免快捷键误操作隐藏物品。
卡片本身可聚焦，内部操作和感叹号使用独立按钮，避免嵌套按钮；复选框焦点不阻断菜单或移动快捷键。
感叹号支持悬停/聚焦，portal 提示避免被窗口滚动区域裁切。窄屏允许窗口滚动，保持装备排列。
地图右上，血蓝/经验/技能/状态下中，功能名与快捷键右下；移除常驻基础操作说明。
菜单快捷键集中在 App 的目录，与按钮共用行为；Esc 按窗口优先级关闭，按钮 Enter 保持原生语义。

## 世界、表现与生命周期

出生搜索使用与 ProceduralWorldSource 相同水体配置的同步 resolver，在最多 14 圈内寻找 5×5 干燥地面。
找不到则明确失败。`HexMap.loadWorld()` 调用开始即拥有 source；调用前未发布的 source 由适配器清理。
逻辑战斗坐标单位为 tileSize=1，表现层根节点按实际 tileSize 缩放，镜头跟随插值位置和地表高度。
高度按最近六边形格中心缓存，最多 4096 项；世界卸载、surface 改变或达到上限时清空。

主角使用 KayKit 游侠，怪物为四种骷髅，细节见资产合同。动作在构建时烘焙，实例动画使用共享 morph 数据；
怪物仅提交内圈。弹道、经验和物品采用实例池，装备/宝珠/药剂分别显示方块/八面体/药瓶，宝箱体/盖/锁独立池；不进行逐怪骨骼求值。
固定池禁用自身视锥剔除，由玩法窗口控制实例数量；地形仍由地图区块和 LOD 控制。
角色资源首次初始化异步加载，成功预算申请后才挂载；已释放层或过期世界不接收加载结果。
原始源模型、生成网格/法线、PNG atlas、实例 morphTexture 和所有材质均有明确释放路径。

`CombatSession.start()` 用加载世代拒绝过期结果，加载时停止时钟、清输入与旧模拟。
隐藏、失焦、暂停、死亡与关闭按合同停止/清理输入；恢复可见性不会覆盖用户主动暂停。
pagehide 非往返缓存场景停止应用帧并等待异步释放，重复关闭返回同一 Promise。
地图或资源失败进入 failed 并显示原因，可重新加载同一种子；没有静默替换模型或伪造地图的降级路径。

## 构建与验证

`npm run app:dev` 准备本地库、地形、森林和预烘焙角色，然后在 5173 启动；`app:build` 严格检查并生成生产应用。
构建脚本先校验 realpath 与父目录，只替换 `apps/survivor/.assets`；不下载网络资产或删除源文件。
Vite 保持 React、Three.js、世界运行时的明确分组，生成文件不入 Git。

`test:app` 覆盖确定性、圈层、真实战斗/拾取、等级节奏、装备三轴、概率归一化、宝珠、药剂、加点隔离、
排序优先级以及自动清理的开关、升级和入包边界。
`test:app:e2e` 覆盖真实 Worker/WebGL、五个模型、血蓝地图位置、窗口分离、固定体位、穿脱装备、tooltip、
快捷键与失败资源恢复。遵守仓库标准 gate，生命周期与驻留相关修改增加 500 次世界替换 soak。
