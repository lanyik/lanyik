# App 开发设计：生存 RPG 战斗应用

状态：`apps/survivor` 已实现地域生态与装备构筑切片。本文描述当前代码的架构、权威状态、结算顺序、
渲染和生命周期合同。玩家体验见[游戏想法](../游戏想法.md)，精确数值与状态转换见
[战斗、成长与装备](./game/combat-and-progression.md)。未实现内容在文末单独列出。

## 1. 应用与基建边界

应用采用模块化单体，由纯数据战斗核心、地图适配层、批量表现层、React HUD 和组合入口组成。
战斗核心不导入 Three.js、React、DOM、Worker 或地图内部模块；世界只负责地形与表现，不拥有
玩家生命、怪物、经验或装备事实。

```text
apps/survivor/
  src/
    core/
      CombatSimulation.ts       # 战斗、生成、拾取、等级、背包与穿戴的唯一写入者
      RegionalWorld.ts          # 四圈区块、确定性地域、人口槽与每轮宝箱/Boss 消费记录
      Equipment.ts              # 十一部位、等级/星级/品质、38 种词条目录与聚合
      CombatStats.ts            # 属性上限、溢出转换与伤害公式
      DeterministicRandom.ts     # 战局随机状态
      FixedStepClock.ts          # 墙钟到固定 tick 的有界转换
    app/
      CombatView.ts              # 核心之外的最小表现端口
      CombatSession.ts           # 会话、命令、页面可见性和 UI 发布
      bootstrap.tsx              # 依赖组合与生命周期
    adapters/
      HexCombatView.ts           # 无限世界加载、出生搜索、镜头和输入组合
    presentation/
      CombatLayer.ts             # Three.js 常驻角色与实例化实体池
      MovementInputController.ts # 相对镜头 WASD 输入
      App.tsx / app.css          # HUD、属性与装备交互
  tests/                         # 核心合同与浏览器验收
```

根包新增的 `cameraPanEnabled` 和 `setCameraTarget(worldX, worldZ)` 是通用公开能力：前者明确转移
键盘/触摸平移所有权，后者在浮动原点下连续跟随逻辑坐标。应用不访问 `HexMap` 私有控制器。

## 2. 权威状态与写入所有权

每局只有一个 `CombatSimulation`。它拥有：

- 玩家连续位置、朝向、生命、等级、经验、金币、属性点、免伤盾与受击保护；
- 怪物、弹道、经验球、地面装备与宝箱的活跃池；
- 已穿戴装备、背包、地面装备对象表及稳定 ID 分配；
- 区块生态、地域内容、人口槽冷却、普通攻击/脉冲冷却、击杀数、战斗 tick 与确定随机状态；
- 待交给会话展示的等级、拾取、穿戴与死亡通知。

`CombatSession` 拥有是否暂停/隐藏、加载状态和通知显示期限，不修改战斗表。`CombatLayer` 只读取
短生命周期渲染视图。React 只读取冻结的低频 `SessionSnapshot` 并发送 `allocate`、`equip`、
`discard`、`toggle-pause` 或 `restart` 命令。

地图 `WorldSource`、区块、地形高度、Three.js 对象和 DOM 输入不进入战斗快照。装备对象变化频率
低且需要界面展示，使用冻结对象；高频实体使用紧凑数组，不把数百个怪物复制进 React 状态。

## 3. 固定步长与帧顺序

权威战斗步长为 20ms（50Hz）。`FixedStepClock` 把 `requestAnimationFrame` 时间戳换算成完整 tick，
最多接受单帧 250ms 的墙钟时间；多余后台时间被丢弃，不追赶离线收益。渲染用剩余比例在上一个
和当前权威位置间插值，显示刷新率不会改变战斗结果。

单个 `CombatSimulation.step()` 的固定顺序为：

1. 保存玩家前一位置，更新无敌时间并应用归一化移动输入；
2. 同步玩家周围的四圈区块，清理外圈实体，按地域人口槽和死亡冷却补充怪物；
3. 自动选择攻击范围内最近怪物，结算伤害浮动和暴击并创建弹道；
4. 推进弹道并以线段扫掠检测命中，死亡立即提交经验与可能的装备掉落；
5. 结算就绪的范围脉冲技能；按圈层频率推进怪物追击或回归领地，结算接触伤害和反伤；
6. 推进经验球吸附和升级；
7. 检查地面装备拾取与背包容量；
8. 检查附近宝箱，原子提交奖励与消费记录；每 25 tick 结算一次生命回复，失效低频快照。

同一种子、初始位置和输入序列产生相同战斗与掉落状态。异步区块完成顺序不参与战斗随机数。

## 4. 高频实体数据布局

首版使用 swap-remove 的预分配 Structure-of-Arrays 数据池：

| 实体 | 上限 | 主要数组 | 满载规则 |
|---|---:|---|---|
| 怪物 | 640 | ID、类型、精英/Boss、圈层可见性、位置、出生位置、生命、速度、伤害、半径、受击闪烁；另存所属区块引用与槽号 | 生成器停止增加活怪 |
| 弹道 | 128 | 位置、前一位置、速度、伤害、寿命、暴击 | 武器等待可用槽位 |
| 经验球 | 768 | 位置、前一位置、经验值 | 满池新经验合并到索引 0，容量溢出时价值守恒 |
| 地面装备 | 64 | 装备 ID、品质、位置 | 暂停新装备生成，现有装备保留 |
| 宝箱表现 | 49 | 档位、位置 | 仅由常驻区块内的未开宝箱生成，显示内圈 |

池容量是公开玩法合同。正常 tick 对活跃前缀作连续内存扫描；没有逐怪事件对象、ECS 查询、每 tick
Map 空间分桶或全状态深拷贝。当前上限下，自动索敌和弹道命中直接扫描活怪前缀，保持简单且缓存
友好；只有真实性能数据证明这部分成为热点时才引入空间索引。

`RegionalWorld` 按出生点对齐 12×12 玩法区块，49 个常驻区块分成 9 个实时、16 个低频、24 个静态。
只有跨区块时重建驻留窗口；普通补充每 10 tick 执行，低频 AI 按实体 ID 错峰。
怪物保留出生区块引用，引用的 `resident` 失效时移除实体并清空池引用，不长期持有已卸载区块。
追击只发生在内圈和出生点 14 单位范围内，失去目标后返回领地，已删除旧的远距搬运逻辑。
经验与地面装备离开外圈时清理，地面对象表与数值池一起移除。

地域覆盖 3×3 玩法区块，决定人口、精英比例、强度和物品等级，恐怖地域中心有单独 Boss 槽。
每轮 180 秒的宝箱/Boss 消费集合跨卸载保留，到新一轮清空；不会按战局总时长累积历史。
具体空间生成、容量和消费边界见玩法合同。

## 5. RPG 状态

装备包含稳定 ID、槽位、品质、星级、物品等级、名称、基础值、显式词条、聚合值和综合战力。
随机顺序为槽位、品质、星级、无重复词条和名称；等级来自地域与奖励种类。
等级控制基础属性，星级控制 2/3/4 条词条，品质控制词条颜色与数值档位。

`sumEquipment()` 是装备加成的唯一聚合入口。角色派生属性由等级、四项基础属性和十一个装备槽
重新计算。穿戴命令先验证背包身份，再在一个同步操作中移除新装备、放回旧装备、替换槽位并更新
派生值；背包不会出现半交换状态。丢弃只接受背包 ID，不能误删已装备或地面物品。

经验只有被吸附并接触玩家后结算。一次大经验可连续升级，每级增加 2 点未分配属性；加点命令检查
枚举与余额。最大生命变化保持当前生命比例并封顶，禁止穿脱生命装备制造免费治疗。
属性派生与攻防公式集中在 `CombatStats.ts`；暴击失败才判断卓越，致命独立判断，生命抽取按最大生命千分比计算。
吸血只按实际敌方扣血计算；反伤只由真实受伤触发，不递归触发其他攻击效果。
基础脉冲技能和单次免伤盾均具有真实冷却，施法速度和盾恢复词条参与实际玩法。

## 6. 世界、镜头与渲染

`HexCombatView` 使用与 `ProceduralWorldSource` 相同的水体配置创建同步 surface resolver，在最多
14 圈候选范围内寻找 5×5 连续非水、非山、非湖地面。找不到时明确失败，不无限更换随机种子。
随后由 `HexMap.loadWorld()` 接管 source 所有权并以出生格为流式加载中心。

战斗坐标使用 tileSize=1 的逻辑 X/Z；表现层根节点按实际地图 tileSize 缩放。`CombatLayer` 为怪物、弹道、
经验与装备各持有一个预分配 `InstancedMesh`，宝箱体/盖/锁分别持有固定实例池。
怪物仅压紧提交内圈实例；颜色缓存使用压紧后的实例索引。角色是一个常驻基础
几何组合。实例禁用 Three.js 自身视锥剔除，由数量上限和围绕玩家的模拟范围约束；地图地形仍使用
自己的区块剔除和 LOD。

实体高度按其最近六边形格中心采样并缓存，避免每个实体每帧执行连续地表求值。缓存最多 4096 格，
达到上限、世界卸载或 surface 版本变化时清空。战斗实例不注册为地图渲染块并明确关闭 Three.js
实例视锥剔除，因此矩阵更新不把地图区块可见性标记为脏；镜头自身的位移阈值负责更新地形流送。

镜头每帧跟随插值后的玩家逻辑位置。`setCameraTarget()` 同时平移相机和 orbit target、读取同一
surface 高度，并保持旋转/缩放偏移；世界根节点浮动重置不泄露到战斗坐标。

## 7. 会话与生命周期

`CombatSession.start()` 使用加载世代拒绝过期结果。开始加载时先停止时钟、清输入、清通知和旧
模拟；`HexCombatView` 在 `loadWorld()` 之前保留未发布 source，进入调用后由地图拥有，避免双方
重复释放。

页面隐藏、失焦、暂停、死亡与关闭都会停止或清空相应输入。恢复可见性只重新建立墙钟基准，不覆盖
用户主动暂停。`pagehide` 非往返缓存场景会停止应用帧并等待地图异步释放；重复关闭返回同一 Promise。

地图错误进入明确的 failed 状态并显示原因，用户可重新加载同一种子。当前没有伪造 2D 地图、降低
渲染质量或静默换种子的 fallback。

## 8. 构建、验证与产物

根工作区命令：

| 命令 | 作用 |
|---|---|
| `npm run app:dev` | 构建本地库、准备受控地形资产并启动 Vite |
| `npm run app:build` | 严格类型检查并生成生产应用 |
| `npm run app:typecheck` | 验证库公开类型与应用类型 |
| `npm run test:app` | 运行随机、装备、时钟、战斗与出生搜索测试 |
| `npm run test:app:e2e` | 在真实 Chromium 中验证加载、出怪、移动、暂停与装备面板 |

资产脚本只允许替换 `apps/survivor/.assets`，执行前校验 realpath 与父目录；源纹理、模型和 demo
产物不会被应用脚本删除。Vite 使用明确的 React、Three.js、世界运行时分组，避免把所有依赖强制
压进一个应用缓存块。
