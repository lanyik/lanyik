# 打造、寻宝共鸣与永久灵境

核心为 `Crafting.ts`、`AffixItem.ts`、`Orbs.ts`、`SpiritRealm.ts`；事务由 `CombatSimulation` 执行，界面为
`CraftingPanel.tsx` 和 `SpiritRealmPanel.tsx`。通用物品和自动清理见[物品合同](items.md)。

## 工坊与费用

J 打开工坊，背包的“打造”可直接定位物品。四个页签为词条提取、词条打入、装备继承、宝珠工坊。
左侧只有一个物品格子库，按品质、等级自动排序，支持名称搜索、部位/品质过滤，展示星级、等级、锁定及穿戴状态。
右侧为打造台：继承左槽放来源、右槽放目标，下方并排展示目标原词条与继承结果、费用和操作按钮。
点击槽位切换选材分类，点击格子或拖入槽位放置；来源只允许背包未锁定装备；
目标可为背包或穿戴中的装备。目标基础值、部位、等级、品质、星级均保留，只修改附加词条。

费用中的 `q` 为品质索引（白 0 至彩 5），`s` 为星数，`n` 为来源附加词条数量；费用统一向上取整。
四种不同已嵌宝珠触发折扣时，以下所有消耗乘 0.85，否则乘 1。

| 操作 | 结果 | 费用 |
|---|---|---|
| 提取 | 销毁整件来源装备，选中的一条成为 1 份精粹，其余全部消失 | `80 × (q来源+1) × (s来源+1)` 金币 |
| 打入 | 消耗 1 份精粹，覆盖目标指定的一条，原词条不返还 | `120 × (q目标+1) × (s目标+1) + 60 × (q精粹+1)` 金币 |
| 继承 | 消耗来源装备，目标全部附加词条替换为来源完整列表 | `4 × n × (1+abs(q来源-q目标)) × (1+abs(s来源-s目标))` 粉尘 |
| 分解宝珠 | 销毁背包宝珠，获得粉尘 | 无额外消耗，获得 `3^q` 粉尘 |
| 精炼宝珠 | 原 ID、类型保留，品质提升一档，必定成功，最高彩 | `12 × 3^q` 粉尘 |

装备生成时星数决定 2/3/4 条初始词条；继承后数量完全以来源为准，不按目标星级截断或补齐。
打入不能使同一装备出现两个同名属性。词条品质和值完整保留，装备品质不会再次乘算精粹数值。
基础值加新词条重新聚合、评分；穿戴目标还会重新计算角色属性，并按现有换装规则约束当前资源和冷却。

`quoteCraft` 是界面和权威模拟共用的纯预检：验证 ID/类型/装备 revision、来源锁、重复属性、费用和精粹容量。
预检在完整库存副本上确认容量，之后才原子提交移除、覆盖、堆叠与费用。失败不扣钱、不销毁、不消耗 ID。
穿戴、锁定和词条修改会增加装备 revision；弹窗保存 ID+revision，提交时发现装备变化则拒绝。
宝珠提交保存 ID+品质，精炼后旧请求失效；已嵌宝珠需先取下才能分解/精炼。粉尘不能由一次操作凭空增殖。
金币、粉尘、装备与精粹属于本局；本次只将灵境作为永久成长保存。

## 危险操作交互

提取/打入/继承、宝珠操作和背包手动回收使用同一原生模态 `dialog`，界面操作后仅弹一次。
同窗展示完成后的物品、完整词条、费用或收益、销毁/覆盖内容及不可撤销提示；取消默认获得焦点，Esc 取消。
提取可选“以后不再提示”，只保存这一项浏览器偏好；提取页可恢复确认。打入与继承每次必经这一个确认窗。
模态期间不响应移动和全局游戏快捷键；物品过期、死亡或余额不足禁用提交，权威模拟再次预检。

打入支持拖动精粹到目标具体词条，落点高亮和跟手提示；松手只打开确认，绝不直接扣费。
也可点选精粹、覆盖位置后点击打入，键盘支持空格拿起、数字选择槽位、Esc 取消。
提取台展示装备转化为精粹的结果；打入台展示精粹、目标和具体覆盖槽；宝珠台展示粉尘回收和精炼品质。
窄屏格子库和操作台纵向排列，格子库有界滚动，操作和关闭按钮保留，背后 HUD 收起。

## 寻宝共鸣

六槽解锁和四种宝珠类型保持原合同，不增加宝珠等级或随机小词条。

| 已嵌组合 | 效果 |
|---|---|
| 某一类型至少 2 颗 | 该类型所有宝珠的寻宝评分乘 1.25；四颗不会再乘一次 |
| 至少 3 种不同类型 | 击杀和宝箱金币加成 +25 个百分点 |
| 4 种类型齐全 | 提取、打入、继承、精炼消耗降低 15% |

配对强化和多样性效果可同时存在。最终评分仍进入原有收益递减公式；组合结果在嵌入/取下时缓存，击杀热路径不重新分组。
金币按 `基础金币 × (1+装备金币加成+共鸣金币加成)` 取整；寻宝不放大宝珠本身掉率或品质，灵魂始终每只怪 1 个。
粉尘在宝珠品质成长和装备继承之间形成资源选择；分解收益白/蓝/紫/金/钻/彩依次 1/3/9/27/81/243。

## 灵境与持久化

每只实际死亡的怪物自动提取 1 灵魂，普通怪、精英、领主相同；远离后卸载怪物不产生灵魂。
L 打开灵境，显示持有灵魂、成长进度、累计阶数及四项永久加点。
每阶固定消耗 1000 灵魂，玩家选择力量/体魄/敏捷/精神之一永久 +1；阶数为四项永久点数之和，不设置递增费用。
永久点数在开局时加入基础属性，和本局加点相加后走统一派生公式，不直接改装备或增加寻宝评分。

`SpiritRepository` 是 Worker 注入的异步端口，核心完全不依赖浏览器。
生产 `IndexedDBSpiritRepository` 使用当前 origin 的 `survivor-progression` 数据库、`spirit` 仓库和 `realm` 单键；
记录 `{souls, attributes, revision}`，读取时校验非负安全整数。不存在旧结构转换或静默回退。
Web Lock `survivor-spirit-profile` 独占写入；第二个同时运行的页面明确提示先关闭另一页，避免覆盖永久进度。
Worker 初始化先载入灵境；命令/固定步批次完成后，只有 revision 变化才执行一次严格持久化事务，提交完成后才发布状态。
因此 UI 已收到的击杀/成长已保存；未发布的在途批次若页面被终止，不承诺保存。没有逐 tick 写盘、定时自动保存或无界写队列。
保存失败进入明确错误状态并停止继续模拟，不假装保存成功。销毁等待在途写事务结束再关闭连接与释放锁。
死亡、重新开局、刷新保留灵境；清除站点数据会删除它。没有跨浏览器/设备同步。
性能统计中的 `batchMs` 包含存储等待，`executeMs` 排除存储与碰撞等待，避免把 I/O 记为 CPU 执行。

## 验证

`Crafting.test.ts` 覆盖费用守恒、容量拒绝、源销毁、目标完整继承、词条重算、重复提交、锁定、精炼与共鸣。
`SpiritRealm.test.ts` 覆盖每怪 1 灵魂、每阶 1000、开局永久属性、非法存档及落盘先于状态发布、失败后停止。
`crafting-spirit.spec.ts` 使用真实 Worker/IndexedDB/WebGL，验证单次确认、提取偏好、格子拖动打入、继承、分解和刷新/重开保留。
