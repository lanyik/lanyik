# 地形通行与刷怪

导航：[总导航 · 游戏设计](../README.md#game) · [按任务阅读](../README.md#routes)

`CombatEnvironment.ts` 固定渲染与权威模拟共享的高度、格子尺度、森林密度和水岸参数。
荒野生产模拟 Worker 注入 `ProceduralCombatTerrain`，家园注入 [HomesteadTerrain](exploration-and-homestead.md)；独立单测/数值基准的开放战斗场使用 `OPEN_TERRAIN`，生产不存在查询失败后放行的降级路径。

## 通行数据

游戏单位为世界显示单位的 1/34。导航区块为 12×12 游戏单位，格距 0.5，每块 24×24 个阻挡标记。
区块首次访问时用同一种子和水体参数解析地格，复用 `WorldSurfaceView` 的共享顶角宏观高度；保留 25×25 的 Float64 高度及 Uint8 水体标记，临时采样窗口随后释放。攻击高度查询对这个 0.5 单位栅格做双线性插值；这是宏观表面的近似，不包含着色器微位移。
每格四角水体判定和高度梯度生成阻挡：海、岸水、湖、河禁止进入，采样坡度超过 40° 禁止进入。
角色以身体圆与阻挡格方框相交检查，因此水边和陡坡边缘有半格级的保守余量；此处是宏观地表导航，不把着色器微位移当成可攀爬细节。
净空查询与移动共用接触几何；只问是否阻挡时首个有效接触即可结束，移动仍求最深接触及其法线。相切也属于阻挡，查询顺序不改变地形事实。

`generateWorldTreePositions` 复用渲染端 `buildForestLod` 的近景候选、水岸间距、稳定优先级、气候密度与抖动尺度。
树干使用半径 `0.2×树尺度` 的圆柱足迹；树冠不作为墙。近景树干和碰撞使用同一位置，远景 LOD 裁剪不会改变通行性。
缓存最多 121 块，超过时逐块淘汰，销毁清空；缓存外再次进入按坐标确定性重建，不随旅行无限增长。
高度/攻击扫掠会连续查询同一区块，因此另保留最近一次区块的坐标和同一个对象引用，命中时不重复分配字符串键和查询 Map。切块时替换，构建异常时不保留错误坐标对应的旧对象，销毁时清空；不增加区块容量、不改变淘汰次序、采样或碰撞规则。

## 移动与出生

玩家普通移动、怪物巡逻/追击/回家、冲锋和玩家冲刺全部经过 `CombatWorld.moveActor`。
`SurfaceMotion` 将移动段按最多 0.15 游戏单位分段，在受阻段内二分九次定位接触点，再将剩余位移投影到接触面的切线。每段最多解四次接触；墙角可以停止，不能穿透。普通移动不再按 X/Z 轴分别尝试；冲锋/冲刺保持方向并精确停在接触前。
树干使用圆接触法线，几乎正面撞树时，给剩余速度 30% 的稳定肩侧偏移，连续绕过圆柱；不对墙面或封闭角落强行侧移。
玩家速度以 36/s 指数响应追踪输入，碰撞后只保留实际完成的速度；松键短暂减速，碰墙不会积蓄速度。朝向取真实位移，表现端以 24/s 平滑转身，停走动作使用 140ms 姿势过渡。
怪物直行完全受阻时最多尝试左右 60° 两个局部方向绕树；持续受阻的追击、寻射线与归位进入[有总预算的局部寻路](simulation-and-ai.md#受阻寻路与群体占位)，封闭障碍不会被强行穿透。

玩家挂机和怪物绕障共用局部 A* 算法，搜索缓冲与预算分别归各控制器；四邻接节点沿用实际身体半径加半格的净空余量，首段额外扫掠，压缩路径保留转折。占位分离、实际走路与短距离闪避仍经 `CombatWorld.moveActor`，不触发基础库的跨区块寻路服务。预算、取消与失败语义归[模拟与 AI](simulation-and-ai.md#受阻寻路与群体占位)。

出生搜索保留连续干地条件，额外验证玩家周围 0.6 单位净空。
世界地图的 `teleport` 命令由模拟 Worker 串行提交，要求有限坐标、通过[探索权限](exploration-and-homestead.md#探索与传送)，并用玩家身体半径检查落点净空；水域、陡坡、树干、家园建筑或边界等阻挡位置拒绝并发布提示，不搜索或替换其他落点。
成功后同时设置当前/上一帧位置，清移动惯性并结束冲刺，按已有规则同步玩法驻留、遭遇可达性、宝箱和当前地域；不扫掠跨越的路线，不修改内容原点、角色成长或冷却。镜头从权威位置更新，存档仍保存原点与新玩家坐标。关闭/查询未完成的模拟不接受传送，死亡时忽略。
区域怪物以聚落为单位生成候选，组合见[行为合同](simulation-and-ai.md)。实际落点由下述连通布局选择；单位围绕各自出生岗位巡逻、脱战归位。掉落物吸附独立于生物通行规则。

## 遭遇布局与可达性

渲染地形的生成 Worker 与[地图流送](../render-streaming.md)不负责玩法区块。玩法碰撞地形、遭遇布局和导航由战斗 Worker 独占；`RegionalWorld` 将准备与驻留提交分开。普通移动接近边界时，按实际移动方向每 tick 最多提前准备一块；转向时丢弃不属于新目标窗口的准备结果。初始化、读档、冲刺跨区或传送缺块时，每完成一块便让出事件循环，全部完成后按固定顺序一次性切换驻留、传播可达性和启用遭遇。等待期间不推进下一个 tick、不发布部分结果、不消费出生槽，也不改动模拟随机流；传送落点和冷却只在提交时改变。

驻留仍最多 81 块；常规相邻窗口最多额外准备 17 块，远距切换的准备队列/结果合计最多 81 块，切换前可同时保留旧 81 块。地形缓存仍最多 121 块。准备结果属于当前模拟，销毁清空队列并阻止迟到提交。单个区块仍是不可抢占的同步生成任务，分批不承诺单块或整 tick 永远低于预算；失败直接终止所属会话，不跳过碰撞或临时生成空白区块。离线立即执行器显式同步排空相同任务，用于 CPU 基准和确定性回放；生产路径缺少准备结果时明确报错。

`EncounterNavigation` 随每个玩法驻留区块创建 24×24 的四邻接连通标签。节点中心用玩家半径 0.3 加半格 0.25 检查净空，这个余量覆盖整条相邻节点连线；不沿对角线穿过墙角。该网格和地形缓存分别按内容原点、世界原点定位，不能混用区块索引。
出生选点复用节点已证明的净空，小于等于该半径的身体无需重复查询静态地形；更大身体单独检查。从候选附近向外搜索，只有未访问节点的距离下界严格超过当前最优距离才停止，等距仍按原节点序号选择，不能因遍历顺序改变布局。

`RegionalWorld` 将候选投到最近合法节点，只在有区块边界入口的连通域放置遭遇，封闭小岛状空地不作为营地落点。领主先检查实际半径加 0.08 并预留空间，支持成员在同一连通域、营地中心三单位以内依次安排；所有成员仍留在原地域和所属区块内，保留种类、等级及精英抽样。身体与已安排成员留出净空，不足的成员不生成。宝箱以 0.45 半径选择同地域的合法节点，避开已安排的成员。布局只取决于种子与静态地形，卸载重建、接近方向或 Worker 完成次序不改变位置。

玩家每跨 0.5 单位网格或驻留窗口变化时，从当前位置用实际直线移动扫掠连接附近节点，经相邻区块边界节点传播可达标记。只有已证明可达的出生槽/宝箱可以启用；玩家三单位内的出生槽继续等待，成功创建实体后才消费槽。已证明的通行连接在本次驻留期间保留，卸载即释放；读档清除访问标记并从读档位置重新验证。开启宝箱还验证玩家到箱子的直接通行，不能隔着薄墙自动开启。

保证范围是当前最多 81 块中的保守四邻接通行网格，并结合本次驻留已走过的连接。它不承诺穿过不足 1.1 单位的窄道，也不搜索驻留窗口以外的绕路；无法证明的内容暂不启用，完全没有合法场地时不生成，不传送、不强制放行。这里不修改地形来修桥开山，战斗绕障和占位另由怪物控制器承担。

## 攻击遮挡

`CombatTerrain.height/traceAttack` 是模拟端的攻击事实来源。树干沿同源位置按半径 `0.2×树尺度`、高度 `2.5×树尺度` 的实心圆柱扫掠；树冠淡出不改变圆柱，树叶和完全水面栅格不挡攻击。山体使用缓存高度，水平每段最多 0.125 单位采样，首次穿入区间二分八次定位；水岸和陆地仍参与高度遮挡。树干求交为连续线段求交，高度场采样不声称覆盖任意薄的着色器细节。
同一点的水体判断与高度插值复用已经找到的区块和网格索引。树干底部高度首次查询后随所属区块缓存；仅用于当前静态地形，卸载/销毁一起释放，地形可变时必须重新审查失效边界。

普攻索敌、近战/冲锋/敌方特殊攻击命中、治疗以及脉冲/霜环都要求攻击者与目标身体中点之间无遮挡；连锁闪电的每一跳从上一个目标重新检查。施法释放再次检查遮挡，身体到实际手部的发射段也必须畅通。远程敌人处于射程内但视线受阻时使用 `Seek` 意图接近，不因普通射程停在原地，持续受阻时参与同一导航队列。

弹道保留权威当前/上一 tick 海拔与竖直速度，起点来自施法者脚下高度加实际手部高度，瞄准目标身体中部；角色碰撞为有高度的圆柱，不再命中头顶飞过的弹道。先找角色首次交点，再把环境扫掠截到该交点；截断参数保留 `32×Number.EPSILON` 的浮点舍入余量且不超出本 tick 末点，避免重建端点时漏掉恰好同点的障碍。环境在前或同点时优先阻挡，目标身后的墙不会撤销已经发生的命中。地面预警仍显示攻击范围，遮挡通过目标的命中筛选生效，不进行逐障碍特效网格裁剪。表现端只插值权威 XYZ，不再让弹道跟随沿途地面升降。

## 代价与验证

生成器 v22 保留低频陆地场 .014 与山脊场 .012，陆地噪声降为三层、山脊和谷地降为两层；局部细节频率 .145→.045、权重 .16→.035，权重回归大陆主体 .845，平原粗糙度高度项 .025→.004。地表纹理继续提供微细节，通行高度不再叠加密集短坡。
沿用连续丘陵项 .18、高山项 1.05、谷地山口和峰顶指数压缩。40° 阻挡规则不变，长坡和高山仍有地形约束。高程字段变化会改变地类、森林适宜度及排水选路，生成器身份升级至 22，不能把旧种子的所有河道坐标视为未变。
三个固定种子 `rift-ember-1`、`rift-pass-2`、`rift-forest-3`，在 [-128,128)² 地格间隔 2 采样，相邻格 relief×480 的二阶差绝对值 P95 从 9.41/10.92/11.79 降为 2.39/2.52/3.03；用于衡量碎小起伏，不等同于碰撞网格坡度。非海域一阶差估计 >40° 的比例从 1.47/1.58/.93% 降为 1.02/1.10/.61%，最大高度仍为 592/546/538。`terrainPlayability.test.ts` 锁定碎坡、高峰和陡坡保留的共同约束。
通行新增成本集中在首次区块构建，热路径只读附近阻挡格和树干圆，不运行世界噪声。
CPU 高度/水体栅格每块 5,625 字节，最多 121 块；遭遇连通标签每块 1,152 字节，另有有界边界节点与访问标记，按上述驻留及准备容量回收。通行和攻击遮挡不增加 GPU 材质、模型或绘制批次。
历史视野扩张、攻击遮挡与遭遇布局的 CPU、冷启动及缓存记录统一见[测量索引](../README.md#evidence)。这些是模拟 CPU 指标，不代表 GPU 帧率；不同人口、技能和驻留配置不能用于单独比较地形算法。

`ProceduralCombatTerrain.test.ts` 检查实际出生、宝箱和移动身体净空、冲刺不能穿过真实树干、负坐标重建及缓存上限。
`RegionalStreaming.test.ts` 检查逐块让出、预生成不提前启用、转向/对角/远距容量、传送原子性、销毁及失败；生产与立即执行器须保持玩法和随机状态一致。浏览器 `regional-streaming.spec.ts` 直接运行生产 Worker 入口，检查读档/远距传送只有完整状态发布，调度等待单独计时；它不包含 WebGL 帧率验证。
`EncounterNavigation.test.ts` 覆盖封闭空地、薄墙、对角墙角、跨区绕路、领主原中心受阻后的稳定落点、待启用出生槽和全阻挡地图；`AttackObstruction.test.ts` 覆盖遮挡先后、高速弹道、身体高度、施法中途失去视线及范围/连锁筛选。查询 Worker 回归比较带高度与环境遮挡的串行/并行提交。
`benchmark:app` 新增真实程序化地形场景，维持 3 ms/tick 门槛；浏览器仍需核对渲染、贴地和移动结果。

## 镜头与树林

OrbitControls 更新之后，`TerrainCamera` 沿当前轨道球面抬升镜头，保留观察距离，检查镜头及目标到镜头的视线。按净空间距采样，最多 64 点、九次角度搜索；地形高度复用临时窗口，位置、地表版本和挂载版本不变时不重复采样。世界重载重置缓存；浮动原点转换回逻辑坐标后查询。这里解决地面和山体，不把树冠当成阻挡镜头的实体墙。

前景树木以玩家胸口附近为观察中心（高度 .9 游戏单位、半径 2，原为 1.3），仅淡出角色与镜头之间遮挡中心的枝干和叶片。屏幕空间稳定覆盖抖动保留最低 16% 的虚影，边缘连续恢复原状，角色后方及外围树林保持实心；共享实例材质、保留叶片 alpha-test、深度和战争迷雾，不逐树创建透明材质或新增绘制。
近地雾的内/浓/渐隐/外圈为 20/34/44/50 游戏单位；`WorldView` 统一远景地形雾 1156–1700 显示单位，地形距离 2312、植被距离 1700，植被 LOD 420/1000。远景雾取围绕镜头跟随目标的水平径向距离，并采样相同视线的天空颜色，完全入雾的高山不再留下加载轮廓。地形加载半径两块、保留半径三块，玩法驻留半径四块；怪物在 34–42 游戏单位淡出，44/46 唤醒/休眠，避免外围提前消失或静止。天空使用独立 HDR 立方体背景，不参与地形远景雾；资源成本见[环境资产](environment-assets.md)。生成器仍为 v22，本次不改变海拔与通行采样。

接触切线滑动与坡面分类参考 [Unreal SlideAlongSurface](https://dev.epicgames.com/documentation/unreal-engine/API/Runtime/Engine/UMovementComponent/SlideAlongSurface) 和 [Godot CharacterBody3D](https://docs.godotengine.org/zh-cn/4.x/classes/class_characterbody3d.html)；实现适配本项目固定 tick 的二维身体圆和权威高度场，不引入完整刚体引擎。
