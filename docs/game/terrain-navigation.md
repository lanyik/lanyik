# 地形通行与刷怪

`CombatEnvironment.ts` 固定渲染与权威模拟共享的高度、格子尺度、森林密度和水岸参数。
生产模拟 Worker 注入 `ProceduralCombatTerrain`；独立单测/数值基准的开放战斗场使用 `OPEN_TERRAIN`，生产不存在查询失败后放行的降级路径。

## 通行数据

游戏单位为世界显示单位的 1/34。导航区块为 12×12 游戏单位，格距 0.5，每块 24×24 个阻挡标记。
区块首次访问时用同一种子和水体参数解析地格，复用 `WorldSurfaceView` 的共享顶角宏观高度；临时采样窗口随后释放。
每格四角水体判定和高度梯度生成阻挡：海、岸水、湖、河禁止进入，采样坡度超过 40° 禁止进入。
角色以身体圆与阻挡格方框相交检查，因此水边和陡坡边缘有半格级的保守余量；此处是宏观地表导航，不把着色器微位移当成可攀爬细节。

`generateWorldTreePositions` 复用渲染端 `buildForestLod` 的近景候选、水岸间距、稳定优先级、气候密度与抖动尺度。
树干使用半径 `0.2×树尺度` 的圆柱足迹；树冠不作为墙。近景树干和碰撞使用同一位置，远景 LOD 裁剪不会改变通行性。
缓存最多 100 块，超过时逐块淘汰，销毁清空；缓存外再次进入按坐标确定性重建，不随旅行无限增长。

## 移动与出生

玩家普通移动、怪物巡逻/追击/回家、冲锋和玩家冲刺全部经过 `CombatWorld.moveActor`。
移动段按最多 0.15 游戏单位分段检查，防止高速冲刺穿树、越过窄阻挡。普通移动可沿 X/Z 滑动；冲锋/冲刺保持方向并在障碍前停止。
怪物直行完全受阻时最多尝试左右 60° 两个局部方向绕树；不在每怪每帧计算全局寻路，封闭障碍不会被强行穿透。

出生搜索保留连续干地条件，额外验证玩家周围 0.6 单位净空。
区域生成的怪物候选按实际普通/精英/领主体型半径加 0.08 检查，受阻候选不刷出；不向水上或陡坡补刷，也不通过重新掷随机数改变后续战利品。
宝箱使用 0.45 半径净空检查，受阻位置不显示、不开启。掉落物和弹道的既有规则独立于生物通行规则。

## 代价与验证

山脉采用生成器 v20 的更低频陆地高低与山脊场，不新增噪声场、顶点、纹理或 Worker 往返；会改变同种子的地形和依赖高程的河道。
通行新增成本集中在首次区块构建，热路径只读附近阻挡格和树干圆，不运行世界噪声。
在 i7-11700K / Node 22.16，五次样本的真实地形战斗中位数为 0.168 ms/tick，末次冷启动为 229 ms，运行期间缓存 72 块。
开放场旅行 0.066 ms/tick，640 怪物和 128 弹道 0.270 ms/tick；基准包含地形 CPU 查询，不包含浏览器、GPU 或 IndexedDB。

`ProceduralCombatTerrain.test.ts` 检查实际出生、宝箱和移动身体净空、冲刺不能穿过真实树干、负坐标重建及缓存上限。
`benchmark:app` 新增真实程序化地形场景，维持 3 ms/tick 门槛；浏览器仍需核对渲染、贴地和移动结果。
