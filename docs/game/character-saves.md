# 开始界面与角色存档

导航：[总导航 · 游戏设计](../README.md#game) · [按任务阅读](../README.md#routes)

`bootstrap` 先显示 `StartScreen`，点击开始/读档后才创建 HexMap、角色资源与战斗 Worker；返回主界面销毁这组资源。
开始界面提供 1–128 字世界种子、随机种子、继续最近一次有效存档以及四个固定存档槽。
新角色先进入家园，再从“出战荒野”前往种子世界；家园往返见[探索与家园](exploration-and-homestead.md)。
世界预览使用同一生成器、水体参数和总览栅格算法，展示中心 512×512 地格，192×192 像素；输入停顿 300 ms 后交给独立 Worker。
修改种子或离开主界面立即终止旧预览任务，完成后也终止 Worker；主界面不运行 3D 世界或战斗循环。

## 保存边界

- 一个自动槽，三个手动槽。开始/主界面读档完成、每 60 秒、切出页面、返回主界面和家园往返时保存自动槽；切换中不并发自动保存，手动槽只由用户操作覆盖。
- `O` 打开游戏与存档界面，暂停战斗；关闭只恢复由该界面暂停的战斗，保留玩家主动暂停。
- Worker 在前序命令和 tick 完成后导出 `CharacterCheckpoint`，不直接把 10 Hz HUD 快照当成存档。
- 主线程将小型角色记录写入 IndexedDB `survivor-characters/characters`，严格持久化事务完成后才显示已保存时间。
- 常规保存失败显示原因，旧记录保留，战斗继续；荒野死亡不会覆盖最后一次存活存档。副本奖励与死亡采用下述不可回退提交屏障。保存期间拒绝第二次保存，菜单禁用重复操作。
- 返回主界面先等待自动保存成功再销毁会话；保存失败留在游戏内。浏览器关闭事件不能保证异步写入完成，最近完成的自动/手动存档才是持久化边界。

## 存档内容与读档

保存种子、原始出生原点、角色位置/朝向、tick/击杀/宝箱计数、角色等级/经验/属性/剩余点数、金币、粉尘、全部背包类型、穿戴与嵌珠、物品 ID 分配器、自动回收设置与计数。
107 个节点的等级/revision、六个可空技能槽、点数、26 个技能冷却、共享动作恢复及玩家状态/疾行状态、生命/法力、药剂/攻击/免伤盾冷却和战斗随机数也保存。角色格式为 **version 8**：增加完整雷树、导电与静电防护；包含装备的 `autoEquipped` 自动穿戴经历（与单层 `locked` 独立）、当前位置所属世界、荒野返回坐标、稀疏探索页、越级传送期限、角色唯一 ID、副本提交 revision 与四位 Boss 挑战记录。旧版本明确拒绝，不迁移。Z 运行开关不保存，读档后仍需主动开启挂机。
运行时所有权见[战斗架构](combat-architecture.md)：经济字段恢复到 `CombatRewards`，受击保护和被动盾冷却恢复到 `CombatResolution`；八类标量状态逐来源保存强度和剩余 tick，灼烧单独保存每层来源、已快照每跳量、剩余 tick 和距下一跳的 tick。恢复不重复乘控制抗性/输出加成、不结算离线时间。自体来源对应新玩家，外部来源变成不可解析的独立分组，多次恢复保持独立，不能与新世界句柄串联。不保存临时事件、怪物 Buff 或在途技能；读档清除未出手动作、引导、火弹、持续场和轰击聚焦记录，已付法力、技能 CD、动作剩余恢复及玩家正负状态均保留。
节点校验包含角色等级、上下限、前置、购买顺序可达性、互斥专精；未用点加已花点严格等于等级减一。六槽允许 null，已装技能须已学且达到等级，同 ID 不能重复，最多一个终极。状态检查种类、有限强度、剩余 tick、来源唯一性和每种容量；普通状态总上限按各定义来源容量求和为 17，不再手写与目录无关的数量；不信任 UI 草稿。
灼烧保存至多四来源、每来源八层、合计 32 层；强度必须有限且为正，按剩余周期及八层计算的总量也必须有限，剩余时间为 1–7200 tick，距下一跳为 1–60 tick。尾段剩余可短于下一跳，这种层到期直接消失而不补伤。普通状态列表禁止混入 Burning，避免套用错误的刷新格式。
普通攻击剩余冷却始终非负：施法、冻结、弹道满池或发射被拒绝时只递减到零，不积累负冷却；成功射击才保留当 tick 的小数余量以维持射速。这样动作期间的自动/手动保存不会因负数被拒绝，恢复后也不会补发积欠攻击。校验仍拒绝外部传入的负冷却，不在保存入口修饰无效状态。
衍生属性由已保存的装备与角色成长重算，不从存档信任最终战力缓存。

荒野附近怪物、宝箱、弹道和未拾取掉落不存，荒野读档按原始出生原点重建附近遭遇；家园读档加载安全有界地图，保留独立的荒野返回位置。Boss 副本另保存本轮等级、61 个固定成员的生命/位置（0 生命永久表示已击杀）、离开位置、地面物品与经验、唯一宝箱领取状态；重建时只创建活着的怪。不保存副本怪物临时 Buff、攻击阶段和弹道，不能用于逐 tick 战场回放。
读档确认窗明确这个范围；读档完成后保持暂停，玩家查看状态后继续。
灵境沿用独立持久化档案；角色存档中的历史灵境加点先从基础属性扣除，再加上当前永久灵境成长，避免旧档回退或重复叠加。

O 窗口先选择存档卡，在列表下方统一保存/读取；自动槽不可手动覆盖，空槽不可读取。保存状态与“诊断与日志”位于内容顶部，底部固定继续游戏与保存返回主界面。
手动覆盖已有槽、游戏内读档各使用一个预览/提示合一的确认窗。空手动槽直接保存；开始界面明确提示新游戏会更新自动槽。
记录保存角色格式版本与地图生成器版本；不支持的版本显示不可读取，不做迁移或降级。单个损坏槽不阻挡其他槽读取。
读取时检查有限数值、物品类型/品质/堆叠、唯一 ID、装备部位、分类容量、技能装配等；生产 Worker 还检查种子/原点及角色位置净空。

## 副本不可回退的提交记录

`survivor-characters` 数据库版本 2 在四个 `characters` 槽之外增加 `challenge-progress`。角色 ID 在生产 Worker 首次创建角色时生成，检查点恢复原 ID。每个角色只保留一份最新提交，保存时清除不再被四个槽或当前角色引用的记录，因此最多五份；已有旧格式角色槽仍按版本校验拒绝读取。

副本击杀、拾取经验/物品、领取通关宝箱后，`CombatWorkerHost` 在发送快照与表现缓冲前，把完整角色状态、掉落随机数和副本状态一起写入自动槽及不可回退记录，使用同一个严格持久化事务。多条事实在一个 Worker 批次内合并一次写入，不逐 tick 无条件保存。入口扣卷轴和离开状态使用现有旅行保存屏障。常规自动/手动保存也更新已有副本记录。

`CharacterRepository.resolve` 在创建目标 3D 世界前比较角色 ID、提交 revision 和 tick。旧槽早于已提交记录时，加载完整的新状态，保留已消耗卷轴、经验、战利品与清场/领奖状态；存档确认窗明确说明这个规则。滞后的自动保存写入同样选取已提交的新状态，不能覆盖进度。新角色是独立 ID；仍被手动槽引用的老角色记录不会因新游戏被清除。

副本中死亡也提交：恢复点放入口、回满血蓝，已经击杀的怪不复活、未拾取奖励保留。R/刷新/读旧档均从已提交状态继续。该事务失败时不发布未持久化的奖励结果，Worker 进入明确失败状态；重试读取最后成功提交的记录。灵境仍由其独立仓库保存，单写者锁沿用现有 Worker 生命周期。

`CharacterSave.test.ts` 覆盖角色往返、永久灵境、非法数据、IndexedDB 重开和槽隔离、命令保存屏障。
`menu-saves.spec.ts` 通过真实 Worker 验证世界预览、手动保存、读档、刷新读取、自动保存返回主界面与窄屏布局。
