# 角色存档与永久进度

导航：[文档索引](../README.md#game)

本文约束保存范围、提交屏障和恢复所有权。字段布局、版本常量与数值上限直接查 [CharacterCheckpoint](../../apps/survivor/src/core/CharacterCheckpoint.ts)；槽读写归 [CharacterRepository](../../apps/survivor/src/app/CharacterRepository.ts)，Worker 提交归 [CombatWorkerHost](../../apps/survivor/src/worker/CombatWorkerHost.ts)。

## 会话入口与保存边界

bootstrap 先显示 StartScreen，开始或读档后才创建地图、资源和战斗 Worker；返回主界面销毁这组会话。种子预览使用同源生成器与独立 Worker，输入替换或退出取消旧任务，主界面不运行战斗循环。

角色有自动槽和手动槽。自动保存时机由应用统一管理，手动槽只由用户覆盖；世界切换期间不并发保存。存档界面暂停战斗，关闭时只恢复由该界面引起的暂停。

Worker 等前序命令和 tick 完成后导出权威检查点，不使用低频 HUD 快照代替。主线程在 IndexedDB 严格持久化事务完成后才显示保存成功，保存期间拒绝重复操作。

常规保存失败保留旧记录并显示原因，战斗可继续；返回主界面必须先保存成功，失败留在会话。荒野死亡不覆盖最后存活档。浏览器关闭不能保证异步保存完成，只有已经完成的提交是恢复边界。

## 保存范围与恢复

保存角色身份与职业、世界种子/原点/位置、成长、经济、全部库存与装配、ID 分配、随机状态、已提交构筑、技能 CD、动作剩余恢复及玩家状态。角色最终属性、战力和 UI 草稿不保存，恢复后从权威输入重算。

CombatSimulation 校验完整检查点与世界条件后，先恢复技能效果，再交给 CharacterState 恢复角色输入并按当前永久灵境重算派生属性，最后恢复生命/法力和世界实体。CharacterState 不访问存储。

字段以检查点类型及校验器为准。读取必须检查有限值、整数范围、唯一 ID、物品类型/部位/容量、构筑点数与可达性、装配和状态容量，不能信任来自 UI 或本地数据库的数据。生产 Worker 还校验世界身份和角色落点净空。

职业必须已登记，背包、身上和副本地面装备均需满足[职业归属合同](items.md#职业装备归属与产出)，已穿装备还需与当前职业相符。缺少职业身份或装备归属的旧格式直接拒绝，不根据武器名称猜测职业，也不补默认字段。

角色格式和生成器版本不匹配时明确拒绝，不迁移或降级；一个坏槽不阻挡其他槽读取。普通攻击冷却不允许负数，保存入口不能临时修饰非法状态来通过校验。

状态保存已生效强度、剩余模拟时间和来源分组；周期状态另存相位与输出，次数/盾回护等专属字段只能出现在对应状态。恢复不重复乘输出或控制抗性、不结算离线时间；自体来源绑定新玩家，外部来源变成不可解析且彼此独立的分组，不能与新世界同号实体合并。

不保存临时事件、荒野怪物 Buff、在途弹体和持续技能；恢复取消未出手动作与场，但保留已付费用、CD、动作恢复及合法玩家状态。自动战斗运行开关不恢复，读档完成保持暂停。

荒野怪物、宝箱、弹道和地面掉落不保存，按原始出生原点重建附近遭遇；家园保存独立荒野返回位置。副本保存本轮成员存活/生命/位置、地面奖励、领取和离开状态，重建只创建存活成员；不恢复临时攻击阶段和 Buff，因此不构成逐 tick 战场回放。

读档和覆盖确认必须说明这些边界及副本不可回退规则；具体窗口布局归[界面设计](interface-design.md)，旅行保存屏障归[探索与家园](exploration-and-homestead.md)。

## 副本不可回退的提交记录

角色拥有稳定 ID，检查点恢复同一 ID。角色数据库除存档槽外，每个被引用角色只保留最新挑战提交；回收不再被槽或当前角色引用的记录，不能保留无限提交历史。

副本击杀、领取经验/物品和通关奖励后，Worker 在发布快照与表现前，将角色状态、随机数和副本状态一起写入自动槽及不可回退记录，使用同一严格事务。一批事实合并写入，不逐 tick 无条件保存；入口扣卷轴与离开仍走旅行保存屏障。

读档在创建目标世界前比较角色 ID、提交 revision 和 tick。旧槽落后时采用完整已提交新状态，保留卷轴消耗、奖励与清场进度；滞后的自动保存也不能覆盖它。新角色使用独立 ID，仍被手动槽引用的角色记录不得误删。

副本死亡同样提交入口恢复点、恢复资源及已清场进度，已击杀成员不复活、未拾取奖励保留。重开/刷新/旧档从已提交状态继续。提交失败不发布未持久化奖励，Worker 明确失败，重试读取最后成功记录。

## 灵境与持久化

永久灵境由 [SpiritRealm](../../apps/survivor/src/core/SpiritRealm.ts) 定义，通过 Worker 的 [SpiritRepository](../../apps/survivor/src/worker/SpiritRepository.ts) 独立保存；核心只依赖异步端口，不访问 DOM。它属于当前浏览器来源的永久档案，不属于某个角色槽。

仓库使用独立 IndexedDB 记录并严格校验；Web Lock 保证单写者，另一个页面不能同时改写。初始化先读取，命令/tick 批次只在 revision 改变时保存，成功后再发布；不积累逐 tick 写队列。失败中止会话，关闭等待当前写入收尾再关闭库和释放锁。

已经向 UI 确认的灵魂和加点批次已持久化；未发布的在途进度不承诺保存。死亡、重开、刷新和读旧角色档不能回退永久成长。恢复角色时先扣除旧档基础属性中的历史灵境加点，再应用当前档案，避免双算。

角色与灵境分属两个存储边界，不宣称跨库原子恢复或跨浏览器同步；未来备份必须同时覆盖两者，待办见[开发重点](development-priorities.md)。

## 验证

CharacterSave、SpiritRealm、Crafting 及仓库/Worker 测试覆盖往返、非法字段、永久成长、旧档屏障、命令顺序、写入失败、关闭与槽隔离。menu-saves、crafting-spirit 和副本浏览器用例使用真实 Worker 与数据库。

命令与必跑组合见[测试策略](../testing.md)。增加字段时同步类型、导出、校验、恢复、版本及相关消费者；更新文档中的范围或提交合同，不逐项复制字段清单。
