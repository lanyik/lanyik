# 战斗结算与状态所有权

导航：[文档索引](../README.md#game)

本文维护数值提交、状态生命周期与后续系统接入约束。技能施法归[技能合同](skills-and-effects.md)，模拟/线程归[模拟与 AI](simulation-and-ai.md)，数值参数与私有执行步骤直接查代码。

调用方向为技能/普攻/怪物动作 → 命中请求 → 数值结算 → 生命提交 → 事实 → 奖励与表现。状态参与结算输入；常驻被动低频编译属性，不通过定时状态伪装。低频背包和角色命令仍在 CombatSimulation，不能将计划中的完整领域拆分当成现状。

## 结算与事件合同

命中请求保存完整实体句柄，跨阶段重新解析。已释放攻击可以在来源失效后造成伤害，但反伤、吸血返还等需要存活来源的操作必须重新确认身份，不能读取复用槽。

CombatVitality 返回实际生命损失/治疗量，吸血和飘字不能使用超过剩余生命的名义伤害。死亡只提交一次，死亡事实在实体移除前复制，奖励不回读已回收的槽。

防御、保护和吸收顺序由 CombatResolution 唯一维护。反伤直接提交生命损失，不再触发命中、吸血或新的反伤；双方同时死亡时保留既定事实顺序和随机消费顺序，不能因拆分模块改变奖励。

事件使用预分配有界缓冲，每笔结算及派生效果完成后同步消费，再进入下一笔。消费者借用当前记录，不能保存数组索引作为历史，也不能递归调用伤害或生命修改；重入和权威缓冲溢出明确失败。

权威事实和可丢弃视觉缓冲分开，表现丢弃不影响奖励。药剂、自然回复、升级及换装比例重算目前仍由角色命令处理；新增“任意治疗触发”前必须统一这些入口，不能假定现有战斗事件已覆盖全部生命变化。

## 状态合同

StatusSystem 是状态唯一拥有者，定义控制种类、强度、来源容量和期限；消费者只读投影和门禁，不直接写入。字段、上限和状态目录见实现，不在此维护第二张数值表。

普通标量状态按来源保存强度与期限。同来源刷新整体替换，不能拆开取最大；不同来源独立到期，弱效果不能给强效果续期。容量满时按已定义强度和稳定优先级准入，失败不部分修改。特殊状态的次数、吸收量和周期层使用各自有界数据，不混入普通刷新入口。

完整目标句柄失效时拒绝施加，非法参数明确报错；目标移除清空状态，来源失效不自动清除已附着效果。已快照强度不因来源换装重算。状态不创建逐项计时器或无限事件历史。

到期批次完成后发布新投影，下一模拟阶段必须立即看到正确移动、保护和控制状态；同批目标可去重计算，但不能把死亡、破盾或控制门禁推迟到帧尾。

冻结限制行动并取消未出手动作，保留 CD；不追溯撤销已释放攻击。免疫、抵抗、来源刷新与控制时长修正都在准入时处理，恢复存档不再次乘抗性。自然到期的后继抵抗从原截止 tick 计算，不能因跳步额外延长。

取消、耗尽、自然到期、净化、引爆和清理是不同原因，不能共用一个隐式“移除即触发”回调。范围持续场由技能拥有，附着在目标身上的周期状态由状态系统拥有。

## 灼烧与引爆合同

灼烧独立保存目标句柄、来源组、已快照每跳输出、期限和下一跳。成功命中且目标存活后才附加；闪避不附加，盾全吸收仍属于命中。来源消失可继续燃烧，目标移除立即清理。

来源数与每来源层数均有界。满层只按剩余未结算总量和稳定顺序替换符合条件的层，不刷新其他层，不预发伤害；缩小新施加上限不追溯删除旧层。周期包含恰好到期的末跳，不足完整周期的尾段不补跳。
已有来源追加/替换不重新统计不同来源；新来源准入只使用来源上限大小的临时去重缓冲，该缓冲独立于周期批次，回调中追加灼烧不能覆盖待结算数据。

捕获到期批次、推进层时钟与发布投影后再回调结算，回调新增层只参与后续批次。同 tick、同目标、同来源的周期量先合并，按完整身份稳定提交；死亡及槽复用不把旧批次作用于新实体。这个合并依赖当前没有逐跳命中触发器，增加触发器时必须重审。

周期伤害读取当前有效保护/护盾和适用防御，不重新走直接命中的闪避、暴击、吸血或反伤链；仍通过公共生命/死亡/奖励入口结算。

引爆只在直接命中成功后消费本人剩余灼烧，其他来源保留；已快照输出不能重复乘施放者增伤或再掷暴击。它作为该次直接命中的组成部分，不另造攻击链。自然到期、替换、移除和退款不触发引爆。

## 雷电命中与防护合同

导电、聚焦等命中后结果依据本次真实命中与完整目标句柄提交，闪避不累计，复用槽不继承；导电改变后续候选优先级，不隐含控制或额外伤害。

各系自体防护拥有独立类别，节点退款只移除对应来源/类别。Protection、StaticGuard 和 AstralGuard 由统一入口取有效最强值，各自到期；不能在各技能中重复相加或相乘。周期伤害不冒充直接命中来刷新防护。

## 星辰强化防护与净化合同

同次施放的星能获取有统一消费标记，不能按命中目标数量重复获取。虚弱读取可解析来源的当前状态，不改变已快照灼烧或失效来源的槽数据。

Empowered 整体比较强度、次数和期限，不能让较弱效果延长更强效果。灌注成功写入后才消费星能；伤害技能全部准入成功后每次起手扣一次强化，整次施法和最后一次都使用完整快照，不逐目标/弹体/周期扣次。失败施放不扣，空放或之后中断不返还。

净化只在出手阶段执行，仍受起手控制门禁；按稳定优先级和有限预算移除来源组，不触发跳伤、引爆或自然到期逻辑。未选中状态照常计时。

壁垒与结界共用一个吸收盾，替换时强度、期限和回护快照整体替换，不相加或继承旧回护。破盾先提交溢出伤害，仍存活才治疗；致死溢出不复活，到期/替换/清理不治疗。保护减伤与盾量分别拥有生命周期。

## 保存与表现

状态保存来源分组和剩余时间，周期保存输出与相位，次数/回护等特殊数据按定义校验。外部来源恢复为不可解析的独立分组，不能连到新世界实体；不重复叠加输出或抗性，也不结算离线时间。详细范围归[角色存档](character-saves.md)。

CombatEvents 留在权威 Worker 同步消费，主线程只读快照和表现帧。视觉、UI 草稿或动画不得反向决定伤害与状态期限。

## 后续接入边界

沉默、元素抗性和通用触发被动尚未形成完整协议；吸血、反伤与回护仍是明确的现有规则。新增消费者时再定义效果身份、来源、触发阶段、容量与取消语义，禁止以事件回调递归造成伤害，不预造无消费者的注册框架。

套装复用装备变更后的属性编译；连携先定义条件、窗口、资源和优先级，不能看特效是否重叠决定触发。任务与剧情需要稳定地点/任务身份及持久进度，不能长期保存 ECS 句柄。开发顺序只维护在[开发重点](development-priorities.md)。

## 验证

StatusSystem、BurnSystem 和 CombatEvents 测试保护来源、到期、槽复用、实际生命变化、死亡去重、防重入、取消与存档。结算重构用固定种子比较玩法快照及随机检查点；性能优化不得排除生命、奖励或随机数差异。

[测试策略](../testing.md)维护执行命令；[管线测量](measurements/combat-pipeline-optimization.json)是历史对照证据，不能替代当前验证或完整遭遇平衡。
