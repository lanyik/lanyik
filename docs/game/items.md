## 类型、身份与库存

物品以类型区分合法字段和操作，技能使用自己的语义值而不占背包；装备等级不能扩散成所有物品的必填字段。品质、星级、物品等级是独立维度，名称和图标不能只靠颜色表达差异。

库存按分类容量管理，ID 是操作身份，排序索引不是。整理不改身份、数量或货币；拖放、使用、打造和回收提交真实 ID，核心重新验证。React 不维护第二份库存规则。

同类堆叠必须满足完整兼容条件，不能仅因图标一致合并。部分插入后失败要恢复数量、ID 和顺序等事务状态；未领取的余额留在地面，不能先删除再尝试入包。

装备基础、词条和派生结果分开拥有。继承/移入词条保留既有数值，不重复按目标品质放大；派生属性读取不可变结果，外部不得修改缓存。

药剂 HUD 和实际使用选择同一核心规则，不依赖背包排序。卷轴消费属于[旅行与副本事务](exploration-and-homestead.md)，独立随机流不能借用战斗掷骰。

## 装备评价与预览

当前装备和候选装备在同一永久被动及成长上下文内计算，再统一应用最终属性上限；临时 Buff 不改变长期评分。比较分数用于配装取舍，不能解释为完整战斗 DPS。

预览复用真实装备替换的计算规则，结果必须与实际穿戴一致；更换装备保持生命/法力比例，不通过反复穿脱回复资源或刷新 CD。图标浮窗归 IconTooltip，详情说明和操作按钮不应各自复制一套评价算法。

## 自动配装与回收

自动配装在库存或相关属性变化时触发，不逐 tick 扫描全包。只接受严格改善，平分按稳定身份处理；装备使用有界槽位规划，宝珠使用受控组合空间，不做无限笛卡尔积。

计划与实际穿戴使用相同评分和寻宝期望。自动化不花费打造资源、不自动精炼、不绕过槽位解锁，也不能覆盖用户锁定。

locked 是单一保护状态；autoEquipped 仅记录自动穿戴经历，不构成另一层锁。手动操作按规则清理经历标记，自动换下不随意改变手动锁定。回收保护已装备、锁定及其他不满足核心准入的物品。

先配装再回收。整批领取/开箱把库存、装备、货币、ID 和随机状态作为同一计划提交，失败不能消耗箱子或部分吞物；保证奖励仍遵守保护规则。

满包领取的失败缓存只在真实输入变化后失效，容量有界。每 tick 配装规划有预算，失败尝试也占预算；未获处理的物品或箱子保留在世界，不能为赶进度跳过事务。

## 打造事务

来源材料取自未锁定背包；目标可以是合法背包物品或已穿装备。提取销毁来源；继承保留目标基础身份并替换完整词条列表，不能按目标星级偷偷截断。打入重复词条按核心规则拒绝。

quoteCraft 是共享纯预检。费用、来源/目标 ID、类型、revision、锁定、重复词条和容量全部通过后，在库存副本中形成完整结果，成功才提交材料销毁、扣费与 ID 分配。失败不改变任何资源。

装备穿戴、锁定和词条变化推进 revision，确认请求带 ID + revision；宝珠精炼后的旧品质请求同样失效。已嵌宝珠必须先卸下才能精炼，UI 禁用不能代替核心验证。

打造收入和支出属于角色存档；永久灵境独立拥有，不能被旧角色档回滚。粉尘、金币和数值费用只维护在核心定义及独立预期测试。

## 寻宝共鸣

嵌珠组合统一聚合数量、品质和星级评分，收益递减与最终概率由 Orbs 等核心入口计算；UI、自动配装和真实掉落不能各算一份。

组合缓存只在嵌入、移除等输入变化时更新，不把组合遍历放入每次击杀。评分不能自我放大宝珠掉率，有限上限和归一化由统一算法保证。槽位解锁规则查代码。

## 危险操作交互

破坏性操作使用一个合并结果预览、费用、销毁提示和确认的模态框，取消为默认安全操作，Esc 可关闭；模态期间阻断游戏全局输入。

只有允许的提取提示可以选择跳过；覆盖、继承等破坏性确认始终保留。确认后核心仍检查 revision 和全部准入，过期预览不能提交。拖放只发命令，悬停、拖动和取消不修改库存。

IconFrame 表达物品类型与值，不能用伪物品 ID 拼凑空槽。浮窗只由对应图标的 hover/focus 驱动，Alt 固定使用单一所有者；键盘、触屏、失焦和取消都走同一收尾边界。

## 验证

物品变更检查库存、EquipmentEvaluation、AutomaticLoadout、Crafting、Orbs 及命令测试，重点保护容量失败、身份稳定、锁定、过期确认、整批原子性和随机数不变。交互变更跑对应拖放、回收与 crafting-spirit 浏览器用例。

执行命令见[测试策略](../testing.md)。地面物品和图标资源的池上限、布局及视觉数值直接查表现代码，新增外部资源同步[资产来源](../README.md#assets)。
