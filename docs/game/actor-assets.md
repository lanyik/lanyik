## 离线处理

`npm run app:prepare` 在已验证位于应用目录内的 `.assets` 中生成生产文件。

1. 读取真实蒙皮与骨架，独立提取颜色、法线、金属/粗糙度和发光贴图。
2. 用 meshoptimizer 简化网格，保留法线、UV、蒙皮权重与骨骼索引变化；目标索引数为原来的 40%，
   误差上限 `.008`，实际数量由保真约束决定。头部按颈部高度裁掉隐藏身体，再压紧索引与顶点。
3. 用通用动作骨架的世界旋转增量映射到目标绑定姿势；保留目标肢体长度，只按髋骨高度比例传递上下起伏，
   不导入水平根运动。所有旋转归一化，缺动作或缺骨骼明确失败，不让局部身体静默留在 T 姿势。
4. 怪物烘焙八帧移动、八帧攻击与四帧待机 morph；主角保留蒙皮，将移动、出手、施法进入/引导/退出、受击、死亡和待机采样为 30Hz 骨骼片段。导入角色待机只取 `Idle_Loop`，不使用持剑/施法准备姿势。
   离线求值使用 LoopOnce 并锁定末帧，防止恰好采样 duration 时回到第一帧；循环 morph 不重复采样终点，骨骼轨道保留终点并优化冗余关键帧。原始法线与蒙皮权重一同保留。
5. 主角四张 1024² 图集，怪物各四张 512² 图集；材质区域有四像素边缘延展。
   UV 随图集重新映射，金属与粗糙度因子写入 ORM 通道，保留法线和眼睛发光。
6. 每组模型导出一个材质 primitive，共六个 GLB、二十四张图集。敌人删除运行时骨架，保持二十帧 morph；主角的服装和头部两套原始骨架合并为一个 Skeleton，共 130 骨骼、一个 SkinnedMesh，保留原始绑定逆矩阵及归一化根节点。主角动作时长/循环表同时生成 `HeroClips.generated.ts` 和 GLB extras，上身根骨骼也由构建写入；加载校验片段、骨骼分区与完整轨道，不能只修改运行时表。具体产物体积由生成 manifest 记录。未使用的独立 Imp 生产模型已移除，源 Imp 仍供术士使用。

| 生产模型 / 用途 | 基准身高 | 静止 / 移动 | 移动周期 | 攻击片段 | 三角形 |
|---|---:|---|---:|---|---:|
| Ranger / 守夜人 | 1.60 | Idle / Jog | 0.9333 秒 | Spell_Simple_Shoot / Enter / Idle / Exit | 14,084 |
| Puglin / 地精仆从 | 1.00 | Idle / Walk | 1.3333 秒 | Punch_Cross | 3,096 |
| Puglin_Brute / 赤脊冲锋者 | 1.00 | Idle / Walk | 1.3333 秒 | Sword_Attack | 3,096 |
| Imp_Shaman / 蓝色小恶魔术士，保留锁链、移除狼牙棒 | 1.25 | Idle / Jog | 0.9333 秒 | Spell_Simple_Enter → Shoot → Exit | 6,576 |
| RiftSpider / 裂隙蛛兽 | 约 .60 | Breathing / 八足交替步态 | .72 秒 | 前足抬起与毒牙前刺 | 9,192 |
| StoneSentinel / 裂岩守卫 | 约 1.50 | Breathing / 沉重步态 | 1.50 秒 | 双臂前击 | 3,760 |

赤脊冲锋者复用 Puglin_Brute 并染橙红，幽光祭司复用 Imp_Shaman 并染绿。
玩法 kind 与生产模型索引分离，由 `EnemyDefinitions.model` 映射；六种普通怪与三种新增领主使用五组敌人 GPU 资源。

程序化模型在构建时生成身体、关节、肢节和眼睛，三类动作保持相同拓扑；不把人形 UAL 绑定到八足骨架。八帧移动、八帧含首尾的攻击、四帧三秒呼吸使用相同求值函数。合并顶点时保留临时部件身份，防止接触部位误焊，全部 morph 同步重映射，随后删除临时属性。蛛兽使用代码生成的甲壳颜色/法线/粗糙度，岩石守卫使用已登记 CC0 Rocky Terrain；右半图集为发光眼睛/核心。两者单 primitive、顶点色与标准材质，无运行时建模、骨架或逐实体材质。程序化造型为项目作品，并非下载的专业雕刻角色。

运行时仍按核心半径缩放敌人，重卫、精英和领主因此具有更大轮廓。
裂爪领主和风暴先知采用术士变体，断层岩王复用岩卫，烬刃斗王复用 Puglin_Brute，后面三者分别使用淡紫、冷蓝和金橙染色。HUD 名称来自 `EnemyDefinitions`；基础数值与攻击时序由该目录决定。新领主复用已烘焙的施法、双臂攻击、剑击与移动动作，没有新增模型源文件或运行时骨架。
生成 manifest 顶层 frames / idleFrames 描述敌人的八帧移动和四帧待机；主角记录骨骼数量与片段，敌人记录 morph 总帧数。各模型保留周期、身高、网格、图集与产物字节数。

## 动作过渡与施法手部

敌人的 `ActorPoseMixer` 按 ECS 槽保存前一姿势、过渡起点、动作和完整实体句柄，固定容量 1857，总 CPU 缓冲 328,689 字节并进入表现资源账本。状态切换后 140ms smoothstep 混合，期间再次切换从当前混合姿势接续；槽复用或新世界重置不会继承上一只怪的姿势。移动、待机继续循环，攻击按权威 progress 播放，释放点仍为 .5；模型池压紧不会改变动画状态归属。

术士采用完整 Enter/Shoot/Exit 序列，占攻击阶段的 0–.43/.43–.64/.64–1，仍烘焙八个攻击采样。核查原骨架后使用 `hand_l`，将每个移动、攻击、待机采样的手部世界位置按相同身高归一化，写入 GLB 的 60 个 `castingHand` 数值。运行时手部飞刃和连线使用与网格相同的 morph 权重，不需要实时骨架。

`ActorSockets.generated.ts` 由同一构建步骤写入释放帧 11/12 的平均手部位置；模拟使用这个位置按真实朝向和普通/精英/领主体型缩放、旋转，生成整组弹道。构建缺骨骼、动作或手部曲线会明确失败。发射海拔取模拟缓存的身体脚下高度加手部高度；确认视线及身体到手部的发射段无遮挡后创建弹道。释放后保存权威海拔、上一海拔、竖直速度和年龄，表现只插值 XYZ，不再用 .45 秒衔接沿途地面高度。模拟高度场为同源宏观表面的 0.5 单位栅格近似；角色表现仍使用表面三角扇插值与微位移余量。

抬手飞刃和血契连线使用同一手部曲线，由独立的 `EnemyPresentation` 固定实例池提交；血契与领主攻击不复用玩家法阵，伤害/治疗时机由固定 tick 决定。岩卫石脊使用自身攻击姿势，不套用术士手部曲线；受祭司祝福的同伴显示三片护骨。新增法术不增加 GLB、骨架或动画池。测试覆盖姿势中断、句柄复用、导出曲线与模拟常量一致，以及不同朝向/体型的整组弹道只释放一次。
模型 extras 携带周期，运行时按模型自己的周期播放，不再固定假定全部为 0.8 秒。

## 主角动作与声音

`HeroPose` 选择上下身片段、相位与方向，`HeroAnimation` 独占骨骼采样和过渡缓存，不扩展敌人实例的帧数或槽缓存。髋部和腿部播放移动/待机，上身从两套骨架的 `spine_01` 向下独立播放出手或施法；切换用 120ms smoothstep 混合，中断时从当前混合姿势接续。首次播放和重置后直接建立有效姿势，不参与从未初始化数据出发的过渡；过渡期间每帧更新关节旋转与位置，不能停在旧姿势后跳到终点。瞄准扭转在基础混合后施加，不累积进下一帧姿势。

普攻只在成功创建弹道后开始出手动作；施法读取 SkillSystem 的实际阶段与 `castLocksMovement`。可移动施法保留腿部步态，只有真正锁住移动的前摇/引导使用全身施法，后摇释放腿部；取消后不继续假播。受击 `Hit_Chest` 优先覆盖上身，死亡 `Death01` 覆盖全身并具有最高优先级。

下身根据实际位移转向、按速度推进步态，上身根据真实出手方向瞄准，扭转限于左右 90°并分配给三个脊柱关节。向后移动攻击会转为反向步态，切换有角度滞回以避免边界抖动。源资产只有向前移动，当前反向采样不能替代专门制作的后退/侧移动作；普攻也仍借用通用施法片段，职业武器动作属于[视觉改造项目](visual-overhaul.md#角色技能与声音)。表现转向不改变命中、权威朝向或位移。

权威死亡立即停止玩法。常驻主角 SkinnedMesh 用有界表现时间完成非循环倒地并保持末帧；暂停、隐藏、加载、失败时冻结，恢复不补走离开期间的时间，新局重置。其余动画仍使用模拟时间。冻结不能把角色瞬间跳回第零帧；倒地后不再因受击无敌闪烁。

`PlayerFeedback` 是固定大小的表现投影，每类声音只保留最新事件 tick，同 tick 合并；实际释放、实际掉血和成功拾取才写入，闪避、完全吸收、献祭及失败拾取不伪造受击/拾取声。它不进存档、不消费玩法随机数、不参与规则；RenderFrame 复制投影，主线程不能借用权威可变对象。批量发布允许丢弃中间音效，过期、暂停和读档前事件不补播。

`CombatAudio` 归 HexCombatView，首次用户手势才创建并解锁一个 AudioContext。出手、施法、受伤、命中、拾取、倒地与轻风声由项目原创波形合成，来源见 `assets/audio/sources.json`，没有外部录音、配乐或配音；PCM 首次解锁生成并复用。近处命中按范围筛选，同类声音有最小间隔，最多八个短音和一个环境循环；满额按重要性替换，死亡先停止其他声部。总增益配合动态压缩限制叠音。

暂停、隐藏、加载、失败、切图立即停止声部，恢复从最新状态继续；异步解锁晚到不能复活已关闭实例。返回主界面/关闭释放节点、缓冲引用并关闭 AudioContext。浏览器拒绝解锁会显示可重试错误，不影响战斗权威。音效开关与音量放在 O 菜单，当前为会话设置，切图和重开保留、回主界面后重置；交互归[界面设计](interface-design.md)。

## 场景协调

应用的树木、岩地贴图与统一比例由[场景资产合同](environment-assets.md)定义；`land` 使用 Grass005 草地，饱和度 `.7`、亮度 `.95`。

## 运行时与所有权

当前角色参加[近景太阳阴影](../render-streaming.md#近景太阳阴影)：主角深度 pass 直接使用同一 Skeleton，敌人使用同一实例 morph 纹理，均投影并受影。敌人共享深度材质保留距离/出生区块 alpha-hash 淡出，与颜色 pass 同步，随 `ActorModels` 释放。实心敌方武器、岩石以及掉落实体/宝箱也投影并受影，深度材质由各表现池拥有并保留原距离淡出。已移除 `CombatLayer` 主角圆形假阴影的几何、材质和投影绘制；护盾环、危险预警等地面表现继续使用原投影图。

主角使用一个常驻 SkinnedMesh，颜色 pass 的服装与头部共一次绘制；五组敌人模型各一个固定容量 InstancedMesh，普通怪和领主共享池，最多五次敌人模型颜色绘制。阴影 pass 复用这些几何与实例，增加对应深度绘制。
每只怪物只写入变换、颜色和相邻两帧 morph 权重，不创建逐怪 Skeleton 或 AnimationMixer。
矩阵、颜色和出生锚的 GPU 更新范围仅为可见前缀；morphTexture 使用 RedFormat，按 Three 支持的整张纹理上传权重，空池不上传。
每局开始先清空实例池、技能和投影，并隐藏整个角色/雾根节点；等新局首个表现状态到达再显示，避免加载期间继续绘制上一局满载角色。
事实位置保留双精度，实例与出生锚写入相对插值玩家位置的局部坐标；根节点负责世界平移，避免远行时 Float32 位置量化。
敌人移动和待机相位由模拟动画时间、各自真实周期和实体 ID 确定；导入角色待机 2.5 秒，程序化怪物待机 3 秒，四帧不重复采样终点。切换至待机清空其他动作权重，再只写从 16 开始的待机区段，加载时严格校验帧数和周期。
敌人攻击权重由 ECS 动作进度确定，前摇与后摇各映射到动画一半，末帧不循环回首帧；切换动作清除另一组权重，暂停时随模拟冻结。
预警扇形/直线及敌方弹道颜色读取同一动作与阵营组件，具体规则见[战斗 ECS 与行为树](simulation-and-ai.md)。
颜色与发光图用 sRGB，法线与 ORM 保持线性数据。贴图使用无颜色转换、无预乘、无翻转的 ImageBitmap 解码，关闭 Texture.flipY 以匹配 glTF UV。

可见性与 AI 更新圈分离：`ActorVisibility.ts` 在玩家周围 34–42 逻辑单位 smoothstep 淡出，
接近时反向淡入，使用 alpha hash 保留深度写入。
距离取当前点和出生点到玩家距离的较大值；CPU 剔除时预留模型半径。
每个池保留固定 896×2 float 的 `actorHome` 属性，避免追兵在出生区块卸载时突然消失。
宝箱和地面物品继续共用距离淡出。

模型、四类贴图和[技能图集](skills-and-effects.md)首次异步加载，地图重载复用同一组资源。GLB 或贴图失败会释放已创建资源，
错误包含具体文件名，可在资源恢复后重试同一世界；预算申请通过后才挂载。
六个 GLB 与二十四张角色贴图共用有界并发队列，上限由 `GAME_CONFIG.presentation.assetLoadConcurrency` 指定，默认 4；技能图集单独加载。
初始化信号传入 fetch；取消或失败会停止队列和在途请求，立即释放已完成的半成品。
GLTF/ImageBitmap 解码任务取消时停止等待，晚到结果自行释放，包括主角 Skeleton；已建立 Texture 的像素位图随 texture.dispose 关闭。
主角 boneTexture 在预算核算前预分配，关键帧、插值器与分层缓存按底层缓冲去重后进入 CPU 账本；Skeleton 与骨骼纹理随角色资源关闭，切图只重置姿势并复用资源。
实例 morphTexture 按最大容量预分配，每只怪物一行含基准权重及二十个 morph 权重，使资源账本覆盖真实容量。
应用关闭时释放几何、材质、四类贴图、实例 morphTexture、补光、近战/冲锋预警池、敌方四组表现池、技能图集实例池、持续护罩、边缘雾与资源账本。
没有更改引擎的生命周期、资源核算、流送或调度语义。

## 验证

源文件检查与动作测试覆盖全部输入哈希、未登记输入、缺失动作/骨骼、真实怪物肢体长度不变、
水平根运动去除，以及动作切换回到相同姿势。
浏览器验收覆盖六个 GLB、二十四张贴图、移动时真实 morph 权重、每种怪物一个 primitive、
GLB 和法线图失败后的重试、外圈实例、装备交互、非循环攻击姿势与预警，以及关闭后 CPU/GPU 账本归零。
通过共享消息分类检查真实 WebGL 上传错误与图形 warning；只排除明确的截图 `ReadPixels` 读回性能提示。
单测还覆盖网络挂起、解码挂起期间取消的半成品/晚到资源释放，以及大坐标下小位移和可见前缀上传。
实机截图检查完整战场和模型细节；基建生命周期改动仍执行 500 次世界替换 soak。
主角与音频另有轻量 `hero-presentation.spec.ts`：单角色 256² 画面验证真实 GLB 的 130 骨骼、单次绘制、移动攻击保留腿部姿势、向后瞄准、倒地边界、浏览器音频解锁/波形/音量及释放；角色资源可进入现有预算并在关闭后归零，渲染器资源回到预热基线，不把 Three.js 自有 PBR 查找纹理算作角色泄漏。融合验收检查过渡中间帧的连续旋转并保留起点/中点/终点截图，不能只检查切换瞬间和完成后的姿势。单测另用已知角度保护上下身中点插值、半途取消、首次播放/重置的逐帧有效变换，并覆盖锁步施法及恢复、冻结、结算事实、传输隔离、音效去重、声部上限和晚到关闭。针对性轻量验收不代表整场战斗性能和听感已完成验证，全量压测与 soak 另行安排。
