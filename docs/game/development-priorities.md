# 荒原进度与开发重点

导航：[文档索引](../README.md#game)

状态复核：2026-09-25。本文只记录当前进度、尚未实现的能力和建议顺序；运行规则归各领域设计，参数与完成细节查代码，不在这里复写。

## 当前进度

已具备探索、战斗、掉落、配装、打造、角色存档和永久成长闭环。地图库已有流送、资源预算、恢复与诊断，游戏已有有界 ECS、权威 Worker、四系及通用构筑、常驻被动和批量表现。当前阶段适合继续完善可玩内容和代表场景验证。

| 领域 | 已有能力 | 仍需完成 |
|---|---|---|
| 战斗 | 普通怪/领主、四系技能与状态、攻击遮挡、权威弹道高度、自动战斗 | 怪物受阻寻路、战斗群体占位、主角攻击/受击/死亡演出和声音 |
| 成长 | 装备、词条打造、技能构筑、被动装配、宝珠、灵境 | 中后期与混系构筑、武器玩法差异、整场遭遇与经济节奏校准 |
| 世界 | 连续地貌、遭遇连通布局、探索迷雾、家园与卷轴副本 | 聚落实体、据点目标、区域差异及相应持久进度 |
| 产品 | 自动/手动存档、失败恢复、诊断导出、窄屏布局 | 新手引导、画质/输入设置、角色与灵境备份 |

## 优先：战斗可信度

攻击与移动已读取同源地表及树干遮挡，前景透视不会移除碰撞。遭遇布局在驻留窗口内证明入口连通，只有实际创建后消费出生槽；保证范围见[地形通行](terrain-navigation.md)。

怪物仍主要依赖局部滑行与偏转，可达性证明不等于能够绕过长墙或凹形障碍，也不等于围攻时已有同伴占位。下一步做有预算的受阻寻路和近身位置分配，以山口、凹墙、密林、河岸及围攻验证到达率、受阻时间、重叠和 CPU 成本。

主角已有移动/待机，攻击反馈、受击与死亡退场尚不完整，当前应用未接入声音。先补可辨认的前摇、命中、拾取和最小环境音；权威死亡立即退出战斗，退场表现使用独立有界池，音频按距离/重要性限声部。

## 优先：成长选择与完整校准

四系和通用构筑已经接入，不再以“增加技能点用途”为独立待办。先验证开局到首领及中后期、混系构筑的真实选择；每阶段同步 UI、存档、规则和验证。未来沉默、元素与触发被动协议仅随实际消费者推进，接入约束见[战斗架构](combat-architecture.md#后续接入边界)。

当前武器主要改变属性，尚无不同武器攻击方式。先实现少量有成本和弱点的差异构筑，例如射击节奏、近战反击、控制与连锁，再扩充数量；不先建立全功能效果框架。

[数值报告](combat-and-progression.md#数值校准)只覆盖参考装备的离线期望。需用固定种子的开局到首领样本，覆盖缺装、同级完整装、越级和高品质专精，记录死亡原因、击杀时间、回复占比、净收入、换装间隔和空跑时间。金币、粉尘已有支出，待评估的是节奏和收益感。

## 随后：探索片段与世界状态

家园和副本已有可玩入口及续战记录；家园经营、仓库、可建造设施和 NPC 尚未实现。荒野营地目前主要是怪物编组，尚缺依地貌布置的建筑、目标与专属产出。

先完成一个可重复的探索片段：发现地标、沿可通行路线接近、处理有配合的敌人、完成据点目标、挑战领主并获得改变下一次选择的奖励。用这个片段锁定节奏和美术样板，再扩充区域与大型任务。

荒野卸载/读档重建人口是当前规则，副本另有持久进度。增加据点或首杀奖励时，明确持续范围、重置时机和稳定地点身份，不能只在 HUD 留标记，也不能把地图库增量能力当作已经实现的游戏事件存档。

## 产品与性能验收

美术方向和资源边界归[环境资产](environment-assets.md)与[角色资产](actor-assets.md)。先统一主角、怪物、植被、建筑、地形及特效的比例、材质和轮廓；近景阴影等新通道由实际预算决定。

先补画质/分辨率比例、文字尺寸和控制说明，音频接入时同步音量设置。物品支持触屏拖拽不代表整款游戏已有移动端操控；手柄与触屏移动由目标平台决定。

长期游玩需要同时覆盖角色和永久灵境的备份入口，校验版本、部分损坏、中断和重复导入。当前诊断导出不能代替角色备份。

在明确设备与分辨率上测平原赶路、密林战斗、领主特效、满包开窗和跨区加载，记录 CPU/GPU 帧时分位、峰值资源与挂载长任务。[UI 测量](ui-performance.md)和历史 CPU 基准只证明各自场景；Windows 原生图形路径及目标设备仍需发布验收。

已补齐[CPU 尾延迟与阶段观测](measurements/performance-tail-latency.json)，并完成[首轮等价计算优化](measurements/performance-tail-optimization.json)。玩法区块现已采用提前准备与异步分块，[本轮记录](measurements/regional-streaming.json)中赶路/自动战斗最大 tick 明显下降，旧版回放和异步回放保持玩法、随机状态及布局一致；P99 和均值增加，不能将分摊工作描述为总计算量下降。

后续关注冷启动、远距传送中仍较重的单块/构造切片，以及灼烧周期结算和躲避首批决策。分块已经避免普通跨区一次生成整列，但不保证所有切片达标。平均门禁不证明峰值达标，阶段探针含额外开销，仍需目标设备完整场景确认输入延迟影响；尚未调整玩法或加入新的尾延迟硬门槛。

建议顺序：战斗可信度与构筑校准 → 探索片段及世界状态 → 内容扩充和产品设置。更多 Worker、全面改写 ECS 或切换 WebGPU 均不是当前玩法开发的前置条件，优化仍按[门禁](../optimization-gates.md)推进。
