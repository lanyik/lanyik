# 荒原进度与开发重点

导航：[文档索引](../README.md#game)

状态复核：2026-09-30。本文只记录当前进度、尚未实现的能力和建议顺序；运行规则归各领域设计，参数与完成细节查代码，不在这里复写。

## 当前进度

已具备探索、战斗、掉落、配装、打造、角色存档和永久成长闭环。地图库已有流送、资源预算、恢复与诊断，游戏已有有界 ECS、权威 Worker、四系及通用构筑、常驻被动和批量表现。现有六边形版本已留存，当前先完成连续世界基座设计与技术样板，再据验证结果扩展可玩内容。

## 当前优先：连续世界基座设计

冻结代码基线为 `8ce5429`，保留分支为 `release/2026-09-29-hex-world-baseline`。仓库选择、职责整理、Three.js 边界和实施顺序统一归[连续世界基座设计](../decisions/continuous-world-foundation.md)。已完成设计及首批仓库清理：浏览器产物改由本地构建，不再重复提交，旧截图与无关忽略模板已清理；未迁移源码或实现新地形。

当前开发已统一到 main，旧实验的留存位置见[分支与归档](../README.md#branches)。建议从 main 创建短期任务分支，先完成高程分块、地表查询与绘制的小样板，再接山系/河网、游戏流送和大气。有限/无限世界及平台要求仍待定案；现有基础机制可以复用，但地格载荷和消费者接线必须重新审查。新仓库不作为降低技术成本的默认手段。

## 随基座接续：写实暗黑视觉改造

[视觉改造项目](visual-overhaul.md)统一世界、角色、技能与游戏界面的标准、工作包及验收。方向与目标为写实暗黑、桌面独显 1440p / 60 FPS，正式目标硬件仍待确定。主角移动/攻击分层、B1 统一颜色输出/天空环境照明及 B2 近景动态阴影已完成；首领副本已接入营地→石路→河岸→首领的连续路线、首批扫描石材和原生 1440p 对照入口。荒野与副本树木已共用风动及同步阴影，副本连续岸坡、湿土、营火和倒木已接入。地形环境反射的粗糙度积分已修正；下一步优先建立山地结构和体积雾样板，补充低视角验收，再扩充废墟并评估向荒野推广；具体缺口归[山地与大气验收](visual-overhaul.md#山地与大气验收缺口)。HUD、背包与角色换装闭环及怪物/四系效果仍待后续。专业武器动作、完整世界样板与界面重设计尚未完成，不能用当前试装代表最终品质。

## 优先：战斗可信度

攻击与移动已读取同源地表及树干遮挡，前景透视不会移除碰撞。遭遇布局在驻留窗口内证明入口连通，只有实际创建后消费出生槽；保证范围见[地形通行](exploration-and-homestead.md#通行数据)。

怪物已有[有总预算的受阻寻路与近身占位](combat-architecture.md#受阻寻路与群体占位)，覆盖长墙、凹墙、脱战归位及外圈补位。接下来在真实山口、密林、河岸及混合体型围攻中检查到达率、受阻时间、重叠和战斗压力；局部搜索与软分离不承诺所有窄口和极端密度可解。

主角已接入[上下身分层、移动瞄准、受击和倒地动作及基础声音](assets.md#主角动作与声音)，可移动施法保留步态，实际锁步施法才使用全身动作；权威死亡立即停止玩法，常驻模型独立完成倒地。音频按范围、频率和重要性限声部，O 菜单可关闭和调音量。当前复用通用动画及原创合成音效，专业侧移/后退和武器动作、配音及配乐尚未实现。

## 优先：成长选择与完整校准

四系和通用构筑已经接入，不再以“增加技能点用途”为独立待办。先验证开局到首领及中后期、混系构筑的真实选择；每阶段同步 UI、存档、规则和验证。未来沉默、元素与触发被动协议仅随实际消费者推进，接入约束见[战斗架构](combat-architecture.md#后续接入边界)。

现有角色已登记为游侠，[职业与装备基座](items.md#职业装备归属与产出)覆盖身份、武器归属、标准防具的通用/专属限制及通用饰品规则。后续按角色职业设计技能、武器行为与整套装备，再接副本的职业定向套装产出；本期没有新职业、套装效果或饰品产出。饰品需独立设计稀缺来源，不放回常规随机池；不提前搭建没有实际内容的效果框架。

[数值报告](items.md#数值校准)只覆盖参考装备的离线期望。需用固定种子的开局到首领样本，覆盖缺装、同级完整装、越级和高品质专精，记录死亡原因、击杀时间、回复占比、净收入、换装间隔和空跑时间。金币、粉尘已有支出，待评估的是节奏和收益感。

## 随后：探索片段与世界状态

家园和副本已有可玩入口及续战记录；家园经营、仓库、可建造设施和 NPC 尚未实现。荒野营地目前主要是怪物编组，尚缺依地貌布置的建筑、目标与专属产出。

先完成一个可重复的探索片段：发现地标、沿可通行路线接近、处理有配合的敌人、完成据点目标、挑战领主并获得改变下一次选择的奖励。用这个片段锁定节奏和美术样板，再扩充区域与大型任务。

荒野卸载/读档重建人口是当前规则，副本另有持久进度。增加据点或首杀奖励时，明确持续范围、重置时机和稳定地点身份，不能只在 HUD 留标记，也不能把地图库增量能力当作已经实现的游戏事件存档。

## 产品与性能验收

画质目标与样板标准归[视觉改造项目](visual-overhaul.md)，当前资源边界归[资产与表现](assets.md)。视觉品质和 CPU/GPU 成本在同一可玩场景中评审。

先补画质/分辨率比例、文字尺寸和控制说明；音频已有会话内开关与音量，设置持久化待补。物品支持触屏拖拽不代表整款游戏已有移动端操控；手柄与触屏移动由目标平台决定。

长期游玩需要同时覆盖角色和永久灵境的备份入口，校验版本、部分损坏、中断和重复导入。当前诊断导出不能代替角色备份。

在明确设备与分辨率上测平原赶路、密林战斗、领主特效、满包开窗和跨区加载，记录 CPU/GPU 帧时分位、峰值资源与挂载长任务。[UI 测量](interface-design.md#更新与性能)和历史 CPU 基准只证明各自场景；Windows 原生图形路径及目标设备仍需发布验收。

CPU 基准已有尾延迟与阶段观测，玩法区块已采用提前准备与异步分块。后续优化需按[测试策略](../testing.md#benchmark-scope)重新测量，并比较权威状态、随机状态及布局；分摊工作不等于减少总计算量，也不保证所有切片达标。

后续关注冷启动、远距传送中仍较重的单块/构造切片，以及灼烧周期结算和躲避首批决策。分块已经避免普通跨区一次生成整列，但不保证所有切片达标。平均门禁不证明峰值达标，阶段探针含额外开销，仍需目标设备完整场景确认输入延迟影响；尚未调整玩法或加入新的尾延迟硬门槛。

建议顺序：连续世界设计与技术样板 → 写实暗黑可玩样板与游戏界面闭环 → 战斗可信度与构筑校准 → 探索片段及世界状态 → 内容扩充和产品设置。更多 Worker、全面改写 ECS 或切换 WebGPU 均不是当前开发的前置条件，优化仍按[门禁](../testing.md#优化门禁)推进。
