# 荒原下一阶段开发重点

导航：[总导航 · 游戏设计](../README.md#game) · [按任务阅读](../README.md#routes)

评估日期：2026-09-15，原评估代码基线 `44b2f23`；同日开始实施，以下已同步攻击遮挡、遭遇可达落点与战斗模块拆分的当前状态。本文区分已经实现的合同与建议中的后续设计；建议不表示对应功能已经接入。范围以 `apps/survivor` 为主，同时检查地图库边界、构建与现有测量。

## 当前判断

项目已经具备可运行的探索、战斗、掉落、换装、打造、存档和永久属性成长闭环。地图流送、Worker 所有权、有界 ECS、实例化、虚拟物品列表、失败恢复与诊断都有实现。下一阶段主要缺口是战斗规则与场景一致、持续成长的选择、值得探索的内容，以及完整的声音和角色演出。

不把存档、金币消费、地形通行、混合聚落、动作过渡、真实天空或伤害飘字重复列为待开发。它们已经存在，但有明确边界：角色存档不保存战场；聚落目前是编组；通行目前是局部移动约束；数值校准目前是参考装备下的离线期望。

| 领域 | 已有基础 | 仍需补齐 |
|---|---|---|
| 战斗 | 六类普通怪、四种领主、八技能与碎冰联动、结算飘字、攻击遮挡与权威弹道高度 | 受阻寻路、战斗群体占位、主角攻击与受击/死亡动作、声音 |
| 成长 | 11 部位装备、词条打造、八技能、宝珠、灵境 | 中后期技能点用途、改变玩法的武器/词条、成长节奏和整场遭遇校准 |
| 地图 | 连续地貌、通行、遭遇连通布局与可达启用、前景透视、天空与雾 | 更完整的行走路线、聚落实体、探索目标和区域差异 |
| 持久化 | 自动/手动角色存档、独立永久灵境 | 世界事件完成状态的产品规则、角色备份与导入导出 |
| 表现与性能 | 免费材质、LOD、实例化、UI 虚拟化、计时与预算 | 美术统一样板、目标设备完整场景帧时、画质设置 |

## 优先：战斗可信度与通行

**已完成第一批：攻击遮挡。** 原基线中阻止角色移动的屏障不会拦截弹道，最小复现的攻击环境查询次数为零。现在 `CombatTerrain.height/traceAttack` 为权威模拟提供同源宏观高度和实心树干查询；普攻、敌方攻击、范围技能、逐跳连锁与治疗检查遮挡。水面不吞掉空中弹道，树冠透视不移除树干。弹道保存真实海拔和竖直速度、扫掠有高度的角色身体，表现只插值同一轨迹；目标身后的墙不会撤销前方已经发生的命中。远程怪受阻时尝试接近射击位置。

**已完成第一批：遭遇连通布局与可达启用。** 原来的单点过滤会提前消费出生槽。现在 `EncounterNavigation` 在每个驻留块生成保守的四邻接连通域，营地移动到有边界入口的合法节点，先预留领主体型空间，再安排同域支持成员；宝箱也选择合法节点。相邻区块通过通行入口传播玩家可达标记；尚未可达或距玩家过近的出生槽等待，只有实际创建后才消费。布局保持种子确定性，成员和宝箱保留原地域归属，加载顺序不决定落点。

保证范围与限制见[地形通行](terrain-navigation.md)：这套图只覆盖最多 81 块的驻留窗口与本次驻留已证明的连接；半格安全余量会排除部分可步行的窄道。完全没有合法场地的内容不生成，不能证明可达的内容不启用；没有因此承诺每个恐怖地域都有可挑战的领主，也没有修改地形来修桥开山。

**仍待完成：受阻寻路与战斗占位。** `CombatSystems.moveEnemies` 仍依靠移动滑行和左右约 60° 局部偏转，没有逐怪路径搜索。连通域可证明存在路线，但不会自动引导怪物绕过长岩壁、凹形障碍和狭窄山口；出生时避免身体重叠也不等于战斗时有同伴占位。下一批应做有预算的受阻寻路和近身攻击位置分配，以山口、凹墙、密林、河岸和围攻场景验证完成率、持续受阻时间、重叠与 CPU 成本。

## 优先：成长节奏与构筑差异

**已完成支撑扩展的第一批拆分。** `CombatResolution`/`CombatVitality` 独立处理数值和实际生命变化，`StatusSystem` 接管减速、保护与结界，`CombatEvents` 为奖励和飘字提供独立结算事实，`CombatRewards` 持有击杀经济。下一步优先拆角色成长并接入技能树/属性修饰器，再明确 Buff 叠层与被动触发规则；套装/连携及任务/剧情依次消费这些规则，具体边界见[战斗架构](combat-architecture.md)。这些新增领域不要求全面替换 ECS，完整功能尚未实现。

**技能成长与等级跨度仍有间隔。** 2026-09-18 增加陨星、涡旋、刃阵及霜环→脉冲碎裂组合。`SkillSystem` 的八个技能初始均为 1 级，`GAME_CONFIG.skills.maxRank=5`，每次升级花 1 点，全系统有 32 次升级。角色每升一级仍发 1 点，最早角色 33 级全部点满，之后仍缺乏点数用途；额外宝珠槽在 50/100/150/200 级解锁。新增具体机制提供了早期构筑选择，尚未解决技能树和完整中后期成长。

应先定义希望玩家在前 20 分钟、第一只领主和后续区域分别获得什么选择，再决定等级带、技能点、宝珠槽与灵境里程碑。可以增加少量互斥技能改造或专精，并支持重新选择；不要用无限加技能等级来掩盖缺少玩法变化。

**武器和装备大多改变数字。** `Equipment.ts` 中弩、弓、月刃、战杖使用同一武器基础属性模型；`fireWeapon` 始终发射同一类自动索敌弹道，没有武器攻击类型。词条和宝珠已有取舍，但主要调整攻击、防御、概率和寻宝。后续应先做两到三种可辨认的构筑，例如射击节奏与弹道差异、近战范围与格挡反击、控制与连锁转化，并让装备或技能改造支撑它们；每一种都需有成本和弱点。

**现有数值报告没有覆盖完整养成。** [数值校准](combat-balance.md)验证同级完整蓝装、均衡加点下的普通命中和普攻期望，排除了走位、主动技能、吸血、岩卫姿态和祭司治疗等。它不能证明裸装开局、越级遇敌、全金装专精、治疗混编营地或长时间挂机均衡。直行性能基准会逐 tick 补满生命，也不构成生存证据。

后续需要固定种子的开局到首领游玩样本，记录死亡原因、击杀耗时、回复/吸血占比、资源净收入、换装间隔和空跑时间；覆盖缺装、同级完整装、越级、高品质专精。金币已有提取/打入等支出，粉尘已有精炼/继承支出，真正待评估的是这些收入和支出的节奏。灵境每 1000 击杀只换一项基础属性 +1，也需要验证获得时机与实际收益是否可感知。

## 随后：探索内容与世界状态

`RegionalWorld.SETTLEMENTS` 已有蛛巢、地精、祭司和混合营地编组，但地点主要由区块种子和地域难度决定，没有依据地貌选择的巢穴、营地建筑、哨兵警戒、事件目标或专属产出。所有恐怖地域领主仍复用同一套术士模型和行为，没有不同首领家族。

建议先完成一个约 15–20 分钟的可重复体验片段：发现一处有辨识度的营地，沿可通行路线接近，处理两种有配合的敌人，完成一个据点目标，挑战一只领主，获得能改变下一次战斗选择的奖励。地图用地标与目标状态引导玩家；生态可以将蛛巢放在林缘、掠夺营放在开阔通道，避免只按难度更换数字。先验证这个片段的探索节奏，再扩充地图数量和大型任务系统。

**世界状态需要与内容一起设计。** 当前角色存档有明确边界：怪物、宝箱、弹道和未拾取物品不保存；卸载重返也会重建人口。这个行为是现行规则，不是存档损坏。增加据点、首杀奖励和事件后，必须决定哪些状态持续、何时重置，并保存有界、可验证的事件/地点状态，不能只在 HUD 上记一个完成标记。地图库已有稀疏世界增量能力，但游戏并没有因此自动保存这些事件。

## 随后：动作、声音与美术统一

`ActorModels.animateHero` 只在移动/待机间切换，`HERO_POSES` 也仅包含这两类姿势；主角自动发射弹道时没有对应的武器动作。怪物已有攻击过渡、施法手轨迹与命中闪白，`CombatVitality.defeat` 记录死亡事实后立即移除实体，没有受击/死亡演出。当前应用入口和源码未接入音频资源或音频播放系统。

优先补主角攻击/施法与受击、短暂死亡退场、脚步、不同命中材质、敌方前摇提示、拾取和环境声音。战斗权威结算与演出分开，死亡实体立即失去战斗资格，退场演出使用独立有界池。音频按距离和事件重要性限声部，避免每次命中创建无上限播放器。

现有草土岩混合、免费树木、HDR 天空和雾已经改善环境，但主角、地精、程序化蛛兽/岩卫及 UI/掉落物的造型语言仍不一致。当前阴影主要是投影接触印记，尚未形成完整的场景动态阴影与间接光照。应先固定一个包含主角、敌人、树木、建筑、地形和战斗特效的美术样板，统一比例、材质响应、颜色和轮廓；之后依据实机预算选择近景阴影或遮蔽增强。继续增加贴图分辨率不能单独解决这些问题，新增视觉通道也不应绕过性能测量。

继续沿用免费、可离线构建的资源。需要账户领取、商用许可不明确或不允许源码分发的资产不应作为当前基础依赖。

## 产品设置与工程验证

当前有快捷键提示、键盘焦点、触屏物品拖拽和窄屏布局，但没有渐进式新手引导、可重绑输入或用户画质菜单。移动输入仍只有 WASD，不能因物品支持触屏拖拽就宣称整款游戏可在手机上操作。先补画质/分辨率比例、文字与飘字尺寸、控制说明；音频接入时同步音量/静音设置。手柄与触屏移动是否实施应由目标平台决定。

角色和灵境存于当前浏览器的两个 IndexedDB 数据库，诊断日志可导出，但角色备份尚无导入导出入口。若面向长期游玩，应提供覆盖两者且经过版本/数据校验的备份流程，并测试部分损坏、操作中断及重复导入，避免只导出角色而遗漏永久成长。

现有 Node CPU 预算、浏览器交互/像素检查、世界切换压力测试、真实 GPU 批次计数都有价值。[UI 测量](ui-performance.md)只覆盖暂停世界的窗口成本，[飘字测量](measurements/horizon-damage-browser.json)只证明固定场景的批次/像素合同；它们不代表持续移动、森林、围攻、粒子和背包同时出现时的帧时。

下一项性能工作应是为明确的目标设备和分辨率建立代表场景：平原赶路、密林战斗、领主特效、满包开窗和跨区加载，记录 CPU/GPU 帧时、P95/P99、峰值资源与挂载长任务。`HexCombatView` 当前固定像素比上限和植被/LOD 距离，并关闭自适应流送；先测量具体卡顿阶段再决定画质档位或调度改动。CI 目前主要在 Ubuntu/Chromium 验证，Windows 启动脚本和目标设备的原生图形路径还需要明确的发布验收。

## 建议实施顺序

1. 按当前扩展需求先完成成长底层：结算/状态/奖励拆分已接入；接着拆角色成长、实现技能树与属性修饰器，再补完整 Buff 和被动规则，用现有技能与装备验证套装/连携的接入。
2. 补齐战斗和成长体验：受阻寻路与战斗群体占位、主角攻击反馈和最小声音集合；解决技能点耗尽后的用途，完成少量差异构筑，验证开局到首领的数值/经济节奏。
3. 完成一个探索片段：地标、聚落实体、据点目标、领主奖励与对应世界状态；以此锁定美术样板。
4. 扩充内容与产品化：更多区域/首领、设置/备份，以及按目标设备测量后确定的性能优化。

现有运行时边界足以承接上述工作。全面改写 ECS、将 HUD 全部搬进 WebGL、增加更多 Worker、扩大同时驻留人口或直接改用 WebGPU，不应作为补齐玩法的前置任务；复杂渲染优化仍按[优化门禁](../optimization-gates.md)的实际证据决定。
