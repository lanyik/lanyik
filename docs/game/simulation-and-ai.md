## 实体存储

高频实体使用预分配、有容量上限的 SoA 存储；出生确定组件组合，状态变化不靠反复增删组件。低频构筑、背包与持久化使用独立领域对象，不为统一形式搬进逐 tick ECS。

实体句柄、存储槽与查询游标是不同概念。跨阶段、异步结果和攻击来源保存完整世代句柄；使用前重新解析，死亡后槽复用不能继承旧伤害、状态或 AI 目标。身份必须保持完整安全整数精度。

查询结果和空间索引候选是借用数据，下一次查询可能覆盖；需要跨查询消费时复制到有界缓冲。出生、移动、移除及时更新空间索引，复用槽前完成清理。效果结算前稳定候选顺序，避免密集数组交换删除影响随机数结果。

空间索引缩小常规查询范围，不保证密集围攻始终为常数成本；大范围查询还须有容量边界，不能按无限世界面积分配。预算与容量修改必须同时检查极端密度。

## 固定模拟与容量

一个权威 Worker 按固定阶段推进所有可变战斗状态。AI/动作遍历先产生有界请求，再在所属阶段提交；不得在仍借用查询结果时随意删除实体或重入结算。完整阶段顺序以 CombatSimulation 为准。

容量失败按数据职责区分：

- 非法实体容量或权威命中/事件溢出明确失败，不能悄悄丢掉已承诺的规则。
- 弹道发射先做整轮准入；无空间时不部分发射、不排队补射。普通攻击冷却不积累负值。
- 经验池满时合并价值；地面物品池满时按掉落规则放弃新创建。成功入包仍必须原子提交。
- 出生槽只在实体实际创建后消费。视觉事实溢出只影响表现。

暂停、页面隐藏和恢复不补算墙钟空档。模拟频率、低频决策和回复间隔存在整除及单位关系；修改 GameConfig 时联查消费者，不能只调一个定时值。玩法坐标保持绝对双精度，GPU 使用局部坐标。

## 共享行为树

怪物复用静态行为树结构，运行状态保存在实体组件。响应式选择器切换分支前 halt 原运行分支；控制、目标丢失、脱战和实体移除必须清理对应动作。决策可降频，已开始的移动、冲锋和攻击时间线仍逐 tick 推进。

攻击前摇、出手和恢复由核心决定；未出手动作被中断后保留相应 CD，已释放弹道按自身生命周期继续。目标身份失效不能转而命中同槽新实体；需要存活来源的治疗、返还或反伤必须再次验证。

怪物目前使用局部移动与偏转，尚无逐怪完整受阻寻路或战斗群体占位。遭遇连通图证明可达性，不负责引导战斗路径；不要把两者视为同一能力。

### 领主变体

普通怪与领主共用行为和结算入口，差异由定义及动作配置表达，不建立第二套伤害系统。模型演出读取权威攻击进度；出生布局、地域归属与启用条件归[战斗与成长](combat-and-progression.md)。

## 玩家自动战斗

自动战斗拥有目标、路径、手动操作让行和躲避意图；所有移动走现有角色通行，所有攻击走现有施法入口，不增加专属速度或无视障碍的通道。

AutoCombatPath 使用有界、增量推进的局部搜索。AutoCombatThreats 从已知攻击读取威胁，复用预分配缓冲，不预测尚未发生的 AI 决策。手动操作优先；普通寻路可为站定法术让行，紧急躲避可以取消吟唱。
躲避评估先排除相对运动线段完全位于身体包围框同一侧的弹道段，再做原有圆/圆柱扫掠；边界相等必须保留，两端跨越不能裁掉。该筛选不缩短预测时间、不减少候选方向，也不改变评分和等分选择顺序。

自动施法开关独立于自动寻怪。自动配装走[物品事务](items.md#自动配装与回收)，不在行为树或每个 tick 扫描全部装备。死亡、传送、恢复清理自动战斗运行状态；角色存档不自动恢复运行开关。暂停和隐藏页面不推进搜索或模拟。

## 多 Worker 职责与执行协议

主线程的 CombatWorkerClient 创建并拥有整组 Worker、MessagePort 和在途请求。权威 Worker 唯一拥有 ECS、随机流、命令执行和战斗结算；可选查询 Worker 只读取数值快照，不能修改实体、掷骰或发放奖励。

批次协议保持连续序列且只允许一个在途批次。命令按接收顺序先于本批 tick 执行；查询 join 期间不能插入其他命令。暂停使用零 tick 屏障，不能夹带尚未提交的模拟时间。积欠 tick 有界且丢弃需计数，命令溢出显式失败。

并行弹道查询只计算候选，权威端等待整批完成后按原顺序提交，地形检查与最终效果仍归权威端。启用前必须有实际负载测量；生产默认串行，线程数量受共享预算约束，不为轻负载单独增设线程。

低频 UI 快照与表现帧分开。表现采用两份独立缓冲交替转移，旧帧在下一请求归还；绝不转移 ECS 正在使用的数组。RenderFrame 统一推导布局与字节数，新增字段同时修改写入、读取、回收、校验和容量测试。

命令、死亡与屏障可强制发布 UI 状态。主线程只插值最新完整表现帧，夹紧范围且不预测命中；RAF 不等待模拟，没有新帧时保留上一完整结果。失速应体现为诊断和输入延迟，不能另起主线程模拟。

任一成员失败使整组会话进入失败状态并终止全部 Worker，旧世代结果和错误都不得污染新会话。重试创建新组，不静默切换主线程或部分恢复旧状态；销毁拒绝在途请求并关闭端口。

## 生命周期与诊断

战斗 Worker 先取得模拟实例所有权，再等待初始化/读档；区块准备与弹道查询共用串行请求屏障。玩法区块采用[有界提前准备与原子切换](terrain-navigation.md#遭遇布局与可达性)，让出通过 Worker 内 MessageChannel 进入下一事件循环任务，不以已完成的 Promise 冒充异步调度。销毁同时关闭让出端口、唤醒在途等待并销毁模拟；恢复执行必须先检查关闭状态，不能发布迟到结果。生产 tick、传送和初始化都走异步路径，立即执行接口只服务离线运行。

输入提交、模拟发布、表现更新与绘制属于不同阶段，主线程沿地图帧循环接入；预算只在任务之间让出，不能抢占一个长同步任务。应用当前关闭自适应流送，调度变化须依据实际瓶颈。

Worker 活跃比是采样窗口内占用率，不是操作系统 CPU 使用率；查询等待、区块让出等待、持久化等待和实际执行分别计时。批次执行时间扣除这些等待；模拟整 tick 耗时保留等待，仅 CPU 口径扣除 tick 内的查询/让出。初始化或传送命令的让出不混入 tick 等待。GPU 查询可能延后返回，不能当作当前帧结果。诊断保留有界窗口，不累积无限历史。

CPU 基准保留每轮尾延迟、超预算次数及最慢 tick/决策序号，跨轮聚合不能抹去早期峰值。低频集中结算可能只占少量 tick，因此平均值与 P99 都不能替代最大值和对应工作量。采样统计与复现命令归[测试策略](../testing.md#benchmark-scope)。

阶段探针只用于独立基准轮次，报告嵌套调用的含子调用耗时、自身耗时及调用次数，并关联 GC 时间窗；不得进入生产模拟或按探针结果直接宣称运行提速。比较时保留原始无阶段探针样本、冷启动范围及工作量一致性，观察阈值与实际 CI 门禁明确区分。

配置修改时重点检查：

- 模拟频率与回复、AI、自动施法等低频消费者的单位和间隔。
- 视野与人口、出生淡出、唤醒和卸载范围的关系。
- 实体/弹道容量与查询、帧缓冲、实例池及基准预算的一致性。
- 槽位、技能点或属性变化与命令校验、快照、快捷键和角色存档的对应关系。

## 验证

按[测试策略](../testing.md)运行游戏单测及对应 Worker/浏览器用例；协议与容量改动覆盖序列、借用缓冲、取消、失败、重建和迟到结果。固定种子回放比较权威快照与随机状态，不能为通过测试排除生命、奖励或随机数差异。

CPU 基准、Worker 并行实验与浏览器帧时分别报告。人群基准会丢弃部分命中，直行基准会补满生命；它们不能证明完整围攻性能、生存平衡或浏览器帧率。原始记录见[测量入口](../README.md#evidence)，平衡报告范围见[数值校准](combat-and-progression.md#数值校准)。
