生物的树干、陡坡和水体阻挡由 `CombatTerrain` 注入，普通移动、冲锋/冲刺、刷怪与宝箱净空共用规则，详见[地形通行与刷怪](terrain-navigation.md)。

本设计已实现于 `apps/survivor/src/core/{EntityWorld,CombatWorld,BehaviorTree,EnemyBehavior,EnemyActions,EnemyStrikes,CombatSystems,EnemyDefinitions,CombatSimulation,CombatText,SpatialGrid,ProjectileBatch,CombatCommand,WorldView}.ts` 及 `src/worker/`。

## 技术选择与接入时机

在扩展怪物攻击前统一实体模型，并直接采用行为树。原有按类型分开的实体池已经采用 SoA，
但数组下标、玩家专用字段与同步删除贯穿战斗和表现；若新行为继续引用这些结构，后续迁移会同时涉及
目标记忆、持续动作、弹道归属、伤害和表现接口。统一时尚未引入存档；当前 `CharacterCheckpoint` 保存角色进度，恢复时重建地域人口，不序列化 ECS 槽或飘字。

现在接入的主要成本是统一实体生命周期、改写系统遍历和表现读取，并验证原有成长/装备行为。
地图运行时、地域内容、会话命令和 React 界面结构可以沿用，不需要重新设计整套引擎。
以后接入仍然可行，但若先让技能、状态效果、召唤物和 Boss 行为绑定旧池下标，迁移就会扩散到各功能与测试；
若现在先抽象稳定身份与读写边界来避免该成本，则已经在承担本次 ECS 的主要工作，因此直接完成统一更合适。
这里的收益是数据与系统边界可组合；旧实现本来就是 SoA，不能仅凭采用 ECS 就宣称更快。

| 方案 | 当前收益与代价 | 结论 |
|---|---|---|
| 各实体池继续扩展，之后迁移 | 初期改动少；跨实体行为会增加第二次改写范围 | 不采用 |
| 通用对象 ECS | 组合方便；需要改写现有数组布局并承担逐实体对象与查询成本 | 不采用 |
| 通用 SoA ECS 库 | 可保留数组；仍需约束回收身份、查询修改时机、容量和执行顺序 | 未作为运行时依赖 |
| 应用内有界 SoA ECS | 统一安全整数句柄、固定容量组件和缓存查询；应用显式维护执行顺序 | 已采用 |

bitECS 0.4.0 的发布包验证中，内置版本化 ID 在“回收 A、重用 A、删除 B”的特定排列下，
会将仍然存活的新 A 判为不存在；也不能将含版本位的完整 ID 直接作为固定 TypedArray 下标。
本项目将身份与存储槽明确分开，相关复用排列、超过 32 位的句柄及容量边界有独立测试。
参考 [bitECS 的存储与身份合同](https://github.com/NateTheGreatt/bitECS/blob/main/docs/Intro.md)。

本地 ECS 只提供本游戏使用的创建、销毁、句柄解析与组件交集查询。组件组合在出生时确定；
频繁变化的动作阶段、AI 圈层和冷却是字段值，不通过添加/移除组件表达。
没有通用插件调度器、动态组件注册、序列化框架或过渡用 AI 状态机。

## 聚落生态

每个 12×12 驻留块确定一个聚落主题与中心，在约三单位半径内按稳定角度和少量抖动安排出生岗位，人口仍受地域 7/9/10 上限约束。不同种子或坐标决定主题；卸载重建得到相同成员和位置，驻留中不会计时补刷。这里只生成生态群组与岗位，尚无帐篷、建筑或营地交互。

| 聚落 | 允许共生的成员 | 分布 |
|---|---|---|
| 蛛兽巢群 | 裂隙蛛兽 | 所有难度 |
| 地精营地 | 地精仆从、赤脊冲锋者 | 所有难度 |
| 祭司据点 | 小恶魔术士、幽光祭司、裂岩守卫 | 困难/恐怖；恐怖地域领主中心固定此组 |
| 混合掠夺营 | 地精仆从、赤脊冲锋者、小恶魔术士、幽光祭司 | 困难/恐怖 |

物种不再逐成员随机抽取；蛛兽不与祭司阵营随意混居。治疗搜索仅接受同一出生区块且无遮挡的同伴；各成员保留自己的巡逻岗位、追击和归位规则。`EncounterNavigation` 把候选安排到有边界入口的连通域，领主优先留出体型空间，同营地成员保持连通；只有已证明玩家可达的位置才启用，详见[遭遇布局](terrain-navigation.md#遭遇布局与可达性)。宝箱使用独立 `seed:chest:chunk` 随机流，生态配比调整不会消耗宝箱随机数。

## 领主变体

每个恐怖地域按独立种子从四种领主中生成一只候选，仍带原有祭司据点支持成员；出生可达性和归属见[战斗与成长](combat-and-progression.md)。`EnemyDefinitions` 是数值、模型映射与特殊动作时序的唯一目录。

| 领主 | 行为组合与应对 |
|---|---|
| 裂爪领主 | 保留三/五发齐射、锁定落点獠牙夹击、狂暴近身横扫 |
| 断层岩王 | 近战重击；六单位内优先蓄力 1.25 秒，随后震波前沿在 1.1 秒内从中心推进到半径 6，半宽 .35，125% 伤害，后摇 .9 秒，结束后特殊冷却 6 秒。前沿经过后内部安全，整次最多命中一次 |
| 风暴先知 | 保持施法距离；蓄力 1.1 秒后连续三波扇形飞刃，间隔向上量化为 39 tick，波间方向偏移 .2 弧度，刃间夹角 .42，每刃 65% 伤害；普通/狂暴每波三/五刃。后摇 1.1 秒，结束后特殊冷却 5 秒，锁定方向不追踪玩家 |
| 烬刃斗王 | 三至 6.5 单位使用既有锁向冲锋，3.4 单位内使用前方横扫，共享特殊冷却；横移躲冲锋，绕背避横扫，冷却期间使用近战剑击 |

半血狂暴不可逆。优先级为岩王震波/先知弹幕、可用横扫、血契、冲锋、夹击/齐射、石脊；各动作均受普通再次起手冷却约束。震波复用动作提交位记录释放和命中；弹幕用提交计数保存已经尝试的波数，每波完整预检弹道容量，满额只跳过当波，不延后补射。死亡、卸载、失去目标或行为中断取消剩余波和震波；已飞出的弹道继续存在。新动作不增加 ECS 数组、Worker 字段、角色模型池或表现池容量。

## 实体存储

模拟 Worker 中的 `CombatSimulation` 持有一个 `CombatWorld`，是会话命令、成长、奖励和固定系统执行的入口。
玩家与怪物共享位置、朝向、半径和生命组件；怪物另有出生归属、行为记忆、移动意图及动作时序。
弹道记录阵营、发射者句柄、三轴速度、生命期和发射时的伤害/精英/Boss 数据；当前与上一 tick 海拔为 Float64，另记录飞行年龄，供表现插值权威轨迹。释放位置来自离线骨骼采样与模拟端地面高度，见[角色资产](actor-assets.md)。
经验与地面物品也是实体；背包、冻结物品定义、地域生成和宝箱消费继续由领域数据管理。

实体总容量为 `1+896+128+768+64=1857`。每种人口上限仍单独检查。`WorldView` 将 81 个驻留区块各最多十名居民加一名领主的 891 个槽向上按 64 对齐，避免扩展视野后外围聚落被容量截断。

| 实体查询 / 表现 | 上限 | 满载行为 |
|---|---:|---|
| 怪物 | 896 | 81 区块最多 891 槽，超过为明确配置错误 |
| 弹道 | 128（敌方最多 64） | 玩家等待可用槽；敌方本次施法跳过发射并进入后摇，齐射预检完整容量 |
| 经验球 | 768 | 新经验合并到首个活跃球，容量溢出不丢价值 |
| 地面物品 | 64 | 不创建额外物品，现有物品保留 |
| 宝箱表现 | 81 | 驻留未开箱，按距离淡出 |

组件按槽存储，查询以固定 TypedArray 保存活跃槽列表，用末项交换删除。
查询游标、存储槽、实体句柄是三个不同概念：游标随交换改变，槽在生命期内稳定，句柄区分槽的不同生命期。

句柄公式为 `(generation-1)×capacity+slot+1`，0 表示无目标；数组只使用 `slot` 索引。
创建时增加该槽代数，销毁时清空有效句柄并归还槽；解析必须同时匹配完整句柄。
代数达到 Uint32 上限后明确拒绝再次创建；支持容量上限保证句柄运算保持安全整数。
怪物卸载/死亡清除出生区块、地域、目标与树运行节点，不保留无限探索历史。

`CombatState.ts` 定义表现需要的字段。核心的 `getRenderState()` 仍借用自己的组件，
只允许 Worker 内的 `RenderFrame.write()` 在完整 tick 提交后读取；主线程不再持有实时 ECS 引用。
`RenderFrame` 将表现字段复制到独立 ArrayBuffer 后转移给主线程；旧表现帧在下一帧接收后才允许归还。
UI 读取独立的低频快照，并在结构化克隆后重新递归冻结。主线程无法通过任一视图修改战斗事实。

## 固定 tick 与结构变更

逻辑固定 120Hz，每 tick 为 1000/120ms，顺序固定：

1. 保存玩家上一位置、推进冷却、`StatusSystem` 活跃状态与表现效果，自动战斗合并玩家移动意图并按需用药，执行疾行或普通移动；
2. 同步地域驻留，先卸载失效实体；玩家通行格或窗口改变时传播可达性、启用符合条件的待出生人口并刷新宝箱；
3. 玩家索敌与发射，推进已有弹道，批量结算命中；若玩家死亡立即结束 tick；
4. 推进已经释放的陨星、涡旋、刃阵并逐技能结算；每 12 tick 按槽顺序尝试自动技能，逐技能结算，死亡怪物不再参与本 tick 的行为决策；
5. 怪物感知与行为树、移动执行、攻击时序执行，再批量结算伤害；
6. 玩家存活时处理经验、地面物品、宝箱，以及每 60 tick 的血蓝回复。

行为树决策和怪物动作执行期间不销毁怪物；感知阶段可以先移除已经卸载的实体。
伤害先写入有界缓冲，在其所属阶段之后由 `CombatResolution` 提交。攻击暴击结果随缓冲传递，实际生命损失、防御与死亡进入 `CombatEvents`；每笔命中及派生效果完成后同步消费，再处理下一笔。`CombatFeedback` 生成跨 Worker 发布保留的 `CombatText`，`CombatRewards` 消费死亡事实并保持原掉落随机顺序。表现不重算伤害。成长与同级装备压力门槛见[数值校准](combat-balance.md)，飘字生命周期和批次见[技能合同](skills-and-effects.md#伤害飘字)。
销毁立即从 ECS 查询与空间索引移除；驻留和弹道系统使用“不递增当前游标”的交换删除循环。
范围技能与拾取先取得独立的空间候选槽列表，再按完整句柄升序提交，不受哈希链顺序或 ECS 末项交换影响。
创建/销毁不会隐式触发其他系统或重入用户代码。

命中缓冲使用完整句柄。多个弹道同时命中同一怪物时，第一笔致死结算提交一次奖励，其余命中因句柄失效被忽略，
不会伤到复用该槽的经验或物品。结算先后采用明确的系统顺序及查询顺序；相同输入、种子和命令顺序可重放。
同距离索敌以较小句柄破平局；弹道使用线段与圆的最早交点，交点相同也以句柄破平局。

已发射的敌方弹道在施法者死亡或卸载后仍飞行，以发射时的数据造成伤害；反伤只作用于仍然有效的原施法者。
玩家受击保护仍为 0.55 秒，闪避/盾/防御公式不变；致死受击与致死反伤同次结算时仍奖励击杀，玩家保持死亡。

## 玩家自动战斗

`PlayerAutoCombat` 在模拟 Worker 内独占玩家挂机开关、目标、路径与接管计时；`AutoCombatPath` 和 `AutoCombatThreats` 分别负责局部路径与短时危险估计。玩家树复用下节的 `BehaviorTree` 执行器，有独立树定义和单个运行节点，不复用怪物行为规则或怪物状态数组。普通攻击、自动/手动技能、药剂、实际移动与开箱仍由原系统提交，控制器不修改生命、背包、伤害或 Boss 动作。

Z / HUD 的 `toggle-auto-combat` 命令开启或关闭，默认关闭；家园及死亡时不能开启。F 自动施法保持独立，关闭后仍可挂机移动并手动释放技能。WASD 非空闲输入当 tick 优先（含互相抵消的方向键），取消路径与当前闪避；松开后等待 .35 秒再恢复自动移动。手动药剂和技能先在命令批次提交，共享冷却与资源约束；生命不高于 40% 时每 .1 秒尝试一次既有生命药剂选择与消费，不阻塞移动，也不额外自动吃蓝药。

有效优先级为手动输入、避险、战斗与寻物。行为树先生成普通移动意图，安全检查在提交移动前覆盖危险意图；不会为了避险销毁尚可复用的寻路结果：

```text
Selector
  手动接管及松键缓冲 → 等待手动输入
  已交战目标 / 可攻击目标 → 保持射程或追击
  附近未开宝箱 → 走近并由原系统开箱
  附近怪物 → 接近目标
  没有目标 → 等待下一次局部搜索

自动意图安全检查（不覆盖手动输入）
  路线在预警/弹道中将被命中 → 普通移动撤离或在安全位置等待
  路线安全 → 保留行为树意图
```

寻怪半径 16 单位，宝箱优先半径 6 单位；已选择的箱子在八单位内保持目标，避免绕障碍时反复取消。敌人以距离、完整实体句柄破平局，箱子以距离、X/Z 坐标破平局。开始交战后保留目标，死亡、卸载、超出搜索范围或暂时拒绝后重新选择；寻怪阶段新出现的近敌可以抢占开箱。进入攻击射程 85% 且攻击视线畅通后停步，普攻仍使用已有索敌规则。不会自动传送或搜索整个地图，附近清空后等待；没有持续巡游或离线收益。移动和拾取经过原地形/库存检查，无法开箱不会强行领取。

决策与用药检查 10Hz，移动仍逐 tick 以原速度响应执行。威胁检查读取十四单位内最多八个正在攻击的敌人，特殊攻击优先于普通近战、同类按距离及句柄选取；已有敌方弹道上限 64。只观察已起手动作、锁定朝向/落点和当前弹道数据，不读取尚未发生的敌方决策。近战、冲锋、横扫、石脊、獠牙夹击、震波使用现有动作参数及 `EnemyStrikes` 几何；普通施法、弯曲三连发和多波风暴在起手阶段就预测发射，已发射弹道按当前转速、剩余转弯时间、寿命、高度和攻击遮挡预测。弹道只预计算一次，直线段只扫掠一次遮挡，所有候选移动共用结果。

预测未来 2.4 秒，每 .1 秒采样，检查玩家轨迹与同时刻的移动刀刃、石脊、震波或弹道接触；横扫采样间隔加几何余量。危险评分按单次攻击的首次接触时间计算，越早命中代价越高。先检查普通意图（包含到达攻击射程后的停步），有危险才比较停步和十六个方向；各候选按当前实际速度、正常移动响应和地形碰撞推演，计划行进最多 1.5 秒、六单位，然后减速停步。停步已安全则等待，不为追怪或拾箱走回危险区域；否则选择风险最低的方向，同风险优先延续方向和原意图。每次决策重新评估，没有固定躲避冷却或单次 1.5 单位上限；危险消退才恢复追击/拾取。仍无无敌、瞬移、加速或自动疾行，手动技能不被取消；过晚开启、被围堵及复杂交叠攻击不保证无伤。

一次安全决策最多十八条候选轨迹、每条二十四步地形移动预测（共 432 次，另计原寻路预算）；已超过当前最优风险的候选提前停止接触评估。敌人、玩家轨迹、弹道轨迹使用控制器内预分配数组。预警弹道预留八名敌人 × 三波 × 五发，加上 64 条真实弹道，最多 184 条、每条 25 个位置采样；不会创建模拟实体、异步任务或额外 Worker 请求。普通意图无危险时不搜索十六方向，没有威胁时不推演轨迹。

直达受阻后才启动玩家专用局部 A*：49×49 个 .75 单位节点，预分配堆、父节点、成本与路径数组；每 tick 最多展开 16 节点、64 次净空探测，起点额外最多四次移动扫掠。四邻接节点复用遭遇导航的半格净空余量规则，移动最终仍经 `CombatTerrain.move`，不搜索窗口外路线。新目标立即规划，其余直达检查间隔至少 .75 秒；目标离上次规划位置超过一单位时重新规划。搜索耗尽明确失败，停止前进/箱子不能消费持续 1.5 秒则放弃目标；最近八个失败位置保留八秒拒绝记录，容量固定，不累积探索历史。控制器不创建定时器、Promise、每帧节点或搜索数组，也不增加 Worker 通信轮次。

死亡结算、关闭、成功传送、恢复存档和地图/角色重建均关闭自动战斗并清路径；状态只进入 `CombatSnapshot.autoCombat` 的低频 UI 分支，不写角色检查点。暂停/页面隐藏停止模拟时间，不在恢复时追赶挂机决策。

验证：`PlayerAutoCombat.test.ts` 覆盖命令独立性、接管、用药/死亡、稳定句柄、箱子优先、受阻放弃与增量路径预算；`AutoCombatAvoidance.test.ts` 使用正常平滑移动与真实敌方攻击/弹道结算，对比站立受击与九类攻击的自动避让，并覆盖夹击长距离撤离、连续攻击、受阻方向、曲线弹道和穿过危险路线。`auto-combat.spec.ts` 覆盖真实 Worker 和键盘入口。`benchmark-survivor.mjs` 的 `autoCombat` 场景在程序地形上开启挂机并要求真实位移，沿用地形场景 3ms/tick 门槛；`autoAvoidance` 在程序地形上固定八个五发风暴预警及 64 条曲线弹道，每次都求完整安全决策，单独报告每决策耗时、P95 和最大值，五次平均耗时样本的中位数门槛为 3ms/decision。两者只证明 Node 模拟 CPU 成本，不代表浏览器帧率。

## 共享行为树

树的组合节点为响应式 Sequence 与按优先级选择的 Selector，叶节点为条件和动作。
动作返回 Success、Failure 或 Running；每个实体仅保存一个运行叶节点编号。
连续决策周期续执行同一个 Running 动作，选择另一动作时先 halt 旧动作；前置条件全部失效也会取消运行节点。
树在构建时检查环和空组合节点；定义共享、执行不生成逐怪节点对象、Promise、计时器或每 tick 临时数组。
响应式执行和中断语义参考 [BehaviorTree.CPP](https://behaviortree.dev/docs/guides/asynchronous_nodes/)。

实际优先级：

```text
Selector
  Sequence：没有有效追击目标 → 脱战归位 / 出生点附近巡逻 / 短暂停留
  Sequence：术士/祭司未在攻击且被近身 → 后退（领主可横扫、祭司已能起手治疗时除外）
  Sequence：斥候未在攻击、冷却未好且距离小于 3 → 绕行
  Sequence：攻击进行中，或冷却已好且可用特殊/普通攻击 → 执行动作
  Sequence：术士/祭司处于射程内且无可用动作 → 侧向绕行
  追击目标（斥候侧向接近）
```

驻留区块只管理人口生命周期，AI 距离按怪物与玩家的实际坐标每 tick 判断，移动玩家跨区块不会突然冻结一整排怪物。
`RegionalWorld.residencyAt()` 与 `chunk.band` 使用 near/buffer/retained/unloaded 名称，快照区块计数保持同名，不再把驻留圈标成 active/low/static。
18 范围内决策按句柄每 4 tick 错峰（30Hz），已有活跃状态到 20 外才退出；44 内唤醒，46 外休眠。
两者之间每 24 tick 错峰决策（5Hz），仍逐 tick 推进移动和移动动画。模型在 34–42 淡出，因此可见远处的怪物保持巡逻。驻留半径四块，最早卸载边界为 48；唤醒、休眠、淡出及地图视距统一由 `WorldView` 定义，仇恨仍为 12/19。
唤醒、决策层变化、目标丢失/变化、攻击结束立即求值；其余时刻保留意图，不把低频步长一次性补成位置跳跃。

12 距离内获取玩家，已有追击持续至 19；玩家距出生点超过 22 也会脱战。
脱战当 tick 抢占攻击，保留原冷却并至少等待该怪物的后摇；必须先回到出生点附近 .05 内，随后才允许重新获取目标。
没有目标时，在出生点 2.5 半径的确定性三角路径间巡逻，速度为原速度 45%；斥候半径乘 1.3，领主乘 .5。
每个路点停留 .7–1.6 秒，角度由完整句柄与路点序号决定，不消耗伤害/掉落随机流。
路径状态、停留期限和归位标记均为 ECS 字段，槽复用时重置；休眠清除移动意图与运行叶节点，不创建计时器。

近战锁定前摇开始时的朝向；命中时重新检查玩家是否仍在范围和朝向两侧各 1.1 弧度的扇形中。
每个种类在模块初始化时编译一棵共享树，按种类只包含实际需要的分支。一个连续动作使用同一个 Running 叶节点，
前摇、释放和后摇期间不会因重新选分支而重置。动作目标与追击目标分别记录完整句柄。
种类身份统一使用 `EnemyKind` 的 Grunt、Scout、Guard、Caster、Charger、Healer 名称；出生选择、行为分支与减伤结算不再直接比较数字种类。

| 种类 | 决策与特殊行为 |

| 地精仆从 | 追击、常规近战挥击 |

重卫正面以命中结算时的玩家方向与重卫朝向比较，适用于当前全部玩家伤害；不是弹道入射角判定。
巡逻目标先检查身体净空，每次最多检查三个确定性候选；全部受阻时原地休息 1.5 秒。实际移动受阻后在下一次 AI 决策改选目标，不消耗战斗/战利品随机流。滑动和绕树后的模型朝向取真实位移，避免身体朝墙而横向滑行；攻击继续锁定起手朝向。
祭司搜索排除自己，选择最低生命比例，同值取较小句柄；施放锁定目标，释放时再次验证原句柄、阵营、存活和距离。
不会在目标死亡或离开范围后替换为另一个同伴。治疗为目标最大生命 20% 与祭司攻击力三倍中的较小值，且不超最大生命。
血契要求祭司当前生命大于自身最大生命的 12% 加 1；有效释放时扣除这 12%，失败或前摇取消不扣生命。抬手期间目标坐标跟随原同伴，空中连线显示施受双方，击杀祭司或使其脱战会打断治疗。
有效治疗同时给予 3 秒减伤祝福：玩家命中伤害乘以 .75，重复治疗刷新期限；到期立即恢复正常伤害，不叠加层数。实体移除或槽复用清除祝福。

冲锋在前摇时锁方向，之后不追踪玩家；慢速状态降低其推进速度，路径预警显示未减速的最大范围。

夹击在起手时锁定目标 XZ 与朝向，两列沿朝向的垂线合拢，不追踪玩家；两端开放，玩家可沿纵向逃离。石脊允许横向避开，横扫留下背后安全区。`EnemyActions` 推进碰撞，`EnemyStrikes` 给碰撞和表现提供同一条轨迹；判定加玩家半径，扫掠含玩家前后位置与端帽，整次动作至多命中一次。`committed` 的两个位分别表示已提交效果与已命中，释放时不立即进行整片范围伤害。取消或施法者移除按完整来源句柄删除所属持续效果。弯刃在固定 tick 旋转速度向量并更新表现朝向，不重新选择目标。

## 表现与验证

动作组件给出种类、锁定朝向和归一化进度；前摇映射到 0–.5，后摇映射到 .5–1。
构建时为五组怪物模型各增加八帧非循环攻击姿势，普通怪和新增领主通过定义中的 model 索引共享池和 morph 数据。
近战前摇显示真实扇形，冲锋显示路径矩形；石脊使用断续直线、夹击使用两侧裂口、横扫使用边界线；震波使用放射线，先知使用扇形方向线。普通施法和血契不生成地面圆环。`EnemyPresentation` 的三维獠牙、岩块、血契连线与窄线预警独立于玩家图集效果；池上限和资源归属见[技能表现](skills-and-effects.md)。
冲锋者橙红、祭司绿色，霜环减速染蓝，领主狂暴染红，祝福期间混入治疗色并围绕身体显示三片护骨；受击闪白优先。敌方弹道使用深红实体弯刃和细尾迹，施法手附近显示飞刃蓄势。
动画与预警只读取模拟结果，暂停不推进动作，取消后清除预警。

测试覆盖身份复用、树抢占、一次命中、锁定方向躲避、圈层中断、弹道最早交点、发射者失效、齐射容量、
重复死亡与同时死亡，以及实际浏览器 morph 权重、预警、弹道颜色和暂停。

`npm run benchmark:app` 单独约束游戏 CPU：真实 24 秒直行战斗，以及 `MAX_ENEMIES`（896）怪物加 128 条未命中弹道的满载系统遍历。
这些场景一次预热、五次采样，以每 tick 耗时中位数检查 .5ms / 3ms 预算；另有地形自动战斗及按决策计时的满载避险场景，定义见[玩家自动战斗](#玩家自动战斗)。报告 Node、CPU 和原始样本。
计时不包含初始化/构建，直行场景拒绝将死亡后的空更新算作工作；满载场景使用六种怪物混编，初始生命 40%，
包含祭司 5Hz 感知与治疗，不提交伤害死亡，持续保留全部驻留目标；远处弹道允许被空间初筛全部排除。
可用 `--baseline=<独立模块路径>` 对比同种子、同输入的旧版直行场景；攻击规则不同会影响存活人口和击杀数，不能据此单独推算 ECS 开销。
该模块须导出 `CombatSimulation` 和按自身模拟频率实现的 `ticksForSeconds`，确保两侧都测量真实 24 秒玩法时间。
该基准不代表浏览器 GPU 或整帧性能。

视野扩张、攻击遮挡和结算分离阶段的原始样本统一见[测量索引](../README.md#evidence)。查询基准测量数值求交与分发，不包含地形遮挡提交；真实地形场景单独覆盖权威端开销。生产默认在单模拟 Worker 内串行查询，不因单个密集样本改变线程配置。

## 空间查询与生命周期

`SpatialGrid` 是固定容量的二维均匀哈希网格，单元格边长 4，和 12×12 的人口驻留区块职责分开。
当前位置按 floor 分格，负坐标与正坐标使用相同规则；哈希碰撞再比较完整格坐标，不把哈希相同当作同格。
每个怪物、经验球、地面物品只登记一个中心槽，TypedArray 保存格头和双向链，无逐移动对象分配。
出生立即登记，普通移动、冲锋、经验与物品吸附更新所在格，死亡、拾取、驻留卸载在释放 ECS 槽前删除索引。
复用槽重新登记类型；主线程不持有这份索引，ECS 句柄仍是跨阶段身份。

| 查询 | 空间初筛与精确规则 |
|---|---|
| 普攻、连锁闪电 | 查询攻击圆内中心，排除视线受阻者；连锁逐跳检查，最近距离与完整句柄破平局规则保留 |
| 脉冲、霜环 | 初筛半径加当前索引的最大体半径，再以各目标实际半径及玩家视线判定 |
| 祭司治疗感知 | 半径 6 内无遮挡的活跃同伴，保留血量比例与句柄破平局规则 |
| 经验吸附、地面拾取 | 查询玩家拾取圆；按完整句柄升序处理，移除候选不会跳过其余项 |
| 友方弹道 | XZ 包围盒加弹道/最大目标半径初筛，XYZ 线段与有高度的角色圆柱求首次交点 |
| 敌方弹道 | 对唯一玩家的身体圆柱求交，无须索引或遍历其他实体 |

查询结果借用固定缓冲，只在下一次查询前有效；只读筛选结束后才推进副作用。
需要随机数或背包容量的范围/拾取操作按完整句柄升序执行，确定性不依赖哈希表布局。
经验与物品各用固定容量数组记录上一 tick 移动过的完整句柄，用于重置插值起点，离开吸附范围不会重复播放旧位移；背包满时物品留在玩家附近，不丢弃或重复入包。
索引半径高水位只扩大候选集合，不改变精确命中；每局独立释放。非法或超出安全整数的格坐标明确失败。
很长的扫掠若覆盖格数超过整个哈希表，直接扫描有界槽表做包围盒筛选，避免枚举无限空格。

弹道初筛在权威端每批执行一次，直接查询 `CombatWorld` 已维护的空间索引，不再重建第二份敌人网格。
收集敌人快照时同时写入固定的实体槽到快照游标映射，候选以 Uint16 游标写入 `ProjectileBatch` 的固定矩阵。
Workers 只接收数值事实和已筛出的候选，不重复建立或查询网格，不读取实时 ECS。
只有显式开启查询配置且候选达到分发门槛时才使用双查询线程。每帧渲染、移动、动作时钟和必要 AI 感知仍顺序处理活跃实体；
实体索引不替代这些必须发生的更新，也不改变地形通行和全局寻路规则。

均匀网格适合当前二维圆形目标和高频移动；四叉树的分裂、合并与节点生命周期没有额外收益依据。
分散场景可大幅减少精确求交；所有实体挤在同一小范围时仍可能产生 896×128 个候选，不能宣称最坏情况变成常数成本。
测量同时覆盖分散与密集近失场景，见[空间查询测量](measurements/spatial-node.json)。
玩家移动与怪物出生使用同种子地形通行规则，检查水体、陡坡与树干净空，详见[地形通行](terrain-navigation.md)。

## 多 Worker 职责与执行协议

已将整个战斗模拟移出主线程。保留一个事实写入者，再将可独立计算且工作量足够的阶段分区，
避免地域对象、PRNG、奖励与生命周期同时受到多个写入者影响。

| 执行者 | 已接管内容 | 写入与提交边界 |
|---|---|---|
| 主线程 | 输入、帧节奏、UI、Three.js 表现、Worker 生命周期 | 提交命令；读取完整快照 |
| 模拟 Worker | 全部 ECS、行为树、移动、攻击时序、伤害、地域人口、成长、背包、随机数 | 唯一事实写入者；串行执行批次与 tick |
| 可显式启用的两个查询 Workers | 达到门槛的弹道线段/身体圆柱求交，按弹道区间分区；默认不创建 | 只读取数值快照；只写自己的目标句柄区间 |
| 地图 Workers | 既有地形生成 | 保持地图独立所有权，共享应用线程预算 |

行为树与移动仍在模拟 Worker 中执行：现有最多 896 怪物且外圈降频，这些遍历尚不足以证明逐阶段分发的收益。
伤害与结构变更有强顺序依赖，继续串行提交。背包和成长属于低频领域数据，没有另设线程或强行转成 ECS。
后续真正增加复杂寻路、群体感知或更大规模查询时，可按“只读数值输入 → 分区结果 → 权威提交”增加执行端口；
目前没有未使用的通用任务图、动态系统注册或共享内存锁。

```text
主线程 CombatSession → CombatWorkerClient
  ├─ 有序批次 / 归还旧表现缓冲 → Combat.worker / CombatWorkerHost
  │    ├─ 命令 → 固定 tick 前半段 → ProjectileBatch
  │    ├─ 默认直接计算；显式启用查询线程且工作量足够时经 MessagePorts 分区
  │    └─ 等待全部结果 → 原查询顺序结算 → tick 后半段 → 完整快照
  └─ 接收快照 → RenderFrame → CombatLayer / React
```

`CombatWorkerClient` 在主线程创建全部战斗 Workers，再转移 MessagePort 连接模拟与查询端。
因此重开或任何一个 Worker 失败时，主线程能直接终止整组，不依赖嵌套 Worker 随父线程结束。
初始化与推进共用连续请求序号；每次只允许一个未完成请求，乱序和重入明确失败。
每批最多 30 tick、64 条命令，所有命令按收到顺序在该批 tick 之前执行；查询等待期间不处理下一条命令。

主线程再保留至多 30 个待执行 tick 与 64 条待提交命令，使用最新移动输入处理待执行 tick。
超过 tick 上限的墙钟积压丢弃并计数，命令溢出则失败；每批是确定的模拟输入，不承诺不同帧节奏下的原始键盘事件完全等价。
暂停丢弃尚未发送的 tick，已发送批次允许提交，随后用零 tick 请求确认最终快照；隐藏不积累后台追赶时间。
Worker 按批次发布表现，每 12 tick（10Hz）发布常规 UI 快照；初始化、命令、通知、死亡和零 tick 请求强制带回 UI 快照。
表现用收到时刻到下一 tick 的时间对前后位置插值并钳制，不外推未知位置。

### 渲染隔离与扩展边界

`bootstrap`、`CombatSession`、`HexMap.animate`、`CombatLayer` 与 Worker 协议共同保证模拟计算与主线程执行分开、
状态由单一线程写入、队列和内存有界；不保证 Worker 负载对帧率没有影响。

| 情况 | 当前行为与限制 |
|---|---|
| 模拟或查询很慢 | `CombatSession.frame` 不等待推进 Promise，地图继续绘制最近完整结果；一个逻辑 tick 的插值钳制后角色停在已知位置，输入到表现的延迟增加 |
| 查询结果未齐 | 模拟在 `Promise.all` 处等待所有弹道分区，后续 tick 与命令不能越过该结算阶段；只阻塞模拟进度，不同步阻塞主线程 |
| 跨线程修改状态 | 活跃 ECS 留在模拟端，表现缓冲转移后发送端失去访问权；查询端只有数值副本，不持有场景对象或权威组件 |
| 错误的业务结果 | 序号、缓冲大小、查询计数与输入坐标等已有边界检查，但不会逐项证明所有输出字段的业务正确性；错误坐标或动作仍可能通过合法消息影响表现 |
| 结果返回主线程 | TypedArray 视图绑定、UI 快照冻结/发布、实例矩阵与动画数据更新、地形挂载和 GPU 上传仍有主线程成本 |
| 多线程资源竞争 | 固定线程数限制并发数量，不为主线程保留独占 CPU 核或内存带宽，也不保证任务时延 |
| 战斗 Worker 失败 | 主线程主动终止整组战斗 Workers 并进入 failed；这是一致性策略，不是继续维持正常战斗的故障隔离 |

主线程只有地图拥有的 RAF 循环：`beforeframe` 调用 `CombatSession.frame`，依次采样输入、提交有限批次、
更新角色表现与跟随镜头；地图随后更新控制器、流送和场景，发出原有绘制前 `frame` 事件，再提交绘制。
`afterframe` 才采集本次主循环耗时并发布诊断。初始化也等待该帧入口更新角色，不再单独触发表现更新。
`bootstrap` 注册/释放帧监听和长帧观察器，不创建第二个 RAF；关闭时先移除监听，再释放会话与地图。
地图恢复 WebGL 上下文后首帧 `dtS=0` 会重建游戏时钟和诊断窗口，不追赶失去绘制上下文期间的时间。
`afterframe.cpuFrameMs` 包含战斗表现和地图/Three.js 工作；`frame.cpuFrameMs` 仍表示前一主循环耗时。
异步消息、React 更新、浏览器布局和最终屏幕呈现并不全部落在主循环计时内，因此同时观察帧间隔与浏览器长帧。
地图挂载已有 `FrameTaskScheduler`，但时间预算只在任务之间检查，不能抢占一个已经开始的长任务；
游戏适配器当前关闭 `adaptiveStreaming`，使用固定流送设置。两者均不能作为严格的整帧耗时上界。

当前 896 怪物、128 弹道等容量是已实现的存储/人口边界；Node 基准和软件渲染 E2E 不构成目标设备上的帧率承诺。
增加内容种类与增加同屏工作量需要分别评估：技能、状态效果、Boss 阶段可以在现有权威端增加领域系统，
由 `CombatSimulation` 明确编排提交顺序；寻路/群体感知需要只读任务输入与结果有效性规则；
成倍增加人口会同时影响全量表现复制、弹道候选密度、实例动画更新和 GPU 成本，不能只增加 Worker 数量。
地形通行通过 `CombatTerrain` 接入移动、冲锋、遭遇布局和宝箱接近检查；`ProceduralCombatTerrain` 从同源表面生成有界阻挡及高度缓存。普攻索敌、近战/冲锋/特殊攻击命中、施法释放与治疗检查身体视线，远程受阻时用 `Seek` 接近而不在射程内停步。弹道先求角色交点，再由权威线程检查交点之前的实心树干与山体，同点环境优先；水面不挡空中攻击。具体高度采样和连通域保证见[地形通行](terrain-navigation.md)。当前已有遭遇连通标签及跨区入口传播，尚无逐怪受阻寻路和战斗群体占位，AI 不读取 Three.js 场景。

保留当前单一事实写入者与有界数值任务的骨架；进一步索引细化、快照布局调整或新增并行阶段的优先级，
由代表性实机场景与具体功能的工作量决定。下述提交入口已经接入模拟；通行数据已有实现，完整寻路算法和独立渲染 Worker 尚未实现。
Worker 上下文与转移所有权的浏览器语义见 [MDN Worker](https://developer.mozilla.org/en-US/docs/Web/API/Web_Workers_API/Using_web_workers)
与 [MDN 转移对象](https://developer.mozilla.org/en-US/docs/Web/API/Web_Workers_API/Transferable_objects)。

### 必须完成的查询边界

`CombatSimulation` 在等待弹道查询期间拒绝进入下一 tick；所有命中按原顺序结算后，才执行 tick 后半段。
查询执行器沿用独立 MessagePorts、容量和超时约束。执行器失败直接终止当前会话；关闭会话时先释放执行器，再关闭模拟。
当前 AI 全部在固定 tick 内同步执行，没有延后计算消费者，因此不保留延后任务队列、驻留版本戳或恒为零的延后任务诊断。
之后若增加异步寻路，应随真实通行数据及其版本一起设计提交边界；让异步结果影响玩法时，重放还需记录接受的结果与实际提交 tick。

### 缓冲与确定性

`ProjectileBatch` 大小固定为 282,688 字节，包含玩家、最多 896 怪物和 128 弹道的数值输入（角色底面/顶面、弹道起止海拔）、目标句柄输出、候选数量及 128×896 个 Uint16 候选游标。查询 Worker 只负责角色几何查询，环境遮挡留在拥有地形缓存的权威线程提交阶段，不在查询 Worker 再生成世界。
`prepare(grid, query, category, enemyIndices)` 必须接收权威端已有的索引、查询缓冲与实体槽映射，在提交任何执行端前完成初筛；
分区拷贝只写有效候选前缀，未使用区间不参与求交。
每个查询 Worker 只有一个循环转移缓冲；连续弹道区间按估算求交次数平分，避免友方与敌方弹道混合时工作量偏斜。
它们不读取地域对象、不消耗随机数、不创建或删除实体。
模拟先收集全部弹道的起止位置，记下槽到批次游标的映射；所有区间完成后，再按原查询的交换删除顺序提交命中，
保持奖励与随机数消费顺序。平局仍比较完整句柄。线程完成顺序不会改变结果。

表现缓冲包含减速/狂暴标记、祝福截止 tick、动作锁定目标 XZ、弹道当前/上一海拔、128 项效果和 256 项伤害飘字事实，大小由 `RenderFrame.bytes` 按布局和对齐计算，当前每份 310,232 字节，共两份：
初始模拟端与主线程各持一份，收到新帧后，下一请求才归还旧帧。
所有实体、宝箱和效果的绝对 XZ 坐标均为 Float64，避免远处世界的表现位置与命中、拾取位置不一致；
提交 GPU 时才转换为相对表现原点的局部 Float32。怪物等级与 AI active 标记没有表现消费者，留在权威端，不再复制到表现帧。
动作目标 XZ 与祝福截止 tick 使用三个固定容量 Float64 数组，合计 `3 × 1857 × 8 = 44,568` 字节；弯刃直接复用现有位置朝向字段，转弯速度、效果来源句柄、起手计数与特殊冷却只留在权威端。表现帧继续从当前容量推导布局，不增加独立事件通道。
生命事实、行为树记忆、冷却、地域引用和物品定义同样留在权威端。
初始分配后不逐帧新建大缓冲；每次转移会重新绑定 TypedArray 视图。复制量为实际发布频率乘 `RenderFrame.bytes`，
不含低频对象快照和浏览器消息调度开销；当前值由诊断与测量脚本报告。

使用 transferable ArrayBuffer 明确转移所有权，发送端的对应缓冲会 detach；活跃 ECS 的组件存储永不转移。
当前无需 SharedArrayBuffer；后者需要跨源隔离，并且仍需定义发布与同步协议。
参考 [MDN 转移对象](https://developer.mozilla.org/en-US/docs/Web/API/Web_Workers_API/Transferable_objects)、
[共享内存约束](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/SharedArrayBuffer)。
入口使用 Vite 可识别的 `new Worker(new URL(..., import.meta.url), { type: "module" })`，生产构建输出独立 Worker 文件。

### 预算、测量与失败

`WorkerBudget` 按浏览器报告的逻辑核数给出固定预算：1–5 核为 1 地形 + 1 模拟；6 核以上为 2 地形 + 1 模拟。
`GAME_CONFIG.workers.parallelCollisionEnabled` 默认为 false，不创建空闲查询线程。显式启用且至少 8 核时再分配 2 查询，最多 5 个后台 Worker。
测试与应用入口可显式传递 `workerBudget(hardwareConcurrency, true)`，仍受核数和通道上限约束。小核数始终由专用模拟 Worker 执行。
单独增加一个查询 Worker 只会增加等待和通信，当前没有与之重叠的权威工作，因此不分配单查询线程。

工作量为每条友方弹道经过网格与扫掠包围盒筛选的实际候选数之和，加每条敌方弹道的一次玩家检查。
只有配置了查询线程且估计至少 49,152 次求交时才分发。这里选择的是执行粒度，任何线程失败都不会切换计算路径继续旧局。
`npm run benchmark:app:workers` 使用真实 Node 查询线程，比较分散和密集近失输入的 16/32/64/128 条弹道；每场景预热 100 批，五次各测 200 批。静止目标索引在计时前建立，候选初筛、数值求交和分发复制/转移/等待仍计时。
满载串行与调度查询均须低于 3 ms；只有生产配置启用并行时，才额外要求实际分发场景比串行更快。报告包含候选数量、配置、缓冲尺寸和原始样本，不能据此推导浏览器输入延迟。
早期全量扫描与后续空间索引测量的输入和代价不同，密集输入也不保证分发比本地更快；保留数据见[测量索引](../README.md#evidence)，不把试测比例写成稳定提速承诺。
专门的浏览器 Worker E2E 显式启用查询配置并制造密集候选，验证独立 Worker 确实参与查询；日常入口不创建查询线程，软件渲染测试不承担帧率证明。

请求和查询都有 15 秒超时；创建失败、脚本错误、解码失败、非法协议、超时均进入 failed，
终止全部战斗 Workers，拒绝等待请求并清空队列。加载世代同时防止旧结果与旧错误覆盖新局。
重开复用地图资源但新建战斗模拟与线程；重试失败局也是重新初始化，不延续部分提交状态。
`session.diagnostics` 暴露存活线程数、在途请求、积压/丢弃 tick、命令数、批次耗时、传输往返时间和本地/并行批次数。
测试覆盖真实线程数值一致性、交换删除后的命中顺序、缓冲 detach 与复用、超时、命令顺序、背压、暂停和旧结果失效；
浏览器再验证 20 次重开、查询线程崩溃、重新加载和关闭后的线程数归零。

### 逐 Worker 负载观测

左上 `WorkerLoadPanel` 展示模拟、各碰撞查询和各地形 Worker，使用任务占用率而非 OS CPU 利用率。
`TaskActivity` 在请求发出和回复到达处累计墙钟耗时；模拟记录主线程到模拟 Worker 的往返，
查询记录模拟 Worker 到对应查询 Worker 的往返。客户端已有完成数和往返耗时复用这份计数。
两者均包含通信、等待及调度延迟，不能相加推导 CPU 核利用率。
模拟等待查询时也处于占用状态。查询统计随完整战斗批次回传，不额外向 Worker 发送轮询请求。
一次模拟任务指一个请求批次，查询任务指一个弹道分区，地形任务指一次生成请求；任务频率不等同于模拟 tick 频率。

地形侧 `WorldGeneratorPool.workerActivity` 独立提供每个线程的 ID、在途状态、累计占用毫秒、
已结束任务数、最近耗时及当前任务类型，`HexMap.workerActivity` 只读转发当前世界的数据。
统计只覆盖实际发给线程的任务，不计排队等待；已发出的任务即使取消，也统计直到其执行 Promise 结束。
线程替换获得新 ID 并清零，销毁后列表为空；静态世界不产生虚构的地形线程。

`WorkerLoadSampler` 约每秒通过已有帧循环取一次值，按实际经过时间计算
`占用率 = Δ累计占用毫秒 / Δ墙钟毫秒`、`任务频率 = Δ结束任务数 / Δ墙钟秒数`。
模拟与地形记录包含当前在途时间，因此长任务尚未回复也能显示占用；查询记录在批次完成时归入采样窗口。
延迟回传跨越多个窗口时百分比钳制到 100%，不会显示超过单线程容量的值。
首次采样和计数器重置只建立基线；每个活跃线程只保存一份基线，没有无界历史。
暂停后的空闲窗口归零；死亡后也继续观察地形线程。重新加载或重开重建采样基线，避免旧局影响新局。
地形任务计数包括失败或取消后结束的请求；战斗异常时仍按既定失败流程终止战斗 Workers，负载面板不参与调度。

### 帧、阶段耗时与输入反馈

`FramePerformance` 在 `afterframe` 记录采样，约每秒与 Worker 行一起发布，暂停后仍继续；加载、隐藏/恢复和重开重置窗口。
面板标明实际窗口秒数，主线程卡顿时不把变长的采样窗口仍称为一秒；恢复时同时重建 Worker 占用基线。
窗口均值累计所有样本，P95 使用窗口内最近最多 512 个值，TypedArray 复用，仅发布时排序；不保存无限历史。

| 指标 | 实际口径 |
|---|---|
| FPS / 帧间隔 P95 | 根据相邻主循环的 RAF 时间戳计算；隐藏/恢复后的首个间隔不参与 |
| 主循环 CPU / P95 | 从地图帧开始到 Three.js 绘制提交完成，包含输入、角色、镜头和地图工作；是墙钟耗时，不是 OS CPU 利用率 |
| 角色 / 镜头、地图挂载 | 分别计时 `HexCombatView.render` 与地图帧任务队列，前者包含实例动画更新 |
| 收包 / UI 发布 | 主线程协议处理、绑定表现视图、冻结快照和同步发布；不包含之后的异步 React 渲染 |
| GPU | 复用地图的异步 WebGL 查询，只统计新完成的样本，并保留样本年龄；没有可用样本时显示 — |
| 浏览器长帧 | 可用时观察 `long-animation-frame`，记录窗口计数、最长帧、最大阻塞和从样式/布局开始到帧结束的最长渲染尾段；只覆盖超过 50ms 的页面帧 |
| 快照年龄 | 距离收到最近完整模拟结果的墙钟时间，暂停时明确标记并允许继续增长 |
| 采样→绘制 | 最近一次移动输入变化，从主线程采样到采用该输入的结果完成 Three.js 绘制提交；含积压与往返，不含设备、事件排队和屏幕呈现 |
| 模拟执行 / 查询等待 | `batchMs` 为模拟端处理整批的墙钟时间，`queryWaitMs` 为远程查询 join 等待之和，`executeMs = batchMs - queryWaitMs`；执行段也不是系统 CPU 计数 |
| 通信 / 调度 | 主线程往返减去 Worker 批次耗时，包含消息克隆、线程调度和主线程接收排队，不能解释为纯通信成本 |
| 积压 / 丢弃 tick | 显示在途批次、待执行 tick、局内因队列溢出丢弃的 tick |
| 超出追赶上限 | `FixedStepClock` 报告帧间隔超过 250ms 追赶上限而裁掉的时间，会话按局累计；与队列溢出分开，暂停、隐藏和上下文恢复不计入 |

输入反馈只在实际绘制后确认，同一输入不会每帧重复计时；暂停、隐藏和新局不会接纳旧输入的迟到确认。
浏览器长帧观察器按应用生命周期创建一次，重置之前/加载期条目丢弃，关闭时 disconnect；不支持时明确缺少观测，不伪造零值。
GPU 和长帧记录异步送达，按到达窗口统计，不能与当前帧 CPU 耗时逐帧相加。
长帧机制见 [Chrome Long Animation Frames](https://developer.chrome.com/docs/web-platform/long-animation-frames)。
这些指标组合定位 Worker 等待、主线程工作和页面卡顿，仍不等同于全线程 CPU 采样或实机性能验收。

### 固定频率配置与吞吐估算

`GameConfig.ts` 统一定义目标、预算、背包规则和品质色，派生周期不重复写常量。运行期不修改固定步长。
固定逻辑与渲染刷新分开；固定更新不代表主流引擎统一使用 120Hz，参见 [Unity 固定更新](https://docs.unity.cn/6000.0/Documentation/Manual/fixed-updates.html)。

| 工作 | 当前调度 | 说明 |
|---|---|---|
| 权威模拟、移动、弹道、命中 | 120Hz 固定 tick | 每 tick 8.333…ms；一秒的渲染帧增加不额外生成逻辑时间 |
| 近圈行为决策 | 30Hz，按句柄错峰 | 位移和攻击释放不降频；目标失效与驻留变更立即响应 |
| 远处巡逻/归位决策 | 5Hz，按句柄错峰 | 保留移动意图，位移连续 120Hz；46 外才休眠 |
| 祭司同伴搜索 | 5Hz，按句柄错峰 | 搜索结果保存完整句柄；施放与释放分别检查有效性 |
| 自动技能判断 | 10Hz | 按槽顺序检查，单技能结算后再执行下一技能 |
| 回复 | 2Hz | 保留每半秒回复量 |
| UI 完整快照 | 10Hz | 命令、通知、死亡和屏障可强制发布 |
| 碰撞 Workers | 按 tick 的查询需求 | 达到 49,152 对实际候选检查才派发；无独立空转定时器 |
| 地形 Workers | 按流送需求 | 沿用地图调度、并发和挂载预算，不伪造固定 FPS |
| 主线程绘制 / 诊断 | 浏览器 RAF / 约 1 秒 | 绘制使用最新完整结果；诊断按实际窗口统计 |

`FixedStepClock` 用整数微秒×Hz 累加，再除以一百万取得 tick，避免把 120Hz 周期取整造成长期漂移。
单帧接受最多 250ms，因此批次和待执行队列上限都派生为 30 tick；暂停、隐藏、上下文恢复不补算间隔。
这限制积压并保证玩法时间步长，不能保证慢设备持续达到 120 个已完成 tick/s。

Worker 记录本批实际执行的 tick 数和单独的模拟阶段时间（包含查询等待，排除命令与快照打包）。
主线程按窗口累加，不对多个批次的 Hz 作简单平均：

- 逻辑实际 Hz = 已完成 tick 数 / 实际窗口秒数，批次跨窗口到达会产生波动。
- 每 tick 耗时 = 完整模拟时间之和 / 已完成 tick 数；执行段另扣除查询等待。
- 预计逻辑上限 = 1000 / 每 tick 耗时，逻辑预算占比 = 每 tick 耗时 / 8.333…ms。
- 理论 FPS = 1000 / max(主循环均值 + 每帧均摊的收包/UI 发布耗时, GPU 均值)。CPU/GPU 两条流水线不相加。

没有 GPU 样本时标注“理论 FPS · CPU”，不能解释成整机渲染上限。估算不包含全部异步 React、页面布局、设备呈现和系统竞争，
与实际 FPS、长帧、快照年龄一起判断。零 tick 批次和暂停窗口不产生逻辑吞吐估计，也不会用初始化耗时倒推逻辑频率。
理论值不会反过来加速逻辑；用户可以观察新增功能是否提高每 tick/每帧成本，即使实际刷新率暂时仍受目标频率限制。
