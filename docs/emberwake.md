# 余烬航线 / Emberwake

这是基于无限世界基建的可玩应用，入口为 `/emberwake.html`，主演示页面也提供链接。
执行 `npm start` 后访问 <http://127.0.0.1:3000/emberwake.html>。
游戏使用中文界面，默认航图为 `emberwake-13`；开场面板可以输入其他种子并开启新航程。

## 目标与节奏

玩家驾驶最后一艘信使飞艇，在风暴抵达前连接三座信标，再回到 `(0, 0)` 的母港。
世界坐标没有逻辑边界；每局的行动时间限制为 120 小时。最后一座信标位于起始源区块
之外，实际航行会触发已有的 Worker 地形生成、源区块流送和渲染驻留淘汰。

时间只在执行行动时推进。镜头移动、航线规划、阅读日志、选择改装、关闭页面都不消耗
游戏时间。到达母港且已连接三座信标即获胜，包括恰好在第 120 小时返回；其他情况下
到达第 120 小时失败。结算展示探索、信标、回声和剩余时间构成的评分，可以重开。

| 行动 | 时间 | 效果 |
|---|---|---|
| 飞行一格 | 1 小时 | 消耗 1 燃料；山地、丘陵或雪地消耗 2，惩罚不叠加 |
| 太阳帆充能 | 3 小时 | 恢复 6 燃料；可以从零燃料恢复，满油时拒绝操作 |
| 补给站停靠 | 1 小时 | 恢复 16 燃料，同一站点只能领取一次 |
| 打捞回声 | 2 小时 | 获得 1 段回声并恢复 6 燃料，同一站点只能领取一次 |
| 接通信标 | 2 小时 | 恢复 24 燃料、连接信号，并提供一次改装选择 |
| 选择改装 | 不耗时 | 必须选择尚未安装的一项，选完才能继续航行 |

初始燃料为 36，容量为 48；恢复燃料始终受容量约束。三种改装分别为：

- **越岭涡轮**：移除山地、丘陵和雪地的额外燃料消耗。
- **集光风帆**：太阳帆每次恢复 10 燃料，仍消耗 3 小时。
- **扩容燃料舱**：容量提升至 64，安装时立即增加 16 燃料。

评分为 `信标数 × 300 + 回声数 × 120 + 探索格数 × 5`；胜利额外获得
`500 + 剩余小时 × 10`。日志仅保存最近五条，探索和站点记录受单局行动上限约束。

## 操作与信息

点击地面或近域雷达选择目的地，再点击“启航”。飞艇可以跨越所有地形，因此规划直接
沿六角网格最短路线逐格推进；没有地面通行障碍，不需要启动分层地面寻路或后台军队模拟。
单段路线最多 48 格，玩家可以分段探索。规划显示格数、时间和每格燃料范围，不假装
已经精确采样未加载地形的整段成本。执行每一步前才读取真实地形并检查燃料。

信标卡片和“定位下一座信标”会选中目标并移动镜头；信标全部接通后，目标按钮定位母港。
航行时镜头跟随飞艇，在未领取的补给、回声、信标处自动暂停，让玩家选择是否停靠。
“暂停航行”或隐藏标签页会阻止下一步开始；已经开始保存的一步会完成提交。

近域雷达展示飞艇周围的确定性信号与已探索格。信号不依赖镜头所在位置；本版本没有
战争迷雾，三座任务信标从开局就可定位，避免把限时决策变成盲目搜索。

| 输入 | 行为 |
|---|---|
| 点击“启航” / 空格 | 启动或暂停已规划的航线 |
| `E` | 在当前位置停靠或接通信标 |
| `R` | 太阳帆充能 |
| `F` | 镜头回到飞艇 |
| `WASD` / 右键拖动 / 滚轮 | 使用基建原有的镜头移动、旋转和缩放 |
| `?` | 查看手册、重开当前种子或输入新种子 |

小屏幕采用紧凑信标列表、雷达和底部按钮，操作不依赖快捷键。

## 代码与所有权

| 文件 | 职责 |
|---|---|
| `public/emberwake/rules.js` | 纯规则状态转换、绝对坐标站点、六角距离和存档状态校验 |
| `public/emberwake/app.js` | 启动、输入、有限逐步航行、独占状态操作、存档和 DOM 展示 |
| `public/emberwake/view.js` | 飞艇和站点的 Three.js 表现、自定义渲染图层、雷达绘制 |
| `public/emberwake.html`、`public/emberwake/style.css` | 独立游戏页面、手册、改装与结算面板及响应式样式 |

规则没有进入 `HexMap` 或主包导出，也没有新增依赖。原有战役演示仍是独立的基建集成
样例；游戏未复制其后台行军、旧存档导入或与玩法无关的诊断控制面板。

游戏直接消费 `ProceduralWorldSource`、`HexMap.loadWorld()`、现有六邻居坐标、
`WorldSurfaceAnchor`、`WorldRenderLayer` 和 `GenerationCheckpointCoordinator`。
源区块为 24×24，加载半径 1，保留半径 2，驻留上限 25，地形与植被共享两个 Worker。
非驻留航行目标通过同一 Worker 池读取基础区块；应用最多另留四个紧凑区块供执行使用。

自定义图层通过受生命周期约束的 host 发布对象，使用实际地表高度定位。飞艇和四座
任务建筑采用共享基础几何体；局部补给与回声使用固定容量的实例网格，航线点最多 48 个。
图层通过独立资源账户申领这些分配，释放时移除帧监听、销毁几何体、材质与实例缓冲并
释放账户。雷达和站点仅在行动或选点时更新，不逐帧枚举世界。帧回调只做飞艇表现动画。
没有修改冻结的基建生命周期、生成协议、调度或地表合同。

## 存档与失败边界

每个种子使用独立存档，IndexedDB 数据库为 `emberwake-generations-v1`。
权威状态只有一个必需 participant `expedition`，版本为 1：位置、时间、燃料、信标、
已领取站点、已探索格、改装、待选改装、回声、游戏状态和日志在同一份快照中保存。
基础地形和站点可由种子重建；实例网格、镜头、路线预览、雷达和缓存不进入存档，
不需要持久化地形覆盖或模拟快照。

每个有效动作先通过纯规则生成新快照，再在应用独占边界内完成严格世代 checkpoint。
输入在提交期间锁定，成功后才执行下一步或下一动作。存档服务负责不可变 staging、
校验和、完整世界描述符、CAS manifest 和完整世代恢复；应用校验游戏状态本身。
保存失败会暂停游戏并明确提示刷新恢复最近的完整存档，不继续进行无法持久化的行动。
刷新恢复到已提交的格子，尚未完成的航线需要玩家重新规划；待选改装和结局也会恢复。

同源同种子通过 Web Locks 保持单一写入者；第二个标签页显示明确提示并禁止开始游戏，
防止旧页面覆盖更新的航程。此浏览器应用要求 WebGL2、模块 Worker、IndexedDB、
Web Locks 和 `structuredClone`，使用现有 Chromium 验证路径。没有内存存档降级或
旧版本游戏状态迁移；世界描述符或 participant 不匹配按基建合同明确拒绝恢复。

## 验证

`tests/demo/emberwake.test.js` 验证负坐标六角邻接、确定性站点、实际可达的完整航程、
燃料与充能、站点不可重复领取、改装门槛、最后一小时胜负和非法存档。
其中高耗油航程不使用随机补给站，确保基础可玩性不依赖随机赠送。

`tests/e2e/emberwake.spec.js` 使用真实 Worker/WebGL 和按钮完成三座信标与返航，
中途刷新恢复待选改装、检查跨区块航行与资源边界，再恢复结局并重开；另验证窄屏雷达
输入、第二个标签页的存档写入隔离，以及更换种子后原航程的独立恢复。
`?quality=fast` 是显式的自动化渲染配置，玩法相同。
常规完整材质的画面通过实际浏览器截图检查。其他必需检查沿用 [testing.md](testing.md)。
