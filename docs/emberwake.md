# 余烬要塞 / Emberwake Mobile Fortress

这是基于无限世界基建的独立实时游戏，入口为 `/emberwake.html`。执行 `npm start`
后访问 <http://127.0.0.1:3000/emberwake.html>，也可以从基建实验室的入口进入。
本原型使用已验证有陆路的固定种子 `emberwake-13`，界面为中文。

## 目标与核心取舍

玩家保护一辆拥有 160 耐久的移动要塞，向东突围 48 格。初始拥有 38 金属、14 燃料
和两辆矿车；16 格和 32 格处各获得一次改装。主车抵达撤离线且仍存活即获胜，
可以选择继续深入，下一道撤离线再向东延伸 48 格。主车耐久归零即失败。
胜负在同一模拟步判断时，主车毁坏优先于抵达目标。

矿车需要驶往矿区，装载燃晶，再追上主车交货。未交付的货物不属于库存；矿车在
途中被击毁会损失整车货物。固定炮塔帮助守矿，但回收需要停火打包；主车过早开走，
回收会停滞。轨道炮击可以清理虫群，却与主车撤离共用燃料。

首波虫潮在 12 秒出现，此后按西侧追击、北侧突袭、东侧拦截、南侧突袭循环。
界面提前显示下一波方向和剩余时间。敌人会攻击主车、矿车和炮塔；快速猎虫优先
追击矿车，第三波开始出现更耐打的重甲虫。驻守、采矿、布防和炮击增加噪声，
转移降低噪声；噪声越高，波次间隔越短、敌人越多。

吞噬带从 `x = -10` 开始，每秒向东推进 0.14 格。进入其中的主车每秒受到 12 点
伤害，矿车和炮塔每秒受到 25 点伤害。地面作业不能在吞噬带内执行。

## 规则与输入

| 指令 | 条件和效果 |
|---|---|
| 转移 | 选择主车 10 格内可达陆地或浅滩；每开始跨越一格消耗 1 燃料 |
| 向东转移 | 选择前方 8 格处的可达点；行进中再次点击则完成当前一步后停下 |
| 采矿 | 派一辆空闲矿车前往 8 格内的矿脉；每 0.6 秒开采 1 单位，容量 20 |
| 召回 | 提前结束开采，保留已有货物并追赶主车；也可以逐车召回 |
| 速射机炮 | 16 金属，42 耐久，射程 4，伤害 3，开火间隔 0.8 秒 |
| 震荡迫击炮 | 26 金属，34 耐久，射程 6，伤害 6，间隔 2.4 秒，命中点一格内群伤 |
| 回收炮塔 | 主车 4 格内停火打包 3 秒；机炮返还 12 金属，迫击炮返还 20 金属 |
| 轨道炮击 | 选择 10 格内落点，消耗 4 燃料；1.2 秒后对两格内敌人造成 26 伤害，冷却 12 秒 |
| 紧急维修 | 18 金属，恢复主车 40 耐久，不超过最大值 |
| 重建矿车 | 22 金属补回一辆损毁矿车，编制最多两辆 |

炮塔需要部署在主车 4 格内的空地，不能与主车或已有炮塔重叠，高地射程增加 1。
主车自带射程 4、伤害 2、间隔 1 秒的自动主炮。深海和湖泊不通行；山地、丘陵和
浅滩会减速。寻路使用真实基础地形，选择格数最短的可通行路线。

矿脉由绝对坐标哈希和基础地形确定，初始附近另设两处确定矿脉；普通矿脉有 32
单位，高地有 42 单位。每辆矿车交货时，货物全部计入金属，同时增加
`floor(货物 / 2)` 燃料。矿车满载或矿脉耗尽会自动返航，返航中每秒重新规划到移动
主车的路线。到达主车邻格或同格并结束路线后交货。单车耐久为 28；矿车和炮塔离
主车超过 17 格会失联，分别损失车辆编制或计入遗留防线。被击毁敌人提供少量金属。

三种改装各只能安装一次：双联火控使主车与炮塔伤害增加 2；重载采矿车将容量提高
到 28，并改善山地和丘陵通行速度；复合装甲将主车最大耐久增加 60，同时修复 60。
首次撤离后继续深入可以在 48 格处取得第三项改装。

| 输入 | 行为 |
|---|---|
| 下方指令 + 点击地面或雷达 | 在目标点执行命令；再次选择当前指令或按 `Esc` 取消 |
| `M` / `1` / `2` / `3` | 转移 / 采矿 / 机炮 / 迫击炮 |
| `Q` / `X` / `V` | 炮击 / 回收 / 维修 |
| `R` / `F` | 召回全部矿车 / 镜头回主车 |
| 空格 | 战术暂停或继续，暂停中仍可下达指令 |
| `WASD` / 右键拖动 / 滚轮 | 基建原有镜头平移、旋转和缩放 |
| 顶部按钮 | 暂停、1×/2×速度、音效、作战手册 |
| 底部保存按钮 | 暂停并等待当前保存完成，再保存此刻的战场 |

开始界面、手册、改装、结算、隐藏标签页和图形上下文中断都会暂停战斗。回到隐藏过
的标签页后由玩家主动继续。小屏幕保留指令、矿车编队和可操作雷达，不依赖快捷键。
音效使用用户操作后启用的 Web Audio 振荡器和包络，不加载音频文件。

## 代码对应关系

| 文件 | 职责 |
|---|---|
| `public/emberwake/rules.js` | 确定性固定步长战斗、命令校验、运输结算、敌方 AI、胜负和存档校验 |
| `public/emberwake/world.js` | 九个紧凑基础区块组成的作战窗口、现有 A* 适配、真实通行性与矿脉查询 |
| `public/emberwake/app.js` | 启动、输入、时钟、窗口迁移、严格世代存档、DOM 与决策面板 |
| `public/emberwake/view.js` | 自定义世界图层、车辆/虫群/炮塔表现、雷达和合成音效 |
| `public/emberwake.html`、`style.css` | 游戏页面、响应式战场面板、手册、改装和结算 |

游戏规则没有进入 `HexMap`、主包导出或基建实验室，也没有新增依赖。飞艇探索原型
的行动、站点、回合规则和表现代码已被替换，未保留兼容分支。

## 模拟与无限世界边界

`FortressSimulation` 不依赖浏览器或渲染器，逻辑每步推进 0.2 秒。帧回调累计时间，
单帧输入时间最多计 0.25 秒，累积上限 0.8 秒，避免卡顿后集中补跑大量战斗。
1×/2×只改变累积速率，规则本身一致。移动进度、武器冷却、打包和炮击倒计时均属于
权威状态；更换路线会保留已经开始的当前一步，避免重复扣油和凭空改变移动位置。

`ProceduralWorldSource` 使用 24×24 源区块和两个共享 Worker。渲染加载半径为 1，
保留半径为 2，驻留上限 25，每帧最多挂载一个区块，挂载预算 3 毫秒。

模拟通过同一个 source 的 `sampleBaseChunk` 在主车周围保留 3×3 个紧凑区块，
与渲染镜头和驻留状态独立。主车跨源区块边界时暂停模拟，等待新窗口全部采样完成，
再一次性发布；失败时不发布半个窗口，并明确暂停游戏。所有请求通过
`Promise.allSettled` 排空，已有重叠区块继续复用。窗口的偶数 X 原点保持负坐标六角
列奇偶关系，使用现有 `PathFinder` 的有限地图接口执行局部 A*；没有把无限地图冒充
有限世界，也没有复制寻路算法或在每个战斗步请求全世界导航。

敌人最多 72 个、炮塔最多 8 座、矿车最多 2 辆，单位路线最多 80 步。刷怪只检查
当前作战窗口内 6–9 格的候选点，并要求实际可达；每波最多 22 个。敌人按错开的
时间重新寻路，远离主车或落入吞噬带后方的敌人会清理。已开采记录只保存发生变化的
矿脉，每 10 秒删除吞噬带后方无法再作业的记录。事件队列最多 256 条，日志最多五条。

## 表现与资源所有权

世界对象通过 `WorldRenderLayer` 的 host 发布，位置使用 `map.surface` 的真实地表
高度和现有六角中心坐标。车辆、炮塔共享基础几何体；虫体、虫腿、矿石、路线和粒子
使用固定容量实例网格。矿石缓冲按半径 11 的全部六角格上界分配，敌人与炮塔容量
对应模拟上限；枪线最多 96 条，爆炸最多 12 组、每组 10 个粒子。

应用通过独立资源账户申领模型缓冲与持有的九个紧凑地形区块。图层随生命周期清除帧
监听，释放共享几何体、材质、实例缓冲和账户。地表高度缓存最多 2048 项，在地表
修订后失效。矿脉、路线、吞噬带和雷达在逻辑步或输入变化时更新；帧回调负责位置
平滑、炮塔朝向、虫腿和短时特效，不枚举无限世界。镜头远离主车不影响战斗结果。
只读 `getEmberwakeDiagnostics()` 返回快照、资源/窗口统计和投影位置，未提供跳时、
赠送资源、改变战局等自动化专用控制接口。

冻结的基建生命周期、地表、生成协议、调度与资源合同均未修改。

## 存档和失败边界

IndexedDB 数据库为 `emberwake-fortress-generations-v1`，world ID 为
`emberwake-fortress`。唯一必需 participant `fortress` 的版本为 1，保存主车、全部
单位及其路线/进度/冷却、待落点炮击、矿脉耗用、金属/燃料、波次/噪声、改装、胜负
和日志。基础地形可重建，镜头、音效、UI 工具、表现特效和九区块缓存不进入存档。

命令和交货、改装、胜负触发 checkpoint，持续战斗每 5 个模拟秒自动保存。保存中
的重复触发合并为一个待保存标记；当前提交完成后再次捕获最新状态，直到所有请求
处理完毕，避免暂停在改装或结局时遗漏最后的变更。边界保存根据权威状态触发，
不依赖可能截断的表现事件队列。手动保存先暂停并等待已有
任务，然后另存当前快照。`withWorldState` 只在捕获/恢复期间排斥输入和模拟变更，
快照完成后不可变 staging 可以在战斗继续时提交，不把 IndexedDB 延迟当作战斗时钟。

`GenerationCheckpointCoordinator` 负责校验和、完整世界描述符、CAS manifest、
完整世代恢复和孤立 staging 回收。应用另行校验单位标识、相邻路线、资源、冷却、
实体容量和状态格式。保存失败会明确暂停；刷新从最近一个完整提交恢复，进入开始
界面后才继续。路径、半步移动、载货、待选改装和结局都恢复，不产生重复交货。

同源 Web Lock 在页面生命周期内维持单一写入者，第二个标签页禁止开始并提示关闭
原页面后刷新。本原型要求 WebGL2、模块 Worker、IndexedDB、Web Locks 和
`structuredClone`。无内存存档降级或旧格式迁移；旧飞艇数据库与新游戏隔离。
玩家可以明确选择重新开局，重置要塞战局并写入新的完整世代。

## 验证

`tests/demo/emberwake.test.js` 覆盖部分载货召回、追上移动主车、延迟回收、真实攻击、
延迟炮击、损毁货物不入库、确定性恢复、非法命令不改变状态、负坐标邻接与失败窗口
不发布。完整远征使用实际生成地形执行采矿、守矿、回收、维修、改装和跨区块移动：
受保护车队能够撤离，相同补给策略下缺少防线的车队损失补给并失败。

`tests/e2e/emberwake.spec.js` 使用真实 Worker/WebGL 和实际按钮、地面点击、雷达
输入，完成矿车运输、炮击、炮塔回收、改装刷新恢复和跨源区块转移；另检查窄屏
可操作性、完整战场恢复和第二标签页写入隔离。通过受控保存完成屏障验证提交期间
的新命令确实另存一代，没有直接改写游戏状态。完整胜负规则放在可重复的模拟层测试。
`?quality=fast` 是显式的自动化渲染配置，玩法保持一致。常规材质、桌面和手机布局
通过真实浏览器截图检查。其他必需检查沿用 [testing.md](testing.md)。
