# 世界风格生成 v1 设计

导航：[总导航 · 地图基础库](README.md#foundation) · [按任务阅读](README.md#routes)

状态：已实现并冻结，当前生成器为 v22。本文维护当前生成、地表与验收合同；历史测量和阈值调整见[测量证据](evidence/world-style-generation.md)，已完成的实施过程由 Git 保存。

本文记录已冻结的世界生成与地形表现方案。目标不是模拟真实地球，而是在保留六边格、区块流式加载、工作线程和现有资源预算的前提下，生成风格统一、自然、耐看的世界。

基础设施约束见 [foundation-v1-freeze.md](./foundation-v1-freeze.md)，测试规则见 [testing.md](./testing.md)。

## 1. 结论

采用三层结构：

~~~text
世界描述符 + 当前生成器版本
              │
              ▼
      世界地表解析器
 WorldSurfaceResolver
              │
       ┌──────┴──────┐
       ▼             ▼
 一次性生成       区块工作线程
 generateWorld    generateWorldChunk
       │             │
       └──────┬──────┘
              ▼
       MapInfo / PackedWorldChunk
              │
              ▼
       生效地表视图
      WorldSurfaceView
  生成基础 + 稀疏编辑 + 显示尺度
              │
              ▼
 地形、城市、单位、植被、标记、自定义层
~~~

核心决定：

- 保留逐格六边形地形，不改成连续地形块或 clipmap。
- 保留 WorldSource、源区块、12×12 渲染块、LOD、生命周期和资源预算。
- 生成规则只保留一份，由 WorldSurfaceResolver 同时服务一次性生成和工作线程。
- 渲染器始终读取“生效地形”，不能用种子生成结果覆盖玩家编辑。
- 区块构建时使用短命的 WorldSurfaceWindow 去重采样，不建立全世界缓存。
- v1 只有一种内部风格配置，由 WORLD_GENERATOR_VERSION 锁定，不增加多余的风格版本字段。
- 512×512 是主要有限世界样本，但算法不能写死 512。
- 不建设物理水循环或全局地形图；水体只实现确定性的宏观海域和有界粗网格排水网络。

## 2. 目标与非目标

### 2.1 目标

1. 多个种子都能产生连贯的大陆、海域、汇流河网、山系、平原和森林。
2. 山体内部连续，边缘有山麓，不出现大量单格尖峰。
3. 森林形成区域；海域不受地表细节噪声打散，河道不呈现椒盐状随机点。
4. 相同描述符和坐标的结果不受区块大小、请求顺序、工作线程数量和缓存命中影响。
5. 源区块、渲染块、LOD、环绕边界、卸载重载和浮动原点没有可见接缝。
6. 城市、单位、路线、草木和标记能正确贴合地表。
7. 六边格边界、选择反馈和玩法可读性仍然清楚。
8. 新增成本继续受现有工作队列和资源预算约束。

### 2.2 非目标

- 不模拟板块运动、真实侵蚀和全球水循环。
- 不把地形渲染改成与六边格无关的连续网格。
- 不重写流式加载、区块驻留、LOD 调度和渲染层生命周期。
- 不开放几十个公共生成参数。
- 不保证新生成器与旧种子生成相同世界。
- 不提前建设通用地形特征系统、全局地图集或 AssetRegistry。
- 不以噪声复杂度和单测数量衡量视觉质量。

## 3. 当前实现

- 当前生成器为 v22。一次性生成和 chunk 生成共用 `WorldSurfaceResolver`，不再分别维护地形分类、湖泊、丘陵、森林和树种规则。
- `LandformSampler` 提供连续地貌、气候和独立低频 ocean 场；无限域使用全局坐标，环绕域使用周期噪声，有界域保留边缘衰减。
- `WorldSurfaceView` 将基础生成和稀疏编辑合成为生效地表，城市、单位、草木、路线和标记使用同一贴地高度契约。
- `PackedWorldChunk` 保持每格 16 位和一圈邻域；共享地表顶角、LOD 边缘采样和逻辑坐标细节相位保护跨区块一致性。
- 完整 descriptor 统一缓存键、默认 worldId 和导航 terrainRevision。参数变化产生新身份，冻结描述符防止计算指纹后的配置漂移。
- 固定 checksum、邻域/环绕接缝、最终地表与概览像素测试保护确定性；风格语料负责生成分布和连通性验收。
## 4. 核心结构

### 4.1 生成地表

LandformSampler 只负责连续基础场。

WorldSurfaceResolver 负责把基础场解释成地形、地表高度、气候、植被、海域和排水河道：

~~~ts
interface WorldSurfaceResolver {
    readonly seed: string;
    readonly domain: LandformDomain;
    readonly profile: WorldStyleProfile;
    readonly waterStyle: WorldWaterGenerationStyle;

    sampleGenerated(x: number, y: number): Readonly<WorldSurfaceSample>;
    resolveGeneratedTile(x: number, y: number): Readonly<TileInfo>;
    visitGeneratedRiverTiles(originX, originY, width, height, visit): void;
    createWindow(): WorldSurfaceResolverWindow;
}
~~~

sampleGenerated() 只处理单点连续结果，不逐像素追踪河道。resolveGeneratedTile() 合并分页河网并读取固定的一圈六邻域，用于海岸和最终格子修饰。visitGeneratedRiverTiles() 一次追踪并栅格化目标范围内的河道，供小地图避免逐格解析整个世界。

主入口导出 `createWorldSurfaceResolver` 及解析器相关类型；应用可读取连续采样和生成地格。
生效地表的 `WorldSurfaceView` 实现仍在包内，渲染和游戏对象通过公开的
`WorldSurfaceAnchor` 契约读取贴地高度，避免绕过玩家编辑。

### 4.2 地表样本

~~~ts
type WorldBiome =
    | "ocean"
    | "coast"
    | "temperate"
    | "dry"
    | "cold"
    | "alpine";

interface WorldBiomeWeights {
    readonly temperate: number;
    readonly dry: number;
    readonly cold: number;
    readonly alpine: number;
}

interface WorldSurfaceSample {
    readonly baseTerrain: Land;
    readonly relief: number;
    readonly biome: WorldBiome;
    readonly biomeWeights: WorldBiomeWeights;
    readonly vegetationDensity: number;
    readonly vegetationKind?: "palm" | "pinia" | "oak";
    readonly landform: Readonly<LandformSample>;
}
~~~

说明：

- relief 是归一化的生成高度，不是最终世界 Y。
- landform 保留当前生成器的原始连续场，供地表解析与渲染调试使用。
- biome 是主标签，主要用于统计和树种选择。
- biomeWeights 用于连续材质混合，不能直接按 biome 画硬边界。
- vegetationDensity 是连续值，不是最终布尔结果；宏观海域由 landform.ocean 与固定阈值分类。

### 4.3 生效地表

运行时权威结果仍然是：

~~~text
生成基础格子 + WorldTileOverride = 生效格子
~~~

WorldSurfaceView 负责把当前 MapInfo、可选解析器和显示尺度合并起来：

~~~ts
interface WorldSurfaceAnchor {
    readonly revision: number;
    readonly minimumHeight: number;
    readonly maximumHeight: number;
    getTileCenterHeight(x: number, y: number): number;
    getWorldHeight(worldX: number, worldZ: number): number;
}

interface WorldSurfaceView extends WorldSurfaceAnchor {
    readonly map: MapInfo;
    readonly resolver?: WorldSurfaceResolver;
    readonly tileSize: number;
    readonly mountainHeight: number;
    getEffectiveRelief(x: number, y: number): number;
    createWindow(): WorldSurfaceWindow;
    setMountainHeight(value: number): boolean;
}
~~~

WorldSurfaceView 不拥有格子，也不写入存档。创建时必须校验地图拓扑、尺寸与解析器一致。

### 4.4 编辑后的高度规则

所有内置渲染层使用同一优先级：

1. 当前没有该格子：返回岸线基准高度。
2. 生效类型为 sea、coastal，或包含 lake：返回岸线基准高度。
3. 类型与 hill 标记均等于原始生成结果：直接采用连续 relief，不再按分类截断为台阶；木林等非高度修饰不改变这一判断。
4. 编辑为 mountain 或 hill：使用对应高度范围和最小值。
5. 编辑为其他陆地：把生成高度限制在平原范围，移除 mountain 后不会留下高台。
6. 静态地图没有解析器时：mountain/hill 使用当前中性山高/丘高，其他类型保持平地。

type 或 modifiers 编辑只改变所属高度范围，不代表自由修改高度。真正的造山、挖坑和连续高度编辑以后必须使用单独版本化的 SurfaceDelta。

### 4.5 临时采样窗口

WorldSurfaceResolverWindow 和 WorldSurfaceWindow 都只用于一次生成块或渲染块构建：前者缓存生成样本与最终生成格子，后者缓存当前 MapInfo 合并稀疏编辑后的地表贡献、共享顶角和高度查询。

- 缓存核心格子、输出邻域和计算需要的有限外圈。
- 环绕世界先规范化坐标再作为缓存键。
- 同一坐标在一次构建中只采样一次。
- 构建完成立即释放。
- 结果必须与逐坐标调用解析器完全一致。

它不是新的存储格式，也不能变成无界的全世界缓存。

### 4.6 文件边界

| 文件 | 职责 |
|---|---|
| src/world/WorldGeneratorVersion.ts | 生成器版本与版本校验；原导出路径继续转出 |
| src/world/WorldStyleProfile.ts | 冻结基础风格、水体生成参数的规范化和校验 |
| src/world/WorldSurfaceResolver.ts | 唯一生成规则 |
| src/world/WorldWaterSampler.ts | 粗网格河源、下坡追踪、汇流宽度、分页缓存与环绕掩码 |
| src/world/generateWorldOverview.ts | 低分辨率地表采样与一次性河道覆盖栅格 |
| src/world/WorldSurfaceView.ts | 生效格子、显示尺度和地表高度查询 |
| 解析器和视图内部辅助代码 | 短命 WorldSurfaceResolverWindow / WorldSurfaceWindow |

依赖方向固定为：

~~~text
风格配置 + LandformSampler
            ↓
 WorldSurfaceResolver
            ↓
   WorldSurfaceView
            ↓
         渲染层
~~~

src/world 不得导入 Three.js、HexMap 或 rendering 模块。

只把 WORLD_GENERATOR_VERSION 移到中性小文件，避免 generateWorldChunk → resolver → profile → generateWorldChunk 循环依赖。其他协议版本不做无关移动。

## 5. 风格配置与确定性

### 5.1 WorldStyleProfile

完整风格配置保持内部只读，按以下几组组织：

| 分组 | 内容 |
|---|---|
| fields | 扭曲、大陆、细节、山脊、谷地、粗糙度、湿度、温度、森林斑块和独立低频海域尺度 |
| terrain | 海域阈值、地表起伏基准、山地/丘陵阈值、雪地/冻土/沙地阈值、气候过渡宽度 |
| relief | 平地幅度、谷地深度、丘陵/山麓/山体高度范围和山体曲线 |
| vegetation | 湿度阈值、最大密度、斑块强度、坡度惩罚、区域放置阈值/边缘抖动和树种温度范围 |
| rivers | 分页上限、粗采样间距、河源密度、河源适宜度、下坡势能权重和最大路径长度 |

规则：

- `WORLD_STYLE_PROFILE` 是由生成器版本确定的冻结基础配置。
- 应用只可覆盖 `WorldWaterGenerationStyle`：海域频率/阈值，以及河源密度、弯曲和汇流宽度；其余内部系数不开放。
- 水体参数在数据源构造时完成严格校验和冻结，并写入 `WorldDescriptor`，不读取运行中的全局可变状态。
- 修改基础生成语义时，必须升级生成器版本并更新格子、地表和配置基准；只调整某个世界的合法水体参数不升级生成器版本。
- field scale 必须真正传入 LandformSampler，不能再保留另一套隐藏常量。
- 海域频率同时缩放 open/toroidal 采样频率和 toroidal 最小周期数，避免小环形世界被最小周期钳制后滑块失效。

现有公开 createLandformSampler({ seed, domain }) 仍表示“当前生成器的默认地貌场”。内部解析器通过未导出的工厂传入冻结配置。

### 5.2 确定性规则

- 所有随机选择使用坐标与 salt 的稳定哈希；普通逐格选择继续使用 randomAt(seed, x, y, salt)。
- 不使用共享随机游标。
- 河源、排水势能、植被和树种等用途使用不同且稳定的 salt。
- 格子坐标必须是安全整数。
- 区块大小、工作线程编号、请求时机、镜头和缓存状态不能参与生成。
- 环绕世界先规范化坐标。
- 所有阈值输入先规范化并限制范围。
- 如果将来需要定点量化，必须在新生成器版本中统一应用于一次性生成、工作线程和测试。

## 6. 地形生成规则

### 6.1 基础分类

1. 独立低频 ocean 场低于海域阈值：sea；terrain detail、ridge 和 roughness 不参与海陆掩码。
2. elevation 足够高且 ridge 足够强，或 elevation 达到极高保底值：mountain。
3. 其余陆地先按 temperature 分 tundra；snow 还必须越过随低温下降、但不会落到岸线的气候雪线。
4. 高温低湿分 sand。
5. 剩余为 land。
6. coastal 不是基础类型；最终 sea（包括河道）的六邻居存在陆地时才派生。

generateWorld()、generateToroidalWorldTile() 和 generateWorldChunk() 统一调用解析器。

### 6.2 地表起伏

视觉层次为：

~~~text
平地和谷地 < 丘陵 < 山麓 < 山体
~~~

约束：

- 海面和湖泊使用统一岸线基准。
- 平地只允许很小的起伏。
- 谷地可以轻微下沉，但不能越过河湖职责边界。
- 丘陵由连续 elevation 区间决定。
- 山体高度主要由 elevation 决定，ridge 用于塑造山脊，不直接等于高度。
- 普通可通行地形的起伏必须明显低于山体。
- relief 不改变通行性和移动消耗；玩法继续读取生效 TileInfo。

当前 v22 使用连续 relief：丘陵项 .18、山体项 1.05；谷地信号在 .48–.9 区间对山体抬升最多压低 78%，超过最大高度 70% 的峰顶以指数压缩趋向上限。未编辑地形直接采用连续值，避免语义分类造成高度跳变。
大陆、山脊、谷地噪声分别使用 3/2/2 层；细节频率 .045、2 层；大陆权重 .845、细节权重 .035、平原粗糙度 .004。实现见 `LandformSampler`、`WorldStyleProfile` 和 `WorldSurfaceView`，不增加运行时平滑或全局缓存。

mountainHeight 仍是显示尺度，不进入生成身份。修改它时，地形、地表查询和贴地对象必须一起刷新。

### 6.3 共享顶角

一个世界顶角由三个格子共享：

~~~text
cornerHeight =
    combine((kindA, reliefA), (kindB, reliefB), (kindC, reliefC))
~~~

combine 必须满足：

- 对三个输入完全对称。
- 不依赖“当前正在绘制哪个格子”。
- 相邻渲染块和不同 LOD 得到相同边界高度。
- 格子中心高度由六个共享顶角推导，不能再次强制成格子自身峰值。

光照法线也使用共享顶角契约：每个世界顶角只由相交的三个格子中心 relief
解出同一坡度，相邻实例在公共边上插值相同的两个端点坡度。不得再从单格局部
三角扇向外有限差分，否则几何虽连续，光照仍会勾出六边形接缝。

getTileCenterHeight() 必须复用同一套六顶角结果。getWorldHeight() 在同一 CPU 三角扇上插值。

首版岸线规则：三个贡献格子中只要有 sea、coastal、lake 或地图外空位，该顶角就落到岸线基准。若样本图库证明临海山体被明显削平，再改成同样对称且有限范围的岸线衰减。

### 6.4 Shader 细节

CPU 三角扇拥有山体、山脊和峰高。Shader 只允许增加有界的小位移、法线和材质细节。

mountainHeightAt() 的细节限制为宏观地表的 ±1.5% 微位移，每次高度计算使用两次细节噪声采样。默认 mountainHeight 为 80 世界单位；贴地消费者按该有界偏移处理地表间隙。

细节还必须满足：

- 只使用逻辑世界坐标。
- 共享边界同一点得到相同结果。
- 不改变地形类型、通行性、气候和存档语义。
- full 与 fast 模式保持相同宏观表面和边界。

### 6.5 气候与植被

biome 由 elevation、temperature 和 moisture 的宽过渡带得到。

植被密度：

~~~text
气候适宜度
× 连续森林斑块场
× 坡度惩罚
~~~

最终 wood 由连续密度跨过固定区域阈值得到，坐标随机值只提供幅度受限的边缘抖动；零密度格不能因抖动进入森林。这样保留确定性和自然边缘，同时避免低适宜度区域出现椒盐状单格树。树种主要由气候决定。

编辑优先级：

- 生效格子没有 wood：密度为 0。
- 手工增加 wood：至少使用中性林区密度。
- treeModel 编辑优先于生成树种。

### 6.6 海域与排水河网

<!-- optimization-gate:automatic-river-generation -->

自动河流门槛已依据[用户观察](evidence/automatic-river-generation/user-observation.md)和[结构化证据](evidence/automatic-river-generation/2026-09-04.json)通过，并由[粗网格排水决策](decisions/coarse-drainage-water-network.md)确定算法取舍。导航或编辑河网的玩法需求也归该门槛，不属于渲染后端迁移条件；当前实现不因此承诺可导航或可编辑的河网图。触发条件与状态由[优化登记](optimization-gates.md)维护。

当前水体职责如下：

- ocean 是不经地形扭曲的低频连续场，只负责海陆掩码；有界世界仍叠加中心抬升和边缘衰减，保证中央陆地与外围海域。
- 河道在间距为 8 个世界六边格的粗轴向网格上工作，不在 2048² 个格子上做全图流向计算；节点在采样和栅格化前叠加连续扭曲，默认频率 0.08、幅度上限 3.75 格，避免主世界暴露规则的六方向折线。幅度不再被内部静默截为 3.5；小型环绕世界若缩小排水步长，扭曲幅度同比缩小，保持小于实际步长一半的约束。
- 稳定河源只从中高海拔的非水、非山雪格产生；每个固定源区提出 4 个候选，不随请求顺序变化。
- 每一步只选择排水势能严格下降的六邻居。势能以 ocean 为主，并由 elevation、valley、moisture 和极小确定性抖动修正。
- 只保留达到宏观海域且满足最短长度的路径。种子河源作为长度基准锚点，沿真实入流图寻找累计渲染中心距离最长的上游支路，替换原来“最高相邻势能 + 至多三步”的贪心延伸。源头到海总节点数仍不超过 72；普通陆地不必满足独立河源的气候/海拔门槛，但山雪、缺失域和分水岭会终止延伸。候选的唯一下游必须指向当前节点，逆流势能严格递增，不会环绕成圈。按规范坐标与剩余节点预算缓存最优支路，缓存只存活于单次范围计算。失败的内陆路线仍不落盘，不生成孤立湖点。
- 下游选择只依赖坐标连续场，因此两条路径到达同一粗格后自然共享后续路径；重叠河源数作为汇流量。半径在默认支流 1.75 与主河 4 之间按 smoothstep(1, 24, flow) 连续过渡，不再突然跳档。
- 沿渲染世界空间中心线反向累加至入海终点的距离，在最后 24 格的邻格间距内以 smoothstep 渐宽，到海时为当前流量半径的 1.6 倍；远离河口的河宽不受影响，不能用欧氏临海距离把邻近海湾但尚未入海的上游也扩大。
- 扭曲后的粗网格边在与渲染器一致的偶列偏移坐标中形成二次 Bézier 中心线：相邻边的中点为端点，粗节点为控制点而非必须经过的硬拐点；真正的源头与入海终点保持原位置。所有入流曲线在共同下游边的中点以相同切线方向接合，不需要选取某一条“主支流”。曲线在连续渲染平面以不超过 1/16 邻格间距的插值误差细分（每段最多 32 个线段），采样点不先取整到格心。
- 栅格化沿曲线弧长线性变宽的扫掠圆盘包络；每个候选格只对该曲线包络判定一次。半径可以是小数，但所有输出坐标都是完整六边格；临界格由唯一几何规则决定水陆，不随机选择。自定义亚格宽度额外保留沿曲线的连通数字中心线。程序化河道仍使用 sea/coastal 类型，每格保持完整单一地形，并继续复用现有水面、岸线、通行与打包语义，不扩展 PackedWorldChunk。
- 程序化随机湖泊已经删除；手工 `lake` 和 `river` modifier 的编辑、渲染与持久化能力继续保留。

无限和有界世界以 128×128 页建立有上限的 LRU 河网位掩码；每页只枚举最大路径长度内可能流入该页的河源，搜索边距包括扭曲与最大河口半径，所以相邻页和不同请求范围结果一致。一次范围枚举会缓存排水节点及其唯一下游边，支流汇合后复用后缀采样；按规范化节点聚合流量、到海距离和宽度，每条共享下游边只栅格化一次。环绕世界一次建立规范化全域位掩码，河源只枚举一次，避免跨边副本重复追踪。

概览放大时按像素中心对应的唯一地格采样基础地形。同一地格覆盖的后续像素复用颜色，
重复地格行复用一行 RGBA 缓冲（最多 1 KiB），不保留整幅图的采样对象。
河网覆盖仍独立投影到每个像素，混合放大/缩小、页边界和原有颜色量化保持一致。
例如 32×32 地格放大到 128×128 像素，基础地形采样为 1,024 次；排水采样另计。

河网使用专用的地形分类/地貌采样，不再为排水节点和一次性河道覆盖保留完整的地表窗口。
水体位掩码在构建时排除基础海域；重复访问直接枚举非零位，无需再次逐河格采样或逐格扫描空白。
普通概览页为 512×512，大跨度且两轴都足够宽时采用 2048×2048 页；页 key 包含尺寸。
概览 LRU 最多保留 16 页（最大合计 8 MiB），地格页另有 16 个 128×128 页。
大范围请求逐页完成，狭长或小范围直采也拆成每轴最多 2048 格的批次；不会因为请求页数
超过缓存容量就改为一次构建整个范围的临时图。去重使用批次内位数组，每个最大批次 512 KiB。
`generatedRiverTileBatches()` 在批次之间让出控制，`visitGeneratedRiverTiles()` 同步消费同一
批次序列。河源搜索仍包含完整的最大上游影响边界，分批不改变河流汇合、宽度和地格结果；
概览任务的调度与取消不改变地表生成语义；当前版本统一见[版本合同](#104-当前版本与基线)。

Worker 通过异步概览入口消费同一批次，基础地形每 16 行提供一次调度边界，每累计约 8 ms
让出事件循环并检查取消。取消会结束生成迭代器并保留已完成的缓存页，不销毁 Worker；
池在收到取消确认后才复用槽位。单个河网批次的冷计算可能超过 8 ms，因此这是批次间的
合作调度预算，不是硬抢占时限。同步概览 API 仍同步完成相同像素。

### 6.7 水体作者参数

`DEFAULT_WORLD_WATER_STYLE` 使用作者确认的截图参数；公开的 `WORLD_WATER_STYLE_RANGES` 是演示面板与 API 校验的唯一区间来源。所有字段必填；默认参数只在未传入整份配置时使用，不为缺失字段兼容旧描述符。

| 参数 / 字段 | 下限 | 默认 | 上限 | 面板步进 |
|---|---:|---:|---:|---:|
| 海域噪声频率 `oceanScale` | 0.7 | 1.4 | 2.8 | 0.05 |
| 海域覆盖阈值 `oceanLevel` | 0.32 | 0.46 | 0.60 | 0.005 |
| 河源区域间距 `riverSourceCellSize` | 8 | 16 | 32 | 1 |
| 每区河源数量 `riverSourcesPerCell` | 1 | 4 | 8 | 1 |
| 河流长度（基准%）`riverLength` | 10 | 100 | 300 | 5 |
| 河道弯曲频率 `riverWarpScale` | 0.02 | 0.08 | 0.12 | 0.001 |
| 河道弯曲幅度 `riverWarpAmplitude` | 0 | 3.75 | 3.90 | 0.05 |
| 支流半径 `riverBaseRadius` | 0.5 | 1.75 | 2.75 | 0.05 |
| 主河半径 `riverHighFlowRadius` | 3 | 4 | 6 | 0.05 |
| 主河流量阈值 `riverHighFlowThreshold` | 2 | 24 | 48 | 1 |

- `oceanLevel` 是海域场的分类阈值，不保证最终水体面积恰好为 46%。海域基础频率为 open 0.0035 / toroidal 0.006，统一乘以 `oceanScale`；基础 profile 与默认作者 profile 必须相同，不能遗漏或重复缩放。
- `riverLength` 表示相对于种子河源锚点到海弧长的目标倍率。100% 为基准，50% 缩短下游后缀，200%/300% 沿真实入流图向更上游移动河源。范围 10–300，步进 5；分母不再是整张河网最远端到海距离，因此超过 100 确实能增加新河段。它不保证每条河都增长到目标倍率：分水岭、山雪、世界边界或节点上限会使具体流域提前饱和。百分比也不等于河道面积比例。
- 所有倍率先建立相同的完整上游支路、唯一曲线、到海弧长和流量半径，再把 `anchor.distanceToSea × riverLength / 100` 的目标预算赋给扩展河头。预算按拓扑序传向下游，汇合处取最大值，每条共享边仍只栅格化一次。截取点位于细分曲线内部，半径沿用原宽度曲线。因此同一世界调长只增加上游河段，不移除已有水格或改变下游河口。源头基准用完整曲线在锚点对应河段起点的海距度量，不在粗节点硬切。
- 倍率不改变 72 节点追踪上限或源区搜索半径。主河上限 6 对应最大河口半径 9.6，分页几何边距覆盖该上限。100% 以种子河源锚点到海的弧长为基准；身份严格拒绝其他长度语义，不保留旧字段兼容路径。
- 支流和主河的合法区间不交叠，避免用户单独拖动滑块产生支流不小于主河的无效组合。幅度上限 3.90 保留小于半个粗步长的结构约束；不能围绕 3.75 对称扩展到 7.5。
- 整数参数校验步进；小数参数只校验有限数和范围，面板步进不作为 API 浮点量化规则。调整和重置都重新生成世界，并把包括长度在内的完整配置用于 Worker、缓存、存档和导航身份。
- 面板输入在 dat.gui 完成步进取整后，按共享 `step` 的十进制小数位数规范化并写回控件绑定值，覆盖滑块、数字框拖动与键盘输入。该库先限制范围再乘步进，`78 × 0.05` 会得到 `3.9000000000000004`，导致显示 3.9 但提交越界；不能再次调用 `setValue()` 重复产生尾差。规范化只处理面板作者精度，不放宽生成器上限，不给 API 增加 epsilon、截断或量化，不改生成器/描述符版本。浏览器回归实际拖过所有小数参数的轨道两端，并检查手动输入的绑定值、显示值和已生成配置一致。

## 7. 世界拓扑与 512×512

三种拓扑共享风格，但边界条件不同：

### 7.1 无限世界

- 使用全局逻辑坐标。
- 没有隐式中心和边缘。
- 正负坐标规则相同。
- 所有计算必须有固定上界。

### 7.2 环绕世界

- 所有连续场必须以 width/height 为周期。
- 海域、河道、植被、地表高度和 Shader 相位都要跨四边与四角连续。
- width 继续满足六边格环绕约束。
- 512×512 是主要质量样本，但不是算法常量。

### 7.3 有界世界

- 保留边缘衰减，形成完整大陆。
- generateWorld() 必须与同域解析器的生成格子一致。
- 普通 StaticWorldSource 不猜种子，继续使用中性地表。
- 只有出现真实需求时，才设计带版本身份的有界流式世界源。

### 7.4 产品选择

| 需要 | 选择 |
|---|---|
| 512×512、四边无缝、支持流式加载 | ToroidalWorldSource |
| 有明确海洋边界或不可越界边缘 | 当前使用有界一次性生成；以后按真实需求增加有界流式世界源 |
| 没有世界边缘 | ProceduralWorldSource；512×512 只是观察窗口 |

有界世界不是无限世界的精确裁剪，环绕世界也不是把无限世界两边强行粘接。不能同时混用三种边界语义。

## 8. 区块与流式加载

### 8.1 保持不变

- WorldSource 仍是存储和输入输出边界。
- 源区块仍是生成、传输和驻留单位。
- 渲染块固定为 12×12。
- WorldStreamer 只表达镜头需求。
- ChunkResidencyCoordinator 继续管理租约。
- 一次 loadWorld() 仍拥有唯一世界源和生命周期。

### 8.2 必须保持的结果

同一描述符和坐标在以下变化下必须得到相同核心格子：

- 合法的源区块大小变化。
- 正序、逆序、随机和并发请求。
- 单工作线程与多工作线程。
- 缓存命中或未命中。
- 相邻区块是否已经驻留。
- 镜头位置变化。
- 卸载后重新加载。

一圈输出邻域继续满足最终渲染需要。生成器内部可以为计算邻域格子建立更大的短命窗口，但不能要求自定义世界源偷偷提供更多数据。

### 8.3 暂不扩充 PackedWorldChunk

v1 不立即增加 relief 或 biome 附加字段，原因：

- 当前结果可由描述符和解析器重建。
- 先统一规则，避免过早固定量化格式。
- 保持现有 16 位格子数据和缓存格式。

只有出现以下证据才升级区块格式：

- 主线程重复采样成为明确性能热点。
- 解析器开始依赖不能按坐标重建的区域结果。
- 远程世界源需要传递权威高度。
- 导航或存档必须保存量化地表高度。

## 9. 渲染与贴地

### 9.1 TerrainMesh

TerrainMesh 不再拥有山地阈值和高度公式，只负责：

- 读取生效格子与六邻居高度。
- 构造共享顶角。
- 生成渲染属性。
- 管理 LOD、材质、迷雾和资源生命周期。

运行时将原图集去边距后拆成独立纹理层，启用逐层 mipmap、三线性缩小过滤和可配置的各向异性请求。
`HexMapOptions.terrainTextureAnisotropy` 是仅初始化生效的正安全整数配置，默认 8；统一验证后透传 TerrainMesh 和纹理加载器，不设置重复默认或私有 fallback。硬件支持上限仍由 Three.js 原生处理。
full/fast 土地材质使用 GLSL 3，在材质分支前计算未折叠世界 UV 的梯度，以 textureGrad 配合采样器镜像重复，避免缩小混叠与跨地形串色。
共享 `terrainMaterial.ts` 每种材质使用两个相位偏移采样，宏观连续场平滑选择相邻偏移；相邻段端点采样一致，降低周期纹理辨识度。
陡坡额外混合 mountain 岩石材质，已是 mountain 的片元不重复叠加。坡度从顶点世界地表斜率传入，不随镜头旋转；气候色调和雪线随后应用。
CPU 相位与 full/fast 材质直接使用配置的真实纹理周期，包括小于 1 世界单位的周期；禁止隐式最小尺度钳制。初始化和实时配置更新集中验证实际周期可表示为正有限 GPU Float32，溢出或下溢直接拒绝。fast 宏观材质波动同样按真实 hexSize 缩放；跨块相位仅相差完整镜像周期，不改变未折叠 UV 的梯度。
可选的 GroundProjection 在独立俯视通道绘制地面印记，由土地/水面实际片元接收；不改变地形几何、surface authority 或生成输入。
纹理加载、资源预算和投影所有权见[渲染合同](render-streaming.md)。
图集必须完整提供所有 Land 类型的有效整数单元映射，缺失或越界直接拒绝，禁止默认第 0 层。
图集请求绑定世界会话 AbortSignal；取消立即结束 readiness，晚到的解码结果只释放、不上传。
地表材质与水面统一使用 GLSL 3 和块内坐标：CPU 保留 Double 全局原点，将噪声拆成整数格编号与小数偏移，将纹理、波浪和风拆成小范围相位后再上传。
噪声格编号采用共享的 32 位整数 hash，替换原视觉 sine hash；浮动原点不改变纹理图案，权威生成、CPU surface 和 ±1.5% 微位移上限不变。
投影源对象相对投影中心写入坐标；接收块与投影中心的差值在 CPU 计算，避免远坐标 Float32 量化。
环绕地图仍由实体渲染块副本负责放置，已删除 shader 的 worldPeriod 重复分支及逐草实例的冗余归属格中心缓冲。

每次渲染块构建使用自己的短命采样窗口。区块卸载、地形编辑或 WebGL 上下文恢复后，从当前 MapInfo 和解析器重建。

### 9.2 顶点属性限制

当前 Terrain 已使用 15 个顶点属性位置，不能随意增加字段。

style 使用 vec4，w 分量保存生效 relief；岸线、水体、湖泊和地图外空位使用负值哨兵，CPU 与 Shader 据此得到相同的共享顶角归零规则。这个改动没有增加属性位置。

当前属性打包状态：

- style 扩为 vec4 已完成。
- fogState 已扩为 vec4：x 存迷雾，y/z/w 存 dry/cold/alpine，temperate 由总和推导。
- landform attribute 继续保存四种生成器调试字段；顶点阶段把最终有效 elevation 写入 vLandform.x，并保留 y/z/w 的 ridge/valley/roughness，已删除重复的 vElevation varying。
- full/fast 材质都使用同一组连续 biome 权重做色调、冷暖和高山去饱和混合，biome 权重本身不增加地形采样；每种材质在同一个纹理层做两次偏移读取，full 路径在边界另外读取参与混合的邻居材质。

硬门槛：

- 不超过最低支持上下文的 MAX_VERTEX_ATTRIBS 和 varying 上限。
- full 与 fast 使用相同属性布局。
- 新增属性字节进入几何资源预算。
- 不先占满能力再假设用户 GPU 更强。

### 9.3 地表高度查询

包内 WorldSurfaceAnchor / WorldSurfaceView 提供连续宏观地表，下列对象共用这一贴地合同：

以下对象统一使用 WorldSurfaceAnchor：

- 城市模型和标签。
- Unit 移动。
- 选择器和悬停标记。
- 路线。
- 草和树。
- 注册的自定义渲染层。
- 按格子聚焦的镜头目标。

草和树按每个实例的 XZ 查询高度，不能整格共用中心 Y。

草木候选点在世界坐标的抖动采样网格中生成，六边形只承担所属格、迷雾与编辑归属，
不再缩小草的生成区域。草覆盖到六条格边，仍按河流、海岸、湖岸与城市规则避让。
静态地图与 Worker 共用布局函数；三档 LOD 按稳定优先级抽稀，保留已有实例的位置和尺寸。
密度参数表示单位六边形面积内的候选密度，单格数量允许自然变化。

treeScale 默认 1.6，演示面板提供“树木大小”控制。树的采样间距至少为
size × treeScale × 0.5，单轴抖动限于间距的 22%，因此树干间至少保留间距的 56%。
该规则跨格子、树种和源区块生效；环形地图采用整数个周期采样单元保证接缝连续。
最终数量还受生效植被密度和水岸避让约束。渲染边界按模型实际包围盒、最大随机缩放
和旋转后的树冠半径扩展，放大模型不会因旧的固定边界被提前剔除。

Unit 沿路径移动时按当前位置调用 getWorldHeight()，但朝向只使用 XZ 平面的偏航角，不随小坡频繁俯仰。

路线在地表上增加小偏移。悬停和选择标记改为贴地窄环，每条边分八段，内外两圈
顶点分别查询地表高度，再增加 height × 0.015 + size × 0.008 的偏移，覆盖微位移并保留遮挡。
两种标记共享最多 128 格的 CPU 投影 LRU；表面对象或 revision 改变时失效，卸载世界时清空。
GPU 几何由两个标记独立持有，淘汰缓存不会销毁当前显示。重复世界和浮动原点只调整平移。
鼠标射线在地表高度区间内逐格遍历，与每格六片三角形组成的地表扇面求交，山坡拾取不再投到 Y=0；
逻辑拾取与贴地查询均使用 CPU 宏观表面，不包含 Shader 的微位移。

HexMap.add(Object3D) 无法知道对象属于哪个格子，因此不承诺自动贴地。调用者必须主动查询高度，或使用 WorldRenderLayer。

### 9.4 植被工作线程

工作线程只生成：

- 所属格子。
- 局部 XZ。
- 缩放和朝向。
- 树种与密度布局。

最终 Y 在主线程挂载时由 WorldSurfaceView 批量计算。这样 mountainHeight 可以实时修改，也不会把旧显示尺度写进工作线程结果或缓存。

### 9.5 动态高度刷新

WorldRenderLayerHost 增加可选 surface?: WorldSurfaceAnchor。所有内置 host 都提供它；旧自定义层可以回退到 Y=0。

使用 surface 的自定义层必须实现可选回调：

~~~ts
surfaceChanged?(host: WorldRenderLayerHost): void | Promise<void>;
~~~

普通消费者通过 surfacechange 事件取得 { revision, surface }。

更新顺序：

1. 增加地表显示版本。
2. 更新 WorldSurfaceView 和 Terrain。
3. 重定位轻量对象。
4. 暂时隐藏仍使用旧版本的植被和注册层对象。
5. 异步重建完成并确认世界生命周期、地表版本仍有效。
6. 显示新对象并发送 surfacechange。

旧异步结果只能释放，不能覆盖新地表。

### 9.6 裁剪与迷雾

- Terrain 的水面、河床和山体 Y 边界从水深、波幅与地表上限推导；山体 Shader 细节上界为 1.015 倍。
- 草和树的 Y 边界已经由统一地表上下限与对象余量推导；自定义层继续通过自己的 WorldChunkMetadata 声明边界。
- 地形、水、草、树和自定义层的 Y 边界必须由统一地表上限与对象余量推导。
- 不再依赖固定的 -size × 2 到 size × 3 经验范围。
- 迷雾可以隐藏地形轮廓，但 WorldSurfaceAnchor 始终返回真实高度。
- 不能把未探索格子的高度改为 0，否则对象恢复显示时会跳动。

## 10. 编辑、版本和恢复

### 10.1 编辑刷新

- 仅 unit 字段变化：不重建地表。
- city 变化：刷新城市与植被抑制。
- terrain、modifiers、treeModel 和 river 变化：刷新目标格子与六邻居。
- 改变通行性或移动消耗：使对应导航摘要失效。
- mountainHeight 等显示尺度变化：只增加渲染地表版本，不改变导航版本。
- 存档恢复期间继续拒绝编辑、清空和新快照。

### 10.2 版本职责

| 变化 | 必须更新 |
|---|---|
| 格子分类、修饰、树种或 CPU 地表语义 | WORLD_GENERATOR_VERSION 与对应基准校验和 |
| 区块字段、邻域或传输布局 | WORLD_CHUNK_FORMAT_VERSION |
| 工作线程请求、响应或转移对象 | WORLD_WORKER_PROTOCOL_VERSION |
| WorldDescriptor 字段或含义 | WORLD_DESCRIPTOR_FORMAT_VERSION |
| 只有 Shader 颜色和光照变化 | 不升级生成器；执行视觉回归 |

生成器版本唯一对应一个冻结基础配置；每个世界的规范化水体参数作为独立身份字段保存，不再增加一套与生成器总是一起增长的风格版本。

### 10.3 唯一世界指纹

继续使用现有规范序列化：

~~~ts
const fingerprint = serializeWorldDescriptor(descriptor);
~~~

该字符串是唯一身份来源：

- 缓存键使用 [fingerprint, chunkX, chunkY]。
- 默认 worldId 使用 fingerprint 或其稳定哈希。
- 导航 terrainRevision 使用 fingerprint 或其稳定哈希。
- 存档继续保存并严格比较完整描述符。
- 水体参数变化会得到新的指纹，因此 Worker 解析器、区块缓存、增量存档和导航版本不会与旧参数混用。

不能在不同调用点分别拼接字段。

`createWorldDescriptor()` 返回运行时冻结的描述符，嵌套水体参数也冻结；调用方不能
在 fingerprint 已计算后修改 seed、尺寸或水体配置。有界世界生成、环绕 source、
chunk 生成和 descriptor 校验共用尺寸范围 8–512，环绕宽度必须为偶数；超界或非整数
参数在分配/采样前失败。底层连续 `LandformSampler` 仅接受声明的三种 topology，
有限域的尺寸必须为不小于 2 的安全整数，其 domain 同样冻结。

指纹标识的是完整生成配置，不承诺不同 seed 的地图内容绝不重复。当前噪声种子
仍压缩为 32 位，内容可能碰撞；多个同配置游戏存档应使用独立 `worldId`。提高种子
熵会改变生成结果，需要新的生成器版本和完整风格验收，不能作为无版本的性能改动。

工作线程请求和响应必须包含并校验生成器版本与区块身份。校验完成前不能写缓存或安装到稀疏地图。

### 10.4 当前版本与基线

| 身份 | 当前值 | 权威定义 |
|---|---:|---|
| 生成器 | 22 | [WorldGeneratorVersion](../src/world/WorldGeneratorVersion.ts) |
| 描述符 | 5 | [WorldDescriptor](../src/world/WorldDescriptor.ts) |
| Worker 协议 | 8 | [WorldDescriptor](../src/world/WorldDescriptor.ts) |
| 紧凑区块 | 1 | [interfaces](../src/interfaces.ts) |

一次性生成、区块生成和 Worker 使用同一解析器与完整描述符身份。水体参数包含河源锚点相对倍率 `riverLength`；概览协议支持分批取消与确认。旧版本、缺失字段和不同语义的身份明确拒绝，不推断默认值或自动迁移。自定义固定 worldId 的调用者必须显式处理旧地形编辑后才能使用新生成身份。

当前格子、地表、河长集合和概览像素基线由[地表测试](../tests/world/worldSurfaceResolver.test.ts)、[河网测试](../tests/world/worldWaterSampler.test.ts)与[概览测试](../tests/world/worldOverview.test.ts)维护；修改语义时按 10.2 同步版本和独立预期。历史数值与阈值调整原因见[测量证据](evidence/world-style-generation.md)，不在当前合同维护多代校验和。

## 11. 性能边界

- 每个世界生命周期只创建一次解析器。
- 每个区块构建只创建一个有界采样窗口。
- 禁止按世界坐标建立无界 Map 缓存。
- 无限/有界河网页固定为 128×128，LRU 上限 16 页；环绕世界只保存一个规范化全域位掩码。
- 小地图先按目标范围枚举粗网格路径，再栅格化到像素覆盖；禁止对 2048² 世界逐格解析或从每个像素重复追踪河道。
- 同一范围内的河源必须复用排水节点与下游选择缓存；缓存随单次范围生成释放，不进入常驻状态。
- 只有实际分析证明对象分配成为热点时，才增加 sampleInto() 等内部快速路径。
- 常驻属性、模型和以后可能增加的附加字段进入资源账户。
- 临时采样窗口不计作常驻资源，但必须按区块尺寸有明确上限，并在构建后释放。
- 调试模式不能每帧重采样全部驻留世界。
- 自适应画质只能减少实例和细节，不能改变权威格子、气候和植被语义。
- 重点测量首次可见区块、稳定区块生成、植被准备、挂载时间和 GPU 属性字节。
- 额外记录 2048×2048 世界到 256×256 小地图的生成耗时；[河道跟进证据](evidence/automatic-river-generation/natural-course-followup.md)保留历史观测，不作为跨机器绝对门槛。

## 12. 测试与视觉验收

### 12.1 确定性测试

必须覆盖：

1. 同种子、拓扑和坐标结果一致；不同种子有差异。
2. 一次性生成与环绕流式生成的核心格子一致。
3. 多种合法源区块大小结果一致。
4. 正序、逆序、随机和并发请求校验和一致。
5. 单工作线程与多工作线程一致。
6. 相邻区块核心和邻域双向一致。
7. 环绕世界四边和四角的字段、格子和 relief 一致。
8. 无限世界负坐标与安全整数边界正确。
9. 风格配置拒绝 NaN、Infinity、负尺度和乱序阈值。
10. 修改风格配置或生成算法时必须同步升级生成器版本。
11. mountain、hill、plain、水体以及手工 lake/river 编辑后的高度范围正确，清除编辑可恢复。
12. 静态世界源使用中性高度，不猜种子。
13. 工作线程校验生成器和区块身份。
14. 固定坐标集具有格子校验和与地表校验和。
15. full/fast Shader 在最低属性能力下都能链接。
16. 河道范围枚举与分页格子解析完全一致；不同范围的重叠区域一致，环绕平移保持同一身份。
17. 每个生成河道连通分量必须到达宏观水体或观察窗口边缘；2048 范围的低分辨率海域组件数与孤立点受门禁约束。

地表校验和至少覆盖 relief、biome 权重、植被密度和 ocean 场的规范量化结果。

### 12.2 几何与流式测试

固定一条跨越以下边界的山系：

- 两个源区块。
- 多个 12×12 渲染块。
- near、middle、far LOD。
- 环绕边界。
- 卸载和重载。
- 无限世界浮动原点重定位。

直接比较 CPU 共享顶角和边缘属性，不能只依靠截图。

浏览器验收还要覆盖：

- 地形稀疏编辑。
- mountainHeight 动态修改。
- 城市、单位、路线、草木和标记贴地。
- 迷雾三种状态切换。
- WebGL 上下文丢失与恢复。
- Y 边界擦边裁剪。
- 属性、纹理和资源计数不增长。

### 12.3 世界样本图库

固定语料由[worldStyleGallery.ts](../tests/helpers/worldStyleGallery.ts)维护，覆盖有界、环绕、无限、极端水陆与最小尺寸样本。每个样本具有远景、中景、近景和调试视图。截图与逐样本 JSON 是本地或 CI 产物，不作为游戏资产或当前合同提交。

记录以下指标：

- 陆地、水体、山地和气候比例。
- 山地连通块数量、孤立山格比例和长度分布。
- 森林邻接率和斑块大小。
- 水体连通块、主水体占比和孤立水格比例。
- 海岸线长度。
- 拓扑接缝错误数。
- 首区块、稳定区块和植被准备耗时。

指标先建立基线，再设宽松范围，不能为了迎合所谓“真实比例”反向扭曲世界。

连通性统计必须使用六邻接并尊重拓扑：环绕世界跨边合并，有界世界不跨边，无限世界标记触及观察窗口边界的截断组件。

固定语料包含 4 个有界世界、6 个 512×512 环绕世界、4 个无限世界种子的正负坐标窗口、2 个水陆极端样本和 2 个最小尺寸样本。`npm run review:world-style:metrics` 执行拓扑与区域统计门禁；浏览器图库只在明确需要人工视觉复核时单独运行，截图和逐样本 JSON 不提交到仓库。

覆盖、连通性与孤立点门槛统一由[统计验收](../tests/world/worldStyleGallery.review.ts)维护。改变门槛必须说明生成语义变化及样本证据；既有森林与山地门槛的调整原因见[历史测量](evidence/world-style-generation.md)。

极端样本覆盖近全水和近全陆结果。无限世界局部窗口允许落在大陆腹地或外海，不再对每个 144×144 窗口强制平均水体比例；另用 2048 范围的粗采样门禁约束宏观水体碎片化。性能 JSON 同时记录首次可见、完全稳定、Worker 地形/植被任务、GPU/CPU 帧耗时和资源计数；不同 GPU 不设截图像素和绝对耗时硬阈值。

按 [testing.md](./testing.md) 执行：

- 构建。
- 浏览器端到端测试。

## 13. 设计取舍与剩余风险

### 13.1 整体方案

对当前目标，最合适的是：

~~~text
无状态生成字段
+ 区块内短命采样窗口
+ 合并编辑的运行时地表视图
~~~

它保留现有流式加载和六边格表现，也避免全世界预计算。

当前河网使用可重算的粗网格排水页，不需要全局地图集。只有玩法要求完整流域蓄水、河流编辑传播或权威远程水文时，才有理由引入持久化区域图。

### 13.2 剩余风险

| 风险 | 处理方式 |
|---|---|
| 岸线归零使临海山体像被切平 | 单独复核临海山地；必要时改为对称岸线衰减 |
| 512 世界好看但小世界重复明显 | 测最小尺寸和多个中间尺寸 |
| 低频海域使小型局部窗口全陆或全海 | 局部窗口不强制平均比例；用 2048 宏观样本与极端种子分别验收 |
| 粗网格河道出现分页断裂或缩放闪烁 | 对范围重叠、分页解析和环绕周期做逐格一致性测试 |
| 小地图重新出现逐格水文热点 | 概览只调用一次河道枚举；持续记录 2048→256 专项耗时 |
| 普通地形起伏影响六边格识别 | 严格限制平地和丘陵高度，保留清晰网格 |
| 静态 MapInfo 无法复现程序化精确高度 | 保持中性回退；有真实需求再加显式能力 |
| 主线程重算高度成为热点 | 先使用短命窗口，性能数据证明后再传附加字段 |
| 非 Chromium 平台出现浮点边界差异 | 扩大平台支持时，在新生成器中统一量化 |
| 自定义层使用高度但不处理 surfaceChanged | 文档和示例明确要求；以后主版本再考虑强制能力 |

## 14. 验收标准

世界生成语义变更必须保持以下验收条件：

1. 一次性生成和流式生成共享唯一解析器。
2. 风格配置与生成器版本一一对应。
3. 世界描述符、缓存、存档、默认 worldId 和导航版本使用同一指纹来源。
4. 多个种子的远、中、近景没有明显碎山、椒盐森林、噪声水点和尺度冲突。
5. 平地、谷地、丘陵、山麓和山体形成连续且克制的层次。
6. 气候、树种、植被密度和地形材质使用同一套空间语言。
7. 源区块、渲染块、LOD、环绕边界、卸载重载和浮动原点没有接缝。
8. 城市、单位、路线、标记、草木和注册层正确贴地。
9. 地形块不会因 Y 边界错误而提前裁剪。
10. 格子与地表校验和、版本变化、缓存隔离和旧存档拒绝规则明确。
11. 单测、类型检查、构建、端到端测试、适用 soak、性能基准和样本图库复核全部通过。
12. 没有为假设需求引入全局地图集、通用特征系统、连续地形重构或物理模拟。

当前验收按[测试策略](testing.md#change-based-local-validation)选择检查。生成语义改动必须显式升级生成器版本，同步独立校验和、缓存/存档身份和指标基线；历史通过记录不替代本次结果。
