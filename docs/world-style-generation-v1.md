# 世界风格生成 v1 设计

状态：世界风格 v1 阶段 0–7 已完成，generator v6 保留为历史冻结基线；2026-09-03 的无限世界曲线采样水网已完成并升级到 generator v8。

本文记录已冻结的世界生成与地形表现方案。目标不是模拟真实地球，而是在保留六边格、区块流式加载、工作线程和现有资源预算的前提下，生成风格统一、自然、耐看的世界。

基础设施约束见 [foundation-v1-freeze.md](./foundation-v1-freeze.md)，测试规则见 [testing.md](./testing.md)。

## 1. 结论

采用三层结构：

~~~text
世界描述符 + 当前生成器版本
              │
              ▼
      世界地表解析器
 WorldSurfaceResolver
              │
       ┌──────┴──────┐
       ▼             ▼
 一次性生成       区块工作线程
 generateWorld    generateWorldChunk
       │             │
       └──────┬──────┘
              ▼
       MapInfo / PackedWorldChunk
              │
              ▼
       生效地表视图
      WorldSurfaceView
  生成基础 + 稀疏编辑 + 显示尺度
              │
              ▼
 地形、城市、单位、植被、标记、自定义层
~~~

核心决定：

- 保留逐格六边形地形，不改成连续地形块或 clipmap。
- 保留 WorldSource、源区块、12×12 渲染块、LOD、生命周期和资源预算。
- 生成规则只保留一份，由 WorldSurfaceResolver 同时服务一次性生成和工作线程。
- 渲染器始终读取“生效地形”，不能用种子生成结果覆盖玩家编辑。
- 区块构建时使用短命的 WorldSurfaceWindow 去重采样，不建立全世界缓存；同步区块 API 只保留最近一个完全匹配种子和拓扑的解析器，以复用有界水网掩码。
- v1 只有一种内部风格配置，由 WORLD_GENERATOR_VERSION 锁定，不增加多余的风格版本字段。
- 512×512 是主要有限世界样本，但算法不能写死 512。
- 河流、完整水文和全局地形图不是 v1 的前置条件。

## 2. 目标与非目标

### 2.1 目标

1. 多个种子都能产生连贯的大陆、山系、平原、森林和湖区。
2. 山体内部连续，边缘有山麓，不出现大量单格尖峰。
3. 森林和湖泊形成区域，不呈现椒盐状随机点。
4. 相同描述符和坐标的结果不受区块大小、请求顺序、工作线程数量和缓存命中影响。
5. 源区块、渲染块、LOD、环绕边界、卸载重载和浮动原点没有可见接缝。
6. 城市、单位、路线、草木和标记能正确贴合地表。
7. 六边格边界、选择反馈和玩法可读性仍然清楚。
8. 新增成本继续受现有工作队列和资源预算约束。

### 2.2 非目标

- 不模拟板块运动、真实侵蚀和全球水循环。
- 不把地形渲染改成与六边格无关的连续网格。
- 不重写流式加载、区块驻留、LOD 调度和渲染层生命周期。
- 不开放几十个公共生成参数。
- 不保证新生成器与旧种子生成相同世界。
- 不提前建设通用地形特征系统、全局地图集或 AssetRegistry。
- 不以噪声复杂度和单测数量衡量视觉质量。

## 3. 当前实现的主要问题

现有基础可继续使用：

- 设计起点的 WORLD_GENERATOR_VERSION 为 3；阶段 3 升到 4，阶段 5 升到 5，雪线语义修订升到当前的 6。
- LandformSampler 已提供 elevation、continentalness、ridge、valley、roughness、moisture 和 temperature。
- 无限世界使用全局坐标；环绕世界使用周期噪声；有界世界有边缘衰减。
- PackedWorldChunk 使用 16 位格子数据，并带一圈邻域。
- TerrainMesh 已使用六邻居高度构造共享山体顶角。
- Shader 的细节相位来自逻辑世界坐标，不受区块顺序和浮动原点影响。

需要解决的问题：

1. generateWorld.ts 与 generateWorldChunk.ts 重复实现地形分类、湖泊、丘陵、森林和树种规则。
2. 生成器与渲染器只共享原始地貌场，没有唯一的最终地表规则。
3. 普通陆地、丘陵和谷地仍缺少统一的连续高度。
4. 森林和湖泊仍带有较强的逐格随机感。
5. 静态 MapInfo 没有种子，只能使用中性山体高度。
6. 现有测试只证明数据邻域一致，没有直接证明最终几何跨区块和 LOD 无缝。
7. 当前 Shader 会用较宽的系数缩放整座山体，这已经不是“小细节”，CPU 无法据此准确贴地。
8. Terrain 当前使用 15 个顶点属性位置，新增地貌字段容易超过部分 GPU 的能力。
9. 地形块的 Y 方向裁剪边界是经验值，扩大起伏后可能提前消失。
10. 缓存键、默认 worldId 和导航 terrainRevision 分别拼接身份字段，容易出现漏项。

## 4. 核心结构

### 4.1 生成地表

LandformSampler 只负责连续基础场。

WorldSurfaceResolver 负责把基础场解释成地形、地表高度、气候、植被和静水倾向：

~~~ts
interface WorldSurfaceResolver {
    readonly seed: string;
    readonly domain: LandformDomain;
    readonly profile: WorldStyleProfile;

    sampleGenerated(x: number, y: number): Readonly<WorldSurfaceSample>;
    resolveGeneratedTile(x: number, y: number): Readonly<TileInfo>;
    createWindow(): WorldSurfaceResolverWindow;
}
~~~

sampleGenerated() 只处理单点连续结果。resolveGeneratedTile() 可以读取固定的一圈六邻域，用于海岸和最终格子修饰。

这两个接口首版保持包内使用，不直接成为公共 API。

### 4.2 地表样本

~~~ts
type WorldBiome =
    | "ocean"
    | "coast"
    | "temperate"
    | "dry"
    | "cold"
    | "alpine";

interface WorldBiomeWeights {
    readonly temperate: number;
    readonly dry: number;
    readonly cold: number;
    readonly alpine: number;
}

interface WorldSurfaceSample {
    readonly baseTerrain: Land;
    readonly relief: number;
    readonly biome: WorldBiome;
    readonly biomeWeights: WorldBiomeWeights;
    readonly vegetationDensity: number;
    readonly vegetationKind?: "palm" | "pinia" | "oak";
    readonly lakePotential: number;
    readonly landform: Readonly<LandformSample>;
}
~~~

说明：

- relief 是归一化的生成高度，不是最终世界 Y。
- landform 保留生成器 v3 的原始连续场，只供渲染调试和后续风格阶段复用。
- biome 是主标签，主要用于统计和树种选择。
- biomeWeights 用于连续材质混合，不能直接按 biome 画硬边界。
- vegetationDensity 和 lakePotential 都是连续值，不是最终布尔结果。

### 4.3 生效地表

运行时权威结果仍然是：

~~~text
生成基础格子 + WorldTileOverride = 生效格子
~~~

WorldSurfaceView 负责把当前 MapInfo、可选解析器和显示尺度合并起来：

~~~ts
interface WorldSurfaceAnchor {
    readonly revision: number;
    readonly minimumHeight: number;
    readonly maximumHeight: number;
    getTileCenterHeight(x: number, y: number): number;
    getWorldHeight(worldX: number, worldZ: number): number;
}

interface WorldSurfaceView extends WorldSurfaceAnchor {
    readonly map: MapInfo;
    readonly resolver?: WorldSurfaceResolver;
    readonly tileSize: number;
    readonly mountainHeight: number;
    getEffectiveRelief(x: number, y: number): number;
    createWindow(): WorldSurfaceWindow;
    setMountainHeight(value: number): boolean;
}
~~~

WorldSurfaceView 不拥有格子，也不写入存档。创建时必须校验地图拓扑、尺寸与解析器一致。

### 4.4 编辑后的高度规则

所有内置渲染层使用同一优先级：

1. 当前没有该格子：返回岸线基准高度。
2. 生效类型为 sea、coastal，或包含 lake：返回岸线基准高度。
3. 生效类型为 mountain：使用山体高度范围，并保证最小山高。
4. 包含 hill：使用丘陵高度范围，并保证最小丘陵高度。
5. 其他陆地：把生成高度限制在可通行地形范围，移除 mountain 后不会留下高台。
6. 静态地图没有解析器时：mountain 使用当前中性山高，其他类型保持平地。

type 或 modifiers 编辑只改变所属高度范围，不代表自由修改高度。真正的造山、挖坑和连续高度编辑以后必须使用单独版本化的 SurfaceDelta。

### 4.5 临时采样窗口

WorldSurfaceResolverWindow 和 WorldSurfaceWindow 都只用于一次生成块或渲染块构建：前者缓存生成样本与最终生成格子，后者缓存当前 MapInfo 合并稀疏编辑后的地表贡献、共享顶角和高度查询。

- 缓存核心格子、输出邻域和计算需要的有限外圈。
- 环绕世界先规范化坐标再作为缓存键。
- 同一坐标在一次构建中只采样一次。
- 构建完成立即释放。
- 结果必须与逐坐标调用解析器完全一致。

它不是新的存储格式，也不能变成无界的全世界缓存。

### 4.6 文件边界

| 文件 | 职责 |
|---|---|
| src/world/WorldGeneratorVersion.ts | 生成器版本与版本校验；原导出路径继续转出 |
| src/world/WorldStyleProfile.ts | 当前冻结风格配置和校验 |
| src/world/WorldSurfaceResolver.ts | 唯一生成规则 |
| src/world/WorldSurfaceView.ts | 生效格子、显示尺度和地表高度查询 |
| 解析器和视图内部辅助代码 | 短命 WorldSurfaceResolverWindow / WorldSurfaceWindow |

依赖方向固定为：

~~~text
风格配置 + LandformSampler
            ↓
 WorldSurfaceResolver
            ↓
   WorldSurfaceView
            ↓
         渲染层
~~~

src/world 不得导入 Three.js、HexMap 或 rendering 模块。

只把 WORLD_GENERATOR_VERSION 移到中性小文件，避免 generateWorldChunk → resolver → profile → generateWorldChunk 循环依赖。其他协议版本不做无关移动。

## 5. 风格配置与确定性

### 5.1 WorldStyleProfile

风格配置保持内部只读，按以下几组组织：

| 分组 | 内容 |
|---|---|
| fields | 扭曲、大陆、细节、山脊、谷地、粗糙度、湿度、温度、森林斑块和湖泊斑块尺度 |
| terrain | 海平面、山地/丘陵阈值、雪地/冻土/沙地阈值、气候过渡宽度 |
| relief | 平地幅度、谷地深度、丘陵/山麓/山体高度范围和山体曲线 |
| vegetation | 湿度阈值、最大密度、斑块强度、坡度惩罚、区域放置阈值/边缘抖动和树种温度范围 |
| lakes | 高度范围、湿度、谷地和斑块阈值 |
| rivers | 水页尺寸/容量、环绕参考尺寸，以及共享曲线场的密度、弯曲、折线比例、采样间距、支流和三个尺度族 |

规则：

- v1 只有一个默认配置。
- 配置不进入公共构造参数。
- 配置由 WORLD_GENERATOR_VERSION 唯一确定。
- 修改任何生成语义时，必须升级生成器版本并更新格子、地表和配置基准。
- field scale 必须真正传入 LandformSampler，不能再保留另一套隐藏常量。
- 只有出现第二个真实可选择的世界风格时，才给 WorldDescriptor 增加风格身份字段。

现有公开 createLandformSampler({ seed, domain }) 仍表示“当前生成器的默认地貌场”。内部解析器通过未导出的工厂传入冻结配置。

### 5.2 确定性规则

- 所有随机选择使用 randomAt(seed, x, y, salt)。
- 不使用共享随机游标。
- 湖泊、植被、树种等用途使用不同且稳定的 salt。
- 河流水源身份由 seed、水源格坐标和 slot 确定；下游由当前六边格坐标及冻结地表字段唯一决定，不使用共享随机游标。
- 格子坐标必须是安全整数。
- 区块大小、工作线程编号、请求时机、镜头和缓存状态不能参与生成。
- 环绕世界先规范化坐标。
- 所有阈值输入先规范化并限制范围。
- 如果将来需要定点量化，必须在新生成器版本中统一应用于一次性生成、工作线程和测试。

## 6. 地形生成规则

### 6.1 基础分类

1. elevation 低于海平面：sea。
2. elevation 足够高且 ridge 足够强，或 elevation 达到极高保底值：mountain。
3. 其余陆地先按 temperature 分 tundra；snow 还必须越过随低温下降、但不会落到岸线的气候雪线。
4. 高温低湿分 sand。
5. 剩余为 land。
6. coastal 不是基础类型；只有 sea 的六邻居存在陆地时才派生。

generateWorld()、generateToroidalWorldTile() 和 generateWorldChunk() 必须删除各自的规则副本，统一调用解析器。

### 6.2 地表起伏

视觉层次为：

~~~text
平地和谷地 < 丘陵 < 山麓 < 山体
~~~

约束：

- 海面和湖泊使用统一岸线基准。
- 平地只允许很小的起伏。
- 谷地可以轻微下沉，但不能越过河湖职责边界。
- 丘陵由连续 elevation 区间决定。
- 山体高度主要由 elevation 决定，ridge 用于塑造山脊，不直接等于高度。
- 普通可通行地形的起伏必须明显低于山体。
- relief 不改变通行性和移动消耗；玩法继续读取生效 TileInfo。

mountainHeight 仍是显示尺度，不进入生成身份。修改它时，地形、地表查询和贴地对象必须一起刷新。

### 6.3 共享顶角

一个世界顶角由三个格子共享：

~~~text
cornerHeight =
    combine((kindA, reliefA), (kindB, reliefB), (kindC, reliefC))
~~~

combine 必须满足：

- 对三个输入完全对称。
- 不依赖“当前正在绘制哪个格子”。
- 相邻渲染块和不同 LOD 得到相同边界高度。
- 格子中心高度由六个共享顶角推导，不能再次强制成格子自身峰值。

光照法线也使用共享顶角契约：每个世界顶角只由相交的三个格子中心 relief
解出同一坡度，相邻实例在公共边上插值相同的两个端点坡度。不得再从单格局部
三角扇向外有限差分，否则几何虽连续，光照仍会勾出六边形接缝。

getTileCenterHeight() 必须复用同一套六顶角结果。getWorldHeight() 在同一 CPU 三角扇上插值。

首版岸线规则：三个贡献格子中只要有 sea、coastal、lake 或地图外空位，该顶角就落到岸线基准。若样本图库证明临海山体被明显削平，再改成同样对称且有限范围的岸线衰减。

### 6.4 Shader 细节

CPU 三角扇拥有山体、山脊和峰高。Shader 只允许增加有界的小位移、法线和材质细节。

阶段 4 已把 mountainHeightAt() 从最高 1.57 倍的宽乘法收紧为宏观地表的 ±1.5% 微位移，并把每次高度计算的细节噪声从四次采样减为两次。默认 mountainHeight 为 80 世界单位，因此最高归一化 relief 处的 CPU/GPU 偏差不超过 1.5 世界单位；可放置城市、单位或植被的区域不会再出现肉眼明显的悬空。

细节还必须满足：

- 只使用逻辑世界坐标。
- 共享边界同一点得到相同结果。
- 不改变地形类型、通行性、气候和存档语义。
- full 与 fast 模式保持相同宏观表面和边界。

### 6.5 气候与植被

biome 由 elevation、temperature 和 moisture 的宽过渡带得到。

植被密度：

~~~text
气候适宜度
× 连续森林斑块场
× 坡度惩罚
~~~

generator v5 不再用独立坐标随机值直接与密度比较。最终 wood 由连续密度跨过固定区域阈值得到，坐标随机值只提供幅度受限的边缘抖动；零密度格不能因抖动进入森林。这样保留确定性和自然边缘，同时避免低适宜度区域出现椒盐状单格树。树种主要由气候决定。

编辑优先级：

- 生效格子没有 wood：密度为 0。
- 手工增加 wood：至少使用中性林区密度。
- treeModel 编辑优先于生成树种。

### 6.6 湖泊与河流

湖泊倾向由以下条件组合：

- 非水、非山地、非雪地。
- 低到中 elevation。
- 高 valley。
- 高 moisture。
- 低频湖泊斑块场。

v1 最终湖泊判断只依赖一圈邻域，不能依赖“当前恰好加载了哪些区块”。

generator v6 冻结时自动河流不是 v1 硬门槛，因此当时只保留手工 `river` modifier。产品复核先产生过 generator v7 的局部下降短路径实现，随后明确纠正为 generator v8：先查询无限曲线/折线场，再在六边形地形生成时采样成水体；不引入 WorldHydrologyRegion 或世界级排水图：

- `InfiniteWaterCurveField` 是宏观水网唯一来源。种子、曲线族、所有权格 X/Y 和 slot 确定一条无限可寻址路径；区域密度只改变候选频率，不由区块或镜头决定结果。
- 三个尺度族分别生成短、中、主干路径；每条主线独立选择方向、长度、累计转向以及曲线或控制折线，支流按父路径与 branch index 精确接入主线控制点。
- `WorldWaterSampler` 在地形格生成期间查询相交曲线，把世界坐标采样点转为 axial/cube 坐标，并用 hex line 填满相邻采样之间的所有六边格，所以最终水体仍是连续但不可导的六边格链。
- terrain 噪声不再决定河网宏观走向。land、sand、tundra 上的命中格生成 river；sea/coastal 形成开口，mountain/snow 中断，现有 lake 保持更高优先级。
- 每个生成河格携带真实采样步的六边连接掩码；空间上相邻但路径无连接的河格不会被误连。未提供掩码的手工河格继续按旧规则自动连接邻居。
- 无限/有界拓扑按 32x32 格水页查询，每个 resolver 最多保留 16 页；相交查询包含曲线最大可达范围，页边和区块边不会裁断河道。
- 环绕拓扑拥有一组按域尺寸缩放的规范曲线，栅格化后双轴取模形成周期掩码；偶数宽度保证横向平移不改变六边格奇偶布局。
- 浏览器曲线场景与生产生成器共享同一实现。场景里的广域海盆仍是视觉实验；生产大陆、海岸和湖泊规则没有随 v8 改动。

## 7. 世界拓扑与 512×512

三种拓扑共享风格，但边界条件不同：

### 7.1 无限世界

- 使用全局逻辑坐标。
- 没有隐式中心和边缘。
- 正负坐标规则相同。
- 所有计算必须有固定上界。

### 7.2 环绕世界

- 所有连续场必须以 width/height 为周期。
- 海岸、湖泊、植被、地表高度和 Shader 相位都要跨四边与四角连续。
- width 继续满足六边格环绕约束。
- 512×512 是主要质量样本，但不是算法常量。

### 7.3 有界世界

- 保留边缘衰减，形成完整大陆。
- generateWorld() 必须与同域解析器的生成格子一致。
- 普通 StaticWorldSource 不猜种子，继续使用中性地表。
- 只有出现真实需求时，才设计带版本身份的有界流式世界源。

### 7.4 产品选择

| 需要 | 选择 |
|---|---|
| 512×512、四边无缝、支持流式加载 | ToroidalWorldSource |
| 有明确海洋边界或不可越界边缘 | 当前使用有界一次性生成；以后按真实需求增加有界流式世界源 |
| 没有世界边缘 | ProceduralWorldSource；512×512 只是观察窗口 |

有界世界不是无限世界的精确裁剪，环绕世界也不是把无限世界两边强行粘接。不能同时混用三种边界语义。

## 8. 区块与流式加载

### 8.1 保持不变

- WorldSource 仍是存储和输入输出边界。
- 源区块仍是生成、传输和驻留单位。
- 渲染块固定为 12×12。
- WorldStreamer 只表达镜头需求。
- ChunkResidencyCoordinator 继续管理租约。
- 一次 loadWorld() 仍拥有唯一世界源和生命周期。

### 8.2 必须保持的结果

同一描述符和坐标在以下变化下必须得到相同核心格子：

- 合法的源区块大小变化。
- 正序、逆序、随机和并发请求。
- 单工作线程与多工作线程。
- 缓存命中或未命中。
- 相邻区块是否已经驻留。
- 镜头位置变化。
- 卸载后重新加载。

一圈输出邻域继续满足最终渲染需要。生成器内部可以为计算邻域格子建立更大的短命窗口，但不能要求自定义世界源偷偷提供更多数据。

### 8.3 PackedWorldChunk 边界

v1 不增加 relief 或 biome 附加字段，原因：

- 当前结果可由描述符和解析器重建。
- 先统一规则，避免过早固定量化格式。
- 保持 16 位格子数据；generator v8 继续使用原先空闲位保存 river、六边连接掩码及其显式标记，payload 大小不变。

只有出现以下证据才升级区块格式：

- 主线程重复采样成为明确性能热点。
- 解析器开始依赖不能按坐标重建的区域结果。
- 远程世界源需要传递权威高度。
- 导航或存档必须保存量化地表高度。

## 9. 渲染与贴地

### 9.1 TerrainMesh

TerrainMesh 不再拥有山地阈值和高度公式，只负责：

- 读取生效格子与六邻居高度。
- 构造共享顶角。
- 生成渲染属性。
- 管理 LOD、材质、迷雾和资源生命周期。

每次渲染块构建使用自己的短命采样窗口。区块卸载、地形编辑或 WebGL 上下文恢复后，从当前 MapInfo 和解析器重建。

### 9.2 顶点属性限制

当前 Terrain 已使用 15 个顶点属性位置，不能随意增加字段。

阶段 2 已把 style 从 vec3 扩为 vec4，w 分量保存生效 relief；岸线、水体、湖泊和地图外空位使用负值哨兵，CPU 与 Shader 据此得到相同的共享顶角归零规则。这个改动没有增加属性位置。

阶段 4 完成后的打包状态：

- style 扩为 vec4 已完成。
- fogState 已扩为 vec4：x 存迷雾，y/z/w 存 dry/cold/alpine，temperate 由总和推导。
- landform attribute 继续保存四种生成器调试字段；顶点阶段把最终有效 elevation 写入 vLandform.x，并保留 y/z/w 的 ridge/valley/roughness，已删除重复的 vElevation varying。
- full/fast 材质都使用同一组连续 biome 权重做色调、冷暖和高山去饱和混合，不增加 atlas 采样；每个 fragment 仍只有一次地形纹理读取。

硬门槛：

- 不超过最低支持上下文的 MAX_VERTEX_ATTRIBS 和 varying 上限。
- full 与 fast 使用相同属性布局。
- 新增属性字节进入几何资源预算。
- 不先占满能力再假设用户 GPU 更强。

### 9.3 地表高度查询

阶段 3 已把包内 WorldSurfaceAnchor / WorldSurfaceView 升级为 generator v4 的连续宏观地表，并完成以下对象的贴地迁移：

以下对象统一使用 WorldSurfaceAnchor：

- 城市模型和标签。
- Unit 移动。
- 选择器和悬停标记。
- 路线。
- 草和树。
- 注册的自定义渲染层。
- 按格子聚焦的镜头目标。

草和树按每个实例的 XZ 查询高度，不能整格共用中心 Y。

Unit 沿路径移动时按当前位置调用 getWorldHeight()，但朝向只使用 XZ 平面的偏航角，不随小坡频繁俯仰。

路线和标记在地表上增加统一小偏移，避免闪烁。

HexMap.add(Object3D) 无法知道对象属于哪个格子，因此不承诺自动贴地。调用者必须主动查询高度，或使用 WorldRenderLayer。

### 9.4 植被工作线程

工作线程只生成：

- 所属格子。
- 局部 XZ。
- 缩放和朝向。
- 树种与密度布局。

最终 Y 在主线程挂载时由 WorldSurfaceView 批量计算。这样 mountainHeight 可以实时修改，也不会把旧显示尺度写进工作线程结果或缓存。

### 9.5 动态高度刷新

WorldRenderLayerHost 增加可选 surface?: WorldSurfaceAnchor。所有内置 host 都提供它；旧自定义层可以回退到 Y=0。

使用 surface 的自定义层必须实现可选回调：

~~~ts
surfaceChanged?(host: WorldRenderLayerHost): void | Promise<void>;
~~~

普通消费者通过 surfacechange 事件取得 { revision, surface }。

更新顺序：

1. 增加地表显示版本。
2. 更新 WorldSurfaceView 和 Terrain。
3. 重定位轻量对象。
4. 暂时隐藏仍使用旧版本的植被和注册层对象。
5. 异步重建完成并确认世界生命周期、地表版本仍有效。
6. 显示新对象并发送 surfacechange。

旧异步结果只能释放，不能覆盖新地表。

### 9.6 裁剪与迷雾

- Terrain 的水面、河床和山体 Y 边界从水深、波幅与地表上限推导；阶段 4 将山体 Shader 细节上界同步收紧到 1.015 倍。
- 草和树的 Y 边界已经由统一地表上下限与对象余量推导；自定义层继续通过自己的 WorldChunkMetadata 声明边界。
- 地形、水、草、树和自定义层的 Y 边界必须由统一地表上限与对象余量推导。
- 不再依赖固定的 -size × 2 到 size × 3 经验范围。
- 迷雾可以隐藏地形轮廓，但 WorldSurfaceAnchor 始终返回真实高度。
- 不能把未探索格子的高度改为 0，否则对象恢复显示时会跳动。

## 10. 编辑、版本和恢复

### 10.1 编辑刷新

- 仅 unit 字段变化：不重建地表。
- city 变化：刷新城市与植被抑制。
- terrain、modifiers、treeModel 和 river 变化：刷新目标格子与六邻居。
- 改变通行性或移动消耗：使对应导航摘要失效。
- mountainHeight 等显示尺度变化：只增加渲染地表版本，不改变导航版本。
- 存档恢复期间继续拒绝编辑、清空和新快照。

### 10.2 版本职责

| 变化 | 必须更新 |
|---|---|
| 格子分类、修饰、树种或 CPU 地表语义 | WORLD_GENERATOR_VERSION 与对应基准校验和 |
| 区块字段、邻域或传输布局 | WORLD_CHUNK_FORMAT_VERSION |
| 工作线程请求、响应或转移对象 | WORLD_WORKER_PROTOCOL_VERSION |
| WorldDescriptor 字段或含义 | WORLD_DESCRIPTOR_FORMAT_VERSION |
| 只有 Shader 颜色和光照变化 | 不升级生成器；执行视觉回归 |

v1 中，一个生成器版本唯一对应一个冻结风格配置，不增加第二套总是一起增长的风格版本。

### 10.3 唯一世界指纹

继续使用现有规范序列化：

~~~ts
const fingerprint = serializeWorldDescriptor(descriptor);
~~~

该字符串是唯一身份来源：

- 缓存键使用 [fingerprint, chunkX, chunkY]。
- 默认 worldId 使用 fingerprint 或其稳定哈希。
- 导航 terrainRevision 使用 fingerprint 或其稳定哈希。
- 存档继续保存并严格比较完整描述符。

不能在不同调用点分别拼接字段。

工作线程请求和响应必须包含并校验生成器版本与区块身份。校验完成前不能写缓存或安装到稀疏地图。

### 10.4 一次迁移

迁移已按五步完成：

1. 提取 WorldSurfaceResolver。
2. 建立 WorldSurfaceView 并复现现有视觉。
3. 一次性升级到 generator v4，加入连续地表、气候、森林/湖泊斑块和全部贴地消费者。
4. 阶段 5 复核发现低适宜度森林仍被独立随机值打散；generator v5 改为连续密度阈值加有限边缘抖动，不改变宏观地貌、气候、湖泊或地表高度。
5. generator v6 把永久积雪限制到气候雪线以上，并让生成雪地保留 hill relief；低温低地继续使用 tundra，山体峰顶由连续 Shader 雪线覆盖。同时渲染法线改为共享顶角坡度，常驻六边格线默认关闭。
6. generator v7 曾加入坐标寻址的局部下降短路径，随后因没有形成预期的宏观曲线水网而废弃。
7. generator v8 把共享无限曲线/折线场作为采样母体，在六边形地形生成时连续栅格化为 river modifier、精确六边连接掩码和周期环绕掩码；现有渲染与稀疏编辑接口保持不变。

generator v8 固定格子回归校验和分别为：无限区块 `c66b54d6`、环绕区块 `184132e3`、有界世界 `30bf99af`；规范量化地表校验和仍为 `7ffc9327`，森林/湖泊/河流区域样本为 `152bdeb0`。基础设施多区块顺序无关校验和为 `db01e7d9`。一次性生成、区块生成和工作线程共享同一解析器；工作线程按完整描述符指纹复用解析器。

阶段 3 升级过生成器版本与 Worker 协议；阶段 5、generator v6、v7 和 v8 都只升级生成器版本。小地图概览后来增加了只读 RGBA 栅格请求，因此 Worker 协议保持 v3。generator v8 继续用 bit 8 保存 river、bit 9–14 保存六边连接掩码、bit 15 标记显式掩码，`PackedWorldChunk` 保持 v2 且仍是每格一个 Uint16；descriptor 结构仍为 v1，其指纹已包含 generator 和 chunk-format 版本，因此不增加重复字段。

旧生成器世界继续按严格描述符不匹配拒绝。自定义固定 worldId 的调用者必须主动迁移或清理旧地形编辑。

## 11. 性能边界

- 每个世界生命周期只创建一次解析器。
- 每个区块构建只创建一个有界采样窗口。
- 禁止按世界坐标建立无界 Map 缓存。
- 水页固定为 32x32 Int8 掩码、最多 16 页；最大裸掩码为 16 KiB（不含 Map 开销）。相交曲线查询仅枚举各尺度最大几何可达范围内的所有权格。512x512 环绕世界的规范掩码为 256 KiB。同步 API 的最近解析器缓存严格限制为一项；Worker 为当前描述符持有一项。
- 世界概览的地表底色保持每像素一次采样；河流按可能到达页面的稀疏路径枚举，并以像素覆盖聚合保留一格宽水道，不对 1024×1024 页面做完整逐格解析。
- 只有实际分析证明对象分配成为热点时，才增加 sampleInto() 等内部快速路径。
- 常驻属性、模型和以后可能增加的附加字段进入资源账户。
- 临时采样窗口不计作常驻资源，但必须按区块尺寸有明确上限，并在构建后释放。
- 调试模式不能每帧重采样全部驻留世界。
- 自适应画质只能减少实例和细节，不能改变权威格子、气候和植被语义。
- 重点测量首次可见区块、稳定区块生成、植被准备、挂载时间和 GPU 属性字节。

- 固定图库的海岸、湖区、山地和大尺度平原没有持续出现“缺少河流导致世界不自然”的主要缺口；阶段 5 唯一稳定复现的风格问题是椒盐森林，已由 generator v5 修复。
- 继续保留现有手工 `river` modifier、六邻接连通渲染、编辑刷新和稀疏持久化，不删除已有能力。

- 只有真实玩法要求可导航/可编辑的河网，或后续固定图库在多个种子上稳定暴露大面积内陆缺水时，才重新开启水文设计；届时先定义流域身份、区域边界和跨区块连续性门禁，再决定生成器与存档迁移。

2026-09-03 复核补充：无限世界现在明确需要可在任意坐标确定性采样的生成水网，手工河流无法覆盖该尺度，也无法独立保证区块 halo 身份一致，因此门禁已由产品需求触发并批准。首轮 generator v7 把要求误解成六邻接排水势短路径；后续澄清明确要求以前面的无限曲线/折线场为采样母体，在六边形地形生成时落成水格。当前 generator v8 采用[曲线采样水网决策](./decisions/curve-sampled-water-network-v8.md)，v7 决策仅保留为废弃历史。现有大陆海面和区域湖泊规则不在本次改动范围，曲线场景的广域海盆也不接入生产。

## 14. 复核结论

### 14.1 是否有更优的整体方案

对当前目标，最合适的是：

~~~text
无状态生成字段
+ 区块内短命采样窗口
+ 合并编辑的运行时地表视图
~~~

它保留现有流式加载和六边格表现，也避免全世界预计算。

更复杂的区域图或全局地图集只在真实河网、完整流域或远程权威高度成为明确需求时才有收益。现在采用会增加首屏等待、存储和无限世界复杂度，不是更优解。

### 14.2 剩余风险

| 风险 | 处理方式 |
|---|---|
| 岸线归零使临海山体像被切平 | 单独复核临海山地；必要时改为对称岸线衰减 |
| 512 世界好看但小世界重复明显 | 测最小尺寸和多个中间尺寸 |
| 普通地形起伏影响六边格识别 | 严格限制平地和丘陵高度，保留清晰网格 |
| 静态 MapInfo 无法复现程序化精确高度 | 保持中性回退；有真实需求再加显式能力 |
| 主线程重算高度成为热点 | 先使用短命窗口，性能数据证明后再传附加字段 |
| 非 Chromium 平台出现浮点边界差异 | 扩大平台支持时，在新生成器中统一量化 |
| 自定义层使用高度但不处理 surfaceChanged | 文档和示例明确要求；以后主版本再考虑强制能力 |

结论：阶段 0–7 已完成，generator v6 是可回归的历史冻结基线；当前 generator v8 已实现由无限曲线/折线场采样生成的六边格水网。生成、身份、贴地、biome 材质语义、气候雪线、区域森林和水网放置已经统一；侵蚀、物理流向和全局地图集继续不引入。现有手工河流能力与稀疏编辑优先级继续保留。

## 15. 完成标准

世界风格 v1 只有同时满足以下条件才冻结：

1. 一次性生成和流式生成共享唯一解析器。
2. 风格配置与生成器版本一一对应。
3. 世界描述符、缓存、存档、默认 worldId 和导航版本使用同一指纹来源。
4. 多个种子的远、中、近景没有明显碎山、椒盐森林、随机水坑和尺度冲突。
5. 平地、谷地、丘陵、山麓和山体形成连续且克制的层次。
6. 气候、树种、植被密度和地形材质使用同一套空间语言。
7. 源区块、渲染块、LOD、环绕边界、卸载重载和浮动原点没有接缝。
8. 城市、单位、路线、标记、草木和注册层正确贴地。
9. 地形块不会因 Y 边界错误而提前裁剪。
10. 格子与地表校验和、版本变化、缓存隔离和旧存档拒绝规则明确。
11. 单测、类型检查、构建、端到端测试、适用 soak、性能基准和样本图库复核全部通过。
12. 没有为假设需求引入全局地图集、通用特征系统、连续地形重构或物理模拟。

上述门槛在 2026-08-29 首次通过；2026-08-31 的积雪与山体接缝复核形成 generator v6 冻结基线，2026-09-03 的曲线采样水网修正推进到 generator v8。固定格子、连续地表、区域森林/湖泊和河流校验见 10.4，固定样本构成与比例基线见 12.3。今后的生成语义改动必须显式升级生成器版本并同步校验和、缓存/存档身份和图库基线。

完成后，停止继续扩建世界生成基础设施，进入确定性模拟核心和第一批真实玩法内容。
