# Three.js 程序化六边形世界设计

## 目标

以 `gunyakov/three-hex-map` 为基础，在当前空工作区交付一个可本地运行的纯图形演示：浏览器显示文明风格的程序化六边形大世界，支持相机浏览、格子悬停/选中，以及按种子和地图尺寸重新生成。

## 基础方案

保留上游项目的 TypeScript 图形库、Three.js 实例化渲染、自定义 Shader、纹理和模型资源。上游代码作为项目基础引入，并保留来源与许可证声明。演示入口不启用 `GameEngine`，只实例化 `HexMap`；上游单位、寻路和战争迷雾代码暂不删除，避免为纯粹清理产生额外风险，但不会进入默认运行路径。

仓库根目录保留上游的构建方式。新增的程序化世界生成逻辑与页面入口保持独立，尽量不改动核心 Shader 和渲染层。

## 第一版范围

第一版包含：

- 全屏 Three.js 六边形地图。
- 可重复的种子式世界生成。
- 可配置地图宽度和高度。
- 海洋、海岸、平原、沙地、苔原和雪地分类。
- 丘陵、森林与少量湖泊修饰。
- 使用上游现有的动态水面、海岸效果、地形混合、草地和树木实例。
- 鼠标悬停高亮、点击选中。
- 轨道相机的旋转、平移和缩放。
- 简洁参数面板：种子、宽度、高度、重新生成、网格开关和水面/植被的现有可调参数。

第一版不包含单位、寻路、回合制玩法、存档、联网、地图编辑器或战争迷雾逻辑。

## 架构

### 上游图形层

`src/HexMap.ts` 继续作为地图渲染入口，负责场景、相机、交互和各渲染层的生命周期。`src/objects`、`src/shaders` 与 `src/helpers` 继续负责实例化几何、Shader 和辅助计算。第一版只在修复兼容性或接入生成数据所必需时修改这些目录。

### 程序化生成层

新增纯 TypeScript 世界生成模块。输入为 `seed`、`width` 和 `height`，输出上游 `HexMap.load()` 接受的 `MapInfo`。

生成过程分为五步：

1. 使用确定性伪随机数和多频率二维值噪声生成海拔、湿度与温度场。
2. 通过大陆中心衰减让地图边缘更偏向海洋，形成可读的大陆轮廓。
3. 根据海拔和温度分类海洋、陆地、沙地、苔原与雪地。
4. 根据相邻格子把临海水域标为 coastal，并根据局部海拔、湿度增加 hill、wood 和 lake 修饰。
5. 返回结构完整的 `MapInfo`，交给 `HexMap.load()` 一次性重建渲染层。

同一个种子和尺寸必须生成完全相同的数据。无效尺寸在进入生成器时被拒绝，并由页面显示可理解的错误信息。

### 演示页面

保留上游 `public` 静态演示结构，但用独立初始化模块替换默认的 `GameEngine` 启动路径。页面启动后生成默认世界并载入 `HexMap`。用户修改种子或尺寸后点击“重新生成”，旧地图资源由 `HexMap` 的现有加载/清理流程替换。

面板不承担地图编辑，只暴露生成输入和上游已有的实时视觉参数。画布始终占满视口。

## 数据流

```text
面板参数
  -> 参数校验
  -> generateWorld(seed, width, height)
  -> MapInfo
  -> HexMap.load(MapInfo)
  -> 实例化地形/水面/植被/网格 Shader
  -> 浏览器画布
```

悬停和点击事件由 `HexMap` 发出，页面仅在状态栏显示坐标和地形信息，不建立游戏状态。

## 性能边界

默认地图尺寸采用上游示例附近的规模，目标为桌面浏览器流畅浏览。允许从面板提高尺寸，但第一版不承诺无限地图或流式区块。继续使用上游每层少量 draw call 的实例化结构，不为每个六边形创建单独 `Mesh`。

生成器只创建普通数据对象，不创建 Three.js 对象。若默认规模下生成耗时不可感知，则保持主线程实现；第一版不引入 Web Worker。

## 错误处理

- 宽高必须为限定范围内的整数，超出范围时不替换当前地图。
- 生成或加载失败时保留当前画面，并在面板中显示错误。
- 纹理或模型缺失时记录明确资源路径；不吞掉异常。
- 页面初始化失败时显示错误面板，而不是留下空白画布。

## 测试与验收

自动测试覆盖：

- 相同种子与尺寸输出一致。
- 不同种子至少产生不同的地形分布。
- 输出宽高、坐标键和所有格子数据完整。
- 地形类型属于上游支持集合。
- coastal 只出现在海水与陆地相邻的位置。
- 无效尺寸被拒绝。

工程验收包括：

- TypeScript 类型检查通过。
- 生产构建通过。
- 自动测试通过。
- 浏览器打开演示后能看到地图，控制台无新增错误。
- 旋转、缩放、平移、悬停、点击和重新生成均实际验证。
- 同一页面连续重新生成多次不会出现重复画布或明显资源泄漏症状。
